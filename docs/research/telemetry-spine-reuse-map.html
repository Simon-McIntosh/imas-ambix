Cross-cutting notes for the coordinator

  1. lane.py is the §2 landmine. The plan's write-path list for §2 does not include imas_ambix/agent/lane.py. If §2 lands without migrating parse_lane_capacity/_parse_sglang_capacity, the repository is left with exactly the "two implementations, one blind" condition the plan is repairing — just moved. Either add lane.py to §2's scope or record the decision to leave it (and then the §5 reader must not mint a fourth copy).
  2. receipt_bins.collect_receipt_bins has no production caller — only tests/test_agent_receipt_bins.py. §5's index is its natural consumer; a reader that reimplements the aggregation instead would orphan it.
  3. The watcher port crosses repositories. §5's source lives in dotfiles (revision above), and dotfiles keeps a launcher on PATH. The port node needs read access to that checkout; that is outside this repo's fence.
  4. §3's only live-measurement obligation (recorder cost under 1% of one core) and §6's p99 latency gate both require a live serve; as the plan states, the §3 reading belongs on the GPU node, never the login node.
