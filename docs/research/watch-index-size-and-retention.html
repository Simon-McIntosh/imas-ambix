Method and provenance

The GPFS source ~/.cache/ambix/watch-index.sqlite3 was opened with SQLite mode=ro and query_only=ON. The SQLite backup API copied it to a mktemp -d directory under the run's writable node-local /tmp/reckon-crew-scratch. The completed backup used journal_mode=OFF and synchronous=OFF on the disposable destination, took 47.06 seconds, and matched the captured 8,669,601,792-byte source exactly. On that local copy, quick_check(1) returned ok and dbstat ran successfully. The shell exit trap removed the copy and its temporary directory; the GPFS source was never opened for writing. Each object's row count below is its table leaf-cell count or its index leaf-plus-interior-cell count. Bytes per row divide all of the object's pages, including interior and overflow pages, by that count. The physical file comparison includes any freelist pages separately.

A preliminary backup with destination syncing enabled copied all pages but stalled in fdatasync and timed out; its own temporary copy was removed. Its read transaction overlapped the gap after the ingest log's 05:59:27Z tick and before the separately recorded 06:11:03Z service stop. The overlap does not establish why the service was stopped. The completed measurement above used the later backup with destination syncing disabled; its result matched the preliminary page image.

Why there is no new retirement manifest

Verdict: no raw receipt is currently eligible. The read-only scan with rebuild=False reported 0 of 20 raw files eligible for retirement. Nineteen old raw files ended between 2026-09-07 and 2026-09-17 but each has compared_pairs=0, so the guard reports no hour carries the counters. The remaining raw file, job 1280470, is still running, modified within the last day and younger than the 14-day row-age threshold. As a positive control for the scan, that live file produced 1,473 compared pairs across 491 hours: zero pairs in the older files is a property of those files, not a scanner that cannot see counters.

Before 06:11 UTC, the fleet service command was imas-ambix agent ingest --cadence 60, with no --no-retention flag. cli.py defaults retention to true and constructs ScheduledRetention; telemetry_ingest.run calls it after every successful tick, and ScheduledRetention invokes a pass when 24 hours have elapsed. retention_pass writes a manifest only inside if result.eligible. The service log records successful ticks on every date from October 17 through October 23 (1,274; 1,282; 1,222; 1,227; 1,148; 1,042; 270 through 05:56 UTC) and no telemetry retention pass failed line. The latest manifest is retire-raw-20261017T125332Z.json, containing one eligible file from an earlier pass. Successful empty passes do not log a completion line, so the log does not independently timestamp each daily pass; the read-only scan and the code's manifest condition explain the earlier gap.

Current schedule state changed during this investigation. The fleet supervisor log records stopping declared service ambix-ingest (pid 4164346) at 2026-10-23T06:11:03Z and a reload immediately after. The current ~/.config/fleet/services.json contains only reckon-admit-local, and the ingest lease is absent. No scheduled retention can run while that service remains stopped. The log does not state why the service was removed; the stop is a separate, later fact from the zero-eligible scan.

Raw receipts without comparable counters remain the authority and cannot pass the current proof for retirement. A change to that proof or to raw-file retention needs a separate decision; this investigation deletes nothing.
