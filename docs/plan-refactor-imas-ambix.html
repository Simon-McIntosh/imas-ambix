imas-ambix plan-refactor

imas-ambix · Plan system · Updated 2026-05-26

Intent: Bring all imas-ambix per-plan JSON files into conformance with the reckon redesign schema, stripping legacy fields from pre-redesign tooling and adding minimal stubs where phase-record artifacts are missing required fields.

1. Background

The reckon redesign landed on 2026-05-26 across three repos (reckon, imas-ambix, imas-efit). The redesign defined a canonical per-plan JSON envelope and a bespoke dashboard format for the central index.json. Every per-plan file in docs/state/imas-ambix/ was written before this schema was finalised and carries five legacy fields in data{} that are no longer part of the canonical schema and are not read by the reckon SPA:

  • decisions_def — old open-choices array, pre-dates the decisions{} map
  • followups_done — resolved followups stored in a separate array; schema uses in-place resolved_at/resolved_by/outcome on the main followups[]
  • dec_open — counter field, now computed by the SPA from decisions{}
  • last — duplicate of last_modified; the canonical field is last_modified
  • created — creation timestamp not in the canonical schema

Fields that look non-canonical but are intentionally kept because the reckon SPA or docs-server reads them: slug, phase, owner, blockers, comments, last_modified, _version, isHeroPlan.

The index.json central file uses the bespoke imas-ambix dashboard format (inventory[], projects[], timeline[]) which the reckon SPA handles natively via state-loader.js. That format is intentionally retained.

3. Surgery plan

A single Python script strips the five banned legacy fields from every per-plan JSON in one pass, skipping index.json and the newly-created plan-refactor-imas-ambix.json. The script also applies the stub fix-ups for the two phase-record artifacts.

Fields to strip (from data{})

  • decisions_def
  • followups_done
  • dec_open
  • last
  • created

Fields to keep (referenced by SPA / docs-server)

  • slug — used by the SPA plan-view routing
  • phase — plan lifecycle badge
  • owner — displayed in plan header
  • blockers — blocker count rendered by the cockpit
  • comments — comment count rendered by the cockpit
  • last_modified — recent-activity ledger
  • _version — docs-server version-write contract
  • isHeroPlan — flag used by the cockpit to pin the hero plan card

Stub fix-ups (option a — preserve in place, not archived)

redesign-rollout.json and tokenizers-12-landed.json are phase-record artifacts: frozen records of decisions locked at a specific point in time. They are not active plans. Both receive minimal fields to prevent SPA parse errors, with status: "shipped" because the work they record has landed.

4. Status of stub / phase-record files

redesign-rollout.json was created as a demo page for the plan-system redesign rollout on 2026-05-21. Its data{} carries decisions, questions, research items, notes, and one followup — all well-formed. The only gaps are missing title, summary, depends_on, blocks, and an invalid status: "in-progress" (schema allows active but not in-progress as a separate value). Fix: add title + summary; change status to shipped since the redesign rollout is complete.

tokenizers-12-landed.json is a flat decision store — the four locked decisions from tokenizers §12 captured at 2026-05-20 22:00. Its data{} is not a plan-shape at all. Fix: add title, summary, status: "shipped" at the top of data{} so the SPA can at minimum display the plan name and status without crashing. The four decision entries are preserved as-is (they are historically accurate and useful reference data).
