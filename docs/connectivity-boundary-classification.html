Connectivity-Based Boundary Classification

Successor to the flux-comparison + geometric-annulus-cap boundary read in toroidal-harmonic-annulus-read. Determine the LCFS and the limited-vs-diverted class from the connectivity of the flux topology — the level-set component that encloses the magnetic axis — rather than from a flux-value comparison guarded by a tuned distance cap. The read is deterministic, per-slice, and firewall-safe (EFIT scores only).

§1 — Why: the heuristic boundary read is fragile

The toroidal-harmonic gate reads the boundary flux ψbnd by comparing the innermost in-vessel X-point flux against the limiter-tangency flux and taking whichever is "more binding" (closer to the axis flux). The RCA of the ramp-up failure (§ Gate C landed) showed this is unreliable for three coupled reasons:

  • It forced a diverted topology onto a limited plasma. MAST ramps up LIMITED (EFIT has no X-point for Ip 21–66%), but the read used the innermost X-point whenever one existed, putting the LCFS on a spurious saddle (ramp-up LCFS 41–52 cm).
  • The flux comparison is corrupted by ill-posed extrapolation. The too-binding "limiter tangency" came from divertor structures at |Z|≈1.7 and the spurious X-points from far-field saddles at |Z|≈1.4 — outside the plasma-extent annulus where the truncated harmonic fit is unconstrained continuation (garbage). A flux value there is not a physical bounding surface.
  • The geometric annulus-cap patch is knife-edge sensitive. Capping the candidate search to a multiple of the pole-to-origin distance recovered the class on one shot but, untuned, regressed the held-out X-point-set (cap 3.5 → −6.03); it needs leakage-free tuning per campaign and does not generalise. A distance cap is a proxy for the real question — is this critical point actually on the surface that bounds the plasma? — which is a connectivity question, not a distance one.

Connectivity answers that question directly and needs no tuned cap: a far-field saddle whose level-set does not enclose the axis is rejected structurally.

§2 — The chicken-and-egg worry, resolved

The proposed recipe — "use a contour library to extract the boundary, then the stationary points" — is indeed circular: you cannot trace the bounding contour until you know which flux value bounds the plasma, and that seems to need the X-points. The resolution is to reverse the order, and it dissolves the circularity completely:

  • Stationary points do NOT need the boundary. The magnetic axis (O-point) and X-points (saddles) are the points where ∇ψ = 0 — a local property of the field, found by bracketing sign changes of ψR, ψZ and Newton-refining, then classified by the Hessian determinant (definite → O, indefinite → X). This is already implemented in imas_ambix/latent/topology.py::find_critical_points and needs no contour and no boundary.
  • The boundary is DEFINED by the stationary points + connectivity. Each critical-point flux (and the limiter tangency) is a candidate bounding value. For each candidate we trace/label the level-set and ask: does the component containing the axis close inside the vessel (diverted, bounded by that X-point) or reach the limiter (limited, bounded by the wall)? The LCFS is the outermost such axis-enclosing surface that does not cross the limiter.
  • So the dependency runs one way: field → ∇ψ=0 stationary points → candidate fluxes → connectivity of contours through them → boundary. The contour library is used after the stationary points, to extract the separatrix curve once its flux is fixed — never to find the stationary points. No chicken-and-egg.

(Even the LCFS ray-cast the gate already does is downstream of the axis + a bounding flux — it has never needed the boundary to find the axis. This plan makes the selection of the bounding flux connectivity-based rather than a flux-magnitude heuristic.)

§3 — Algorithm

Per slice, on the masked total flux ψtot (harmonic plasma + thick-cylinder coil), with the ray-cast origin from the interior estimate (current centroid):

  1. Critical points. find_critical_points(ψ) → O-points, X-points (already exists). Filter X-points to in-vessel, conductor-clear.
  2. Axis + reference flux. The confined O-point nearest the interior-estimate axis (or the estimate itself); ψaxis read there.
  3. Candidate bounding fluxes. Each in-vessel X-point flux, plus the limiter-tangency flux (the deepest-penetrating limiter grid point). No distance cap.
  4. Connectivity test (the core). For a candidate ψc, form the confined set {points on the axis side of ψc}; label connected components (scipy.ndimage.label, 4-connectivity — the mechanism topology.classify_regions already uses). The plasma is the component containing the axis. Accept ψc as a valid boundary only if that component (a) contains the axis and (b) does not touch the domain edge. Among valid candidates, the LCFS is the OUTERMOST (the axis-enclosing component is largest) that still does not cross the limiter.
  5. Limited vs diverted falls out. If the largest valid axis-enclosing component is bounded by an X-point whose separatrix closes in-vessel → DIVERTED (report that X-point). If the component reaches the limiter before any X-point closes it → LIMITED (boundary = limiter tangency; X-point slots empty). This is decided by connectivity, so a far-field saddle whose component does not enclose the axis is never selected — the annulus-cap hack is retired.
  6. LCFS geometry. Once ψbnd is fixed, extract the closed separatrix curve with contourpy (matplotlib's engine) — the axis-enclosing contour at ψbnd — and resample the 8 fixed-angle radii from it. contourpy gives a clean polygon (better than the current outward ray-march, which can miss or double-count at concave divertor legs).

§4 — Library choice

Two roles, possibly two tools; decision below:

  • Connectivity (which component encloses the axis; does it touch the wall): a grid-label operation. scipy.ndimage.label is already a dependency and is used by classify_regions — no new dep, robust, fast. A contour library is not needed for the connectivity decision itself.
  • Separatrix curve extraction (the closed boundary polygon for the LCFS radii + figures): contourpy (already transitively present via matplotlib) returns line segments/polygons at a level; pick the ring enclosing the axis. Alternative skimage.measure.find_contours (marching squares) if contourpy's API is awkward.

Leaning: ndimage for connectivity + contourpy for the curve — both already available, no new heavy dependency. The pole-and-truncation / masking machinery and the firewall are inherited from the harmonic plan unchanged.

§6 — Risks

  • Grid resolution. Connectivity on a 65×97 grid can merge/split components at thin divertor legs; may need local refinement or a sub-pixel contour. Mitigate with contourpy on a bilinear up-sample near the candidate flux.
  • Masked-interior artifacts. The near-pole plateau must not create a false axis-enclosing component; the axis-containment test + the existing mask handle this, but verify.
  • Still bounded by the origin/axis error. Connectivity fixes the boundary SELECTION; the residual ramp-up LCFS error from the centroid-vs-flux-axis offset (the Shafranov issue) is a SEPARATE thread (harmonic plan f-thar-xpt-shafranov) — this plan does not close it, and should be evaluated with that in mind.
