§1 — Objective and strategy

Create imas-nova: a new, importable, dependency-light physics-spine package holding the canonical Biot kernels, operator assembly, machine-description compilation, identity caching, batched topology, and IMAS IO — sourced by curated transfer from nova's keep-set (~35k LOC) and imas-ambix's physics tier (~12k LOC). The evidence base and option analysis are in the research doc nova-scoping-review; this plan is the execution record. Strategy pillars, fixed unless a decision below reopens them:

  • One canonical home, curated transfer. Whether the spine lives in a new repo or in a refactored nova (see the repo-mechanics decision), each component becomes canonical in the spine as it lands and the donor copy is deleted in the same series — no parallel version families, no long-lived duplication. Assembly/structural work is out of scope for the spine in every variant.
  • Pandas-free core. The frame layer is rebuilt as a typed columnar store (schema + dict-of-numpy-columns + accessor objects); pandas and xarray appear only as export/interchange shims. Modern floors: python ≥ 3.12, numpy ≥ 2.
  • JAX-first evaluation, numpy assembly. Green's-function assembly stays numpy/scipy (assemble-once); evaluation, dynamic plasma turns, null-finding, topology, and the GS fixed point run on the jitted path with a batch axis over shots/timeslices.
  • Access Layer only at the boundaries. Ingest transcodes IDSs once into a standard-name-keyed zarr signal cache; the hot path sees dense arrays only; egress assembles true IMAS IDSs at end of run.
  • Fast tests only. Every transferred unit test runs without live DB/UDA access and the whole suite stays in the seconds-to-low-minutes range; DB-bound tests are rebuilt on synthetic or bundled HDF5 fixtures or left behind.

§2 — Repository bootstrap

Stand up the imas-nova repository: uv-managed pyproject.toml; trunk-based on main; ruff; pytest with a default fast lane; reckon docs infrastructure synced. Core dependencies (grep-attributed from the donor keep-sets): numpy≥2, scipy, xarray, zarr, netcdf4, shapely, contourpy, xxhash, appdirs, imas-python, h5py, tqdm, packaging. Extras: jax (cuda12 on Linux), matplotlib (plotting), pyvista/vedo (3-D viz), numba (legacy), bokeh. Explicitly absent from core: pandas (dev/test extra at most), torch, and the nova deps proven dead or leave-set-only (optax, descartes, altair, pillow, rich, moviepy…). Package skeleton mirrors the target architecture: frame/ biot/ topology/ machine/ io/ graphics/ testing/.

Done-when: repo builds an installable wheel; CI runs an empty-but-wired fast test lane; AGENTS.md and the CLAUDE.md loader present; reckon synced.

§3 — Columnar frame core

Port the frame layer onto a typed columnar store, preserving the public API surface consumers actually use (insert, Loc/sLoc/loc/sloc label indexers, aloc/saloc array accessors, += union, store/load):

  • Carry near-verbatim: MetaFrame (schema, ~90 column defaults, column groups, locks, version hashes), Energize (It ⇄ Ic·nturn), SubSpace (independent-DOF projection with subref/factor mapping), Select, MultiPoint, the metamethod loader.
  • Replace: the 7-deep pandas subclass tower and the runtime-manufactured private-API indexers (nova/frame/indexer.py) with explicit accessor objects over {index: ndarray, columns: dict[str, ndarray], schema} — the shape the hot path already has in metaframe.data. Row insertion becomes array concatenation; label lookup is index get_loc + slice.
  • Shims: to_pandas() / to_xarray() exports; xarray→netCDF/zarr persistence for frames at rest (replacing the pandas round-trip in frameset.store).
  • Geometry columns (shapely poly, vtk) stay object-typed columns with the existing lazy loads.

Done-when: nova's frame test files (test_frameset, test_framespace, test_framelink, test_dataarray, test_energize, test_select, test_multipoint, …) pass against the new store; a coil-construction micro-benchmark shows construction no slower than the pandas path; zero pandas imports in imas_nova.frame.

§4 — Biot kernels and operator assembly

  • Lift near-verbatim from nova: constants.py (elliptic/coefficient library), circle, cylinder, arc, bow, line, beam kernels; matrix.py turns/reduce/link reduction with the four-block plasma decomposition; solve.py ensemble assembly.
  • Adopt from ambix as canonical: gs/polygon.py (Urankar Part V polygon sections — nova's stub is not ported) and the hybrid_greens near/far blending contract; reconcile with nova's cylinder so exactly one kernel set remains.
  • Sever pandas: replace BiotFrame with a small data-provider protocol (frame(attr) → (target, source) ndarray, aloc/saloc, reduce indices/links); reduce.py's pandas Index becomes numpy int arrays.
  • Consolidate zeta to a single implementation (JAX-compatible numpy; numba dropped from core).
  • Vectorise the per-angle Python-level stacking in the arc/bow kernels if profiling shows them hot.

Done-when: nova's analytic validation tests (solenoid fields, ITER sub-inductance goldens, 3-D element tests) and ambix's kernel golden-value tests pass against the unified kernel set; kernel modules import with numpy+scipy only.

§5 — Batched evaluation and topology (JAX)

  • Make nova/jax/operate.py's jitted pytree operator (evaluate, evaluate_external, update_plasma_turns) the primary evaluation path, with the numpy Operate as fallback; keep the xxhash/version-counter invalidation contract.
  • Merge the two JAX topology stacks — nova's jax/null.py + jax/topology.py (Kuijper categorisation, limiter/diverted adjudication) and ambix's stencil_nulls, connectivity_boundary, flux_surface_connectivity, topology — into one fixed-shape, vmap-safe module set; the serial numba fieldnull is not ported.
  • Add the missing batch dimension: vmap evaluation + topology over a leading shot/time axis; validate fixed-size null bounds across a MAST shot corpus.
  • Bring over ambix's free-boundary GS solver (latent/gs_solve.py) and the staged-disc and prior boundary reads as the spine's solve/read tier.

Done-when: jitted evaluate/update-turns agree with the numpy path to tolerance on cached operators; a batched (B-shots) topology call returns identical results to per-slice calls; existing ambix latent-physics tests pass in the new home.

§6 — Machine description and identity cache

  • Carry nova's IMAS layer: dataset.py ladder (identity attrs, URI, lazy DBEntry access, content hashing), uri.py, db_entry.py, metadata.py provenance stamping, coils_non_axisymmetric.py.
  • Carry the CrossSection geometry_type dispatch with its multi-machine fallbacks (documented); re-point the frame-insert path at the columnar store; keep the Machine.build → solve_biot → store orchestration.
  • Identity cache: keep content-hash keys (identity attrs + per-source IDS content hashes + Biot discretisation) and version-segmented cache paths; harden with canonical key serialisation (sorted, typed — not str(dict)); include the DD version in the hash; back with zarr (or retain netCDF groups — see decision) so eviction doesn't rewrite whole files. Cache both compiled frames and solved operators, as nova does today.
  • Register ambix's imas_geometry.py reader against the same MachineGeometryReader-style seam so IMAS and FAIR-MAST zarr sources are interchangeable providers; MAST-specific tables (circuits, eras, sensors) remain in ambix as a machine plugin.

Done-when: an ITER machine description compiles from IDSs into frames + solved operators, round-trips through the cache (cold build → warm load bit-identical), and a deliberate geometry perturbation changes the key (stale-reuse regression test — the failure mode ambix's .npz caches already exhibited).

§7 — IMAS IO layer (standard names)

  • Author the owned mapping table: versioned YAML of standard_name → (ids, dd_path, occurrence, unit, cocos_transform) for the spine's core signal set (~30–50 entries: pf_active currents, magnetics probes/loops, equilibrium ψ/Ip/axis/boundary…), seeded from imas-standard-names-catalog where entries exist.
  • Ingest transcoder: whole-IDS full get() + bulk extraction (lazy get for selective channels) → standard-name-keyed zarr/xarray signal store, reusing the AL tensorizer semantics; cache keyed by URI + DD version.
  • Egress: IDS assembly from arrays via IDSFactory + single put() (HDF5 or netCDF); coordinate-ordering handled so validate() passes.
  • Streaming seam (interface now, implementation later): ring-buffer signal API compatible with memory-backend put_slice feed for real-time-adjacent operation.
  • The zarr signal store is the primary data plane, not just a cache ("IMAS in all but AL"): world-model training loaders and the spine both consume the standard-name-keyed tensorized zarr store directly; true IMAS pulses (HDF5 / IMAS-netCDF) are the interchange format materialised at the boundary by the egress builder. Guardrail: a round-trip test (zarr → IDS → validate() → zarr) runs in CI so the store cannot drift into a private schema; COCOS/units/provenance are carried as store attrs.

Done-when: a MAST or ITER test shot ingests once and re-reads at cached-store speed (≥100× the AL full-get, per the measured baseline); a synthetic run's results egress as a valid IMAS equilibrium IDS readable by imas-python at the written DD version.

§8 — Plotting mixins

Carry graphics/plot.py (the fieldless Plot/Plot1D/2D/3D/ Axes mixins) as the single plotting-attachment mechanism — the metamethod plotting duality and the legacy pyplot grab-bag modules are not ported. Standardise cooperative __post_init__ termination (one explicit terminal base). Matplotlib is an extra: core modules must import without it, with plot methods raising a clear guard when absent.

Done-when: coilset/operator/topology classes inherit working plot methods; core import graph is matplotlib-free.

§9 — Test and benchmark transfer (fast lane)

  • Transfer nova's ~72 keep-set test files and ambix's gs/latent physics tests (~20 files + latent suite) alongside their components; adopt nova's importmanager skip/mark pattern uniformly so optional extras (jax, viz, imas) degrade to skips, never collection errors.
  • Rebuild the 8 genuinely DB-bound nova tests (live ITER pulse/run or UDA URIs) on bundled synthetic HDF5 fixtures written by imas-python at build time; the ~9 tests that only needed import imas transfer directly.
  • Speed budget: default lane target < 60 s on a login node — matplotlib tests forced to Agg, cache-writing tests confined to tmp fixtures, pyvista/vedo tests behind a viz marker excluded by default. Fix the donor bugs on the way through: the never-collected text_netcdf.py filename typo, the empty test_arrayloc.py.
  • Port nova's asv benchmarks (operator assembly, framespace, biotoperate) and wire the ambix spine-bench harness against the new package.

Done-when: full default suite green and under budget with no network; coverage spans frame core, kernels, operators, topology, machine build, cache, IO; benchmarks recorded as the baseline.

§10 — Ambix adoption

  • Add imas-nova as an imas-ambix dependency; move gs/ and the latent physics tier per the split table in the research doc, deleting the donor copies as each lands (retire the dead gs/elliptic.py and test-only modules on the way).
  • Re-point the single tokenizer seam (geometry features) and the statespace/eval consumers at the package API; torch decoders remain in ambix, re-expressed as thin wrappers over the spine's numpy/JAX math where they duplicate it.
  • Execute the EM-consolidation review's coupling-generator unification as part of the move (one builder owning circuit classification + channel merge) rather than porting four wrappers.

Done-when: imas-ambix imports the spine from the package; no physics kernels remain in-tree; spine_bench numbers match pre-split baselines; full ambix test suite green.

§11 — Nova upstream convergence (deferred, tracked)

After the spine stabilises: nova adds imas-nova as a dependency, deletes its duplicated core (biot/frame/imas/jax/database keep-set), and continues as the machine-assembly/structural project — gaining the polygon-section kernel, the batched topology, and the pandas-free core its users need for current pandas/numpy releases. This is deliberately last: it touches nova's users and should land against a proven package. Until then nova stays frozen as the oracle for cross-check tests.

§ Decisions

Repository mechanics — three viable routes: (a) new imas-nova repo populated by curated transfer (clean dependency/CI baseline; nova untouched); (b) in-place major refactor of nova — current state parks on a protected legacy branch (assembly work continues there, destined for its own repo), main becomes the refactored core as a 2.0 (keeps the nova name, identity, history, and test set; assembly branch is frozen against the old frame API until extracted); (c) rename nova → imas-nova and strip later. The refactor content is identical in all three — this decision is identity, history, and branch-discipline mechanics.

Identity-cache storage backend: zarr store (recommended — group deletion works, matches ambix's existing dependency, chunked/lazy reads) or keep nova's netCDF-group layout (proven, but eviction rewrites whole files)?

Frame-core migration path: build the columnar store directly (recommended — the SoA store is already latent in metaframe.data and the consumer API is narrow) or ship a composition-over-pandas wrapper first and hollow it out behind the accessor API?
