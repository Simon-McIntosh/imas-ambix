§1 — Objective and strategy

Refactor nova in place into the physics-spine package (repo-mechanics decision locked 2026-07-23): nova keeps its name, identity, history, and core test set; the 2.0 core — canonical Biot kernels, operator assembly, machine-description compilation, identity caching, batched topology, IMAS IO — is built on a develop branch from nova's keep-set (~35k LOC) plus imas-ambix's physics tier (~12k LOC), while the live 1.x line continues to support the ongoing ITER-assembly work until that work extracts to its own repository. The evidence base and option analysis are in the research doc nova-scoping-review (§7a assesses this route); this plan is the execution record. Priority zero is the protection of the GP-interpolation and SSAT/in-pit coil-fitting code — §2a's byte-identity golden harness lands before any branch surgery. Strategy pillars, fixed unless a decision below reopens them:

  • One canonical home, curated transfer. Whether the spine lives in a new repo or in a refactored nova (see the repo-mechanics decision), each component becomes canonical in the spine as it lands and the donor copy is deleted in the same series — no parallel version families, no long-lived duplication. Assembly/structural work is out of scope for the spine in every variant.
  • Pandas-free core. The frame layer is rebuilt as a typed columnar store (schema + dict-of-numpy-columns + accessor objects); pandas and xarray appear only as export/interchange shims. Modern floors: python ≥ 3.12, numpy ≥ 2.
  • JAX-first evaluation, numpy assembly. Green's-function assembly stays numpy/scipy (assemble-once); evaluation, dynamic plasma turns, null-finding, topology, and the GS fixed point run on the jitted path with a batch axis over shots/timeslices.
  • Access Layer only at the boundaries. Ingest transcodes IDSs once into a standard-name-keyed zarr signal cache; the hot path sees dense arrays only; egress assembles true IMAS IDSs at end of run.
  • Fast tests only. Every transferred unit test runs without live DB/UDA access and the whole suite stays in the seconds-to-low-minutes range; DB-bound tests are rebuilt on synthetic or bundled HDF5 fixtures or left behind.

§2 — Nova branch restructure and 2.0 bootstrap

Branch model (upstream is Simon-McIntosh/nova on GitHub — verified not a fork of iterorganization; the git.iter.org URL exists only in pyproject metadata, no such remote is configured). Housekeeping first: the live line is currently the jax branch, 196 commits ahead of a stale main — fast-forward main to the jax tip and retire the jax branch name, so the live 1.x trunk is properly named. Then adopt a gitflow-style split for the transition period:

  • main = the live 1.x line. Assembly work continues here uninterrupted; nova's AGENTS.md gains an explicit two-branch exception to the trunk-based rule for the duration.
  • legacy/v1 + tag v1-assembly-baseline = the frozen state, cut at the commit where the §2a golden harness first runs green. Branch-protected on GitHub (no force-push, no deletion). This is the belts half of belts + braces — the braces are the goldens themselves, which travel.
  • develop = the 2.0 refactor line, branched from main after the baseline. Here the leave-set (assembly, structural, thermalhydralic, dina, design, projects, development — ~55k LOC) is deleted up front (zero live imports make this safe), the dependency floor resets (python ≥ 3.12, numpy ≥ 2 — the one-line np.float_ fix — no pandas in core), and §§3–9 execute. When assembly has extracted to its own repository and the 2.0 gate passes, develop merges to main (develop's deletions stand — main's assembly line will already live in the new repo) and nova returns to single-trunk operation.

Bootstrap on develop: uv-managed pyproject.toml; ruff; pytest with a default fast lane; reckon docs infrastructure synced into nova (/reckon-sync). Core dependencies (grep-attributed from the donor keep-sets): numpy≥2, scipy, xarray, zarr, netcdf4, shapely, contourpy, xxhash, appdirs, imas-python, h5py, tqdm, packaging, plus imas-standard-names + imas-standard-names-catalog as fork-RC pins per §7 (test-PyPI wheels via uv explicit index, git-tag fallback; flips to PyPI on the upstream release). Python floor 3.13 (ISNC requires ≥3.13; supersedes the earlier ≥3.12 pillar unless ISNC relaxes). Extras: jax (cuda12 on Linux), matplotlib (plotting), pyvista/vedo (3-D viz), numba (legacy), bokeh. Explicitly absent from core: pandas (dev/test extra at most), torch, and the deps proven dead or leave-set-only (optax, descartes, altair, pillow, rich, moviepy…).

Plan hosting: this ambix plan remains the umbrella strategy record; repo-local execution plans are authored in the repo whose code they change — the 2.0 refactor and assembly-protection plans in nova's docs/ once reckon is synced there, the assembly repo's plans in that repo when it exists, and §10 (ambix adoption) stays here. Cross-repo linkage via plan-informs.

Done-when: main fast-forwarded and live; legacy/v1 + baseline tag protected on GitHub; develop cut with leave-set removed, floors reset, wheel building, fast lane green; reckon synced in nova with the repo-local refactor plan scaffolded.

§2a — Assembly protection: byte-identity goldens and hardened extraction (priority)

Protected scope: the GP-interpolation and coil-fitting cluster for SSAT and in-pit operations — nova/assembly/gaussianprocessregressor.py, fiducialfit.py, fiducialfit_relative.py, fiducialpit.py (2.8k), fiducialsector.py (1.5k), fiducialccl.py, fiducialtransform.py, sectordata.py, sectorfile.py, windingpack.py/uniformwindingpack.py, SM6_fit.py (~8.7k LOC), plus the recorded fit corpus (input/ITER/*.xlsx — CCL_Deformed_Coils, TFC18_asbuilt, TFC1_CL… — and data/Assembly/ fixtures). This code supports live ITER work; its behaviour must be provably unchanged across every branch and repo move.

Golden characterization harness (lands on main before any branch surgery):

  • Inventory: enumerate every fitting entry point (sector fit, pit fit, relative fit, CCL transform, winding-pack fit, GP regressor predict) and pair each with its recorded inputs from the Excel/data corpus.
  • Canonical outputs: each entry point runs on its recorded inputs and serialises results to a canonical form — float64 numpy arrays in sorted-key .npz (or netCDF) with a deterministic layout. The goldens manifest (JSON) records: input file + sha256, entry point, output artifact + sha256 of the canonical byte stream, and the environment lock hash.
  • Byte-identity is an environment contract: pin single-threaded BLAS (OPENBLAS_NUM_THREADS=1, OMP_NUM_THREADS=1), fix all seeds, and capture uv.lock alongside the manifest — GP fits (Cholesky/LAPACK order) are reproducible to the byte only under a pinned stack. Same lock ⇒ assert exact equality (sha256 of array.tobytes()); a deliberate dependency bump gets a documented tolerance ladder (exact → rtol 1e-12 → investigate before accepting) and re-baselines the manifest in its own commit.
  • Excel handling: the sheets are the traceable record — snapshot them read-only as test fixtures and load via openpyxl cell values (full float precision, never display strings); tests assert on the canonical arrays, not on xlsx bytes (Excel serialisation is not byte-stable). Replacing Excel as the operational interchange (netCDF/parquet) is future work for the assembly repo — the recorded goldens themselves are never converted, they are the record.

Hardened extraction sequence (belts + braces): (1) goldens harness green in nova CI on main; (2) cut legacy/v1 + tag at that commit, branch-protect; (3) create the assembly repository (name under the assembly-repo-name decision) via git filter-repo so nova/assembly + its data/input trees carry full history; (4) the same goldens suite and manifest run in the new repo — the byte-identical gate that must pass before the new repo is declared canonical; (5) a dual-run window where both repos' CI execute the goldens on every commit; (6) a wheel-install check (the packaged product passes, not just the working tree); only then does assembly work switch homes and nova main drop the assembly tree.

Done-when: goldens manifest + harness committed and green on nova main; baseline tag + protected branch exist; the new assembly repo passes the identical manifest byte-for-byte under the pinned lock; dual-run window observed; extraction sign-off recorded here.

§3 — Columnar frame core

Port the frame layer onto a typed columnar store, preserving the public API surface consumers actually use (insert, Loc/sLoc/loc/sloc label indexers, aloc/saloc array accessors, += union, store/load):

  • Carry near-verbatim: MetaFrame (schema, ~90 column defaults, column groups, locks, version hashes), Energize (It ⇄ Ic·nturn), SubSpace (independent-DOF projection with subref/factor mapping), Select, MultiPoint, the metamethod loader.
  • Replace: the 7-deep pandas subclass tower and the runtime-manufactured private-API indexers (nova/frame/indexer.py) with explicit accessor objects over {index: ndarray, columns: dict[str, ndarray], schema} — the shape the hot path already has in metaframe.data. Row insertion becomes array concatenation; label lookup is index get_loc + slice.
  • Shims: to_pandas() / to_xarray() exports; xarray→netCDF/zarr persistence for frames at rest (replacing the pandas round-trip in frameset.store).
  • Geometry columns (shapely poly, vtk) stay object-typed columns with the existing lazy loads.

Done-when: nova's frame test files (test_frameset, test_framespace, test_framelink, test_dataarray, test_energize, test_select, test_multipoint, …) pass against the new store; a coil-construction micro-benchmark shows construction no slower than the pandas path; zero pandas imports in imas_nova.frame.

Done-when: nova's analytic validation tests (solenoid fields, ITER sub-inductance goldens, 3-D element tests) and ambix's kernel golden-value tests pass against the unified kernel set; kernel modules import with numpy+scipy only.

Done-when: jitted evaluate/update-turns agree with the numpy path to tolerance on cached operators; a batched (B-shots) topology call returns identical results to per-slice calls; existing ambix latent-physics tests pass in the new home.

§7 — IMAS IO layer (standard names)

  • Name semantics come from ISN/ISNC — nova owns no standard-name schema. The controlled vocabulary, grammar, units authority, and DD-path links live in the already-managed imas-standard-names (ISN — machinery: strictyaml/pydantic/pint validation, name API) and imas-standard-names-catalog (ISNC — the catalog: data-only, zero runtime deps, pre-built SQLite, 18 domain files including equilibrium and both magnetics domains). Both are fork RCs converging on a first upstream release. Spine signals missing from the catalog are contributed to the ISNC fork (it stabilises fast), never authored as a nova-side YAML. What nova.io keeps is strictly the consumption side: the zarr store layout, the ingest/egress transcoders, the round-trip validators, and the application of codex-discovered facility-signal → standard-name maps.
  • Dependency mechanics on the fork RCs (recommendation): primary path is test-PyPI wheels with uv explicit index pinning — [[tool.uv.index]] entry for test.pypi with explicit = true plus [tool.uv.sources] routing only imas-standard-names/imas-standard-names-catalog through it, exact ==X.Y.ZrcN pins — this rehearses the very packaging path the upstream release will use and gives consumers real wheel semantics, while explicit indexing prevents test.pypi from leaking into any other resolution. Fallback wherever test-PyPI friction bites (retention, publish overhead): git-tag pins on the forks (pkg @ git+https://…@vX.Y.ZrcN — the pattern ISNC's own dev group already uses for ISN). Vendoring a catalog snapshot into nova is rejected (schema drift — the exact failure the user's correction forecloses). Convergence: when the upstream PR lands and releases to real PyPI, the pins flip to normal PyPI ranges (>=1,<2) in one commit. Two hardening items to land in the forks before upstream release: move ISN's fastmcp hard dependency to an [mcp] extra (the spine needs name lookup + pint units, not an MCP server stack), and reconcile the python floor — ISNC requires >=3.13, so nova 2.0's floor becomes 3.13 (harmless here; ambix already runs 3.14) unless ISNC relaxes to 3.12.
  • Ingest transcoder: whole-IDS full get() + bulk extraction (lazy get for selective channels) → standard-name-keyed zarr/xarray signal store, reusing the AL tensorizer semantics; cache keyed by URI + DD version.
  • Egress: IDS assembly from arrays via IDSFactory + single put() (HDF5 or netCDF); coordinate-ordering handled so validate() passes.
  • Streaming seam (interface now, implementation later): ring-buffer signal API compatible with memory-backend put_slice feed for real-time-adjacent operation.
  • The zarr signal store is the primary data plane, not just a cache ("IMAS in all but AL"): world-model training loaders and the spine both consume the standard-name-keyed tensorized zarr store directly; true IMAS pulses (HDF5 / IMAS-netCDF) are the interchange format materialised at the boundary by the egress builder. Guardrail: a round-trip test (zarr → IDS → validate() → zarr) runs in CI so the store cannot drift into a private schema; COCOS/units/provenance are carried as store attrs.
  • Placement in the codex → distil → ambix pipeline (io-contract-home decision): imas-codex discovers facility data and generates the mapping transformations (the standard-names LLM pipelines build off it); imas-ambix distils to the tensorized store and trains. The four-layer split: name semantics in ISN/ISNC (managed there, hardened there — see above); store mechanics — zarr layout, ingest/egress transcoders, round-trip validators, machine-description ingest — in nova.io, depending on ISN/ISNC; facility mapping discovery in codex (emitting maps that validate against ISN's published schema, no nova dependency); distil pipelines in ambix. No new repository is created — the "third repo" for semantics already exists as ISN/ISNC.

Done-when: a MAST or ITER test shot ingests once and re-reads at cached-store speed (≥100× the AL full-get, per the measured baseline); a synthetic run's results egress as a valid IMAS equilibrium IDS readable by imas-python at the written DD version.

§ Decisions

Repository mechanics — three viable routes: (a) new imas-nova repo populated by curated transfer (clean dependency/CI baseline; nova untouched); (b) in-place major refactor of nova — current state parks on a protected legacy branch (assembly work continues there, destined for its own repo), main becomes the refactored core as a 2.0 (keeps the nova name, identity, history, and test set; assembly branch is frozen against the old frame API until extracted); (c) rename nova → imas-nova and strip later. The refactor content is identical in all three — this decision is identity, history, and branch-discipline mechanics.

User decision 2026-07-23: keep nova's name, identity, history, and core test set; assembly is live and continues on the 1.x line while the 2.0 core refactor proceeds on a separate branch; assembly later extracts to its own repository with a hardened byte-identity gate (belts + braces: frozen baseline branch AND golden characterization suite carried to the new repo).

Identity-cache storage backend: zarr store (recommended — group deletion works, matches ambix's existing dependency, chunked/lazy reads) or keep nova's netCDF-group layout (proven, but eviction rewrites whole files)?

Frame-core migration path: build the columnar store directly (recommended — the SoA store is already latent in metaframe.data and the consumer API is narrow) or ship a composition-over-pandas wrapper first and hollow it out behind the accessor API?
