§1 — Executive Summary

This review covers the open-weight LLM landscape as of June 2026, scoped to models capable of serving as an agentic coding and tool-use backend for a physics-simulation harness on our Group A 4×H200 NVL reservation (4 GPUs × 143,771 MiB = 561 GB total VRAM, 650 GB CPU RAM, 30 cores, GPFS-backed model storage). The GPU node 98dci4-gpu-0003 is currently IDLE — all four GPUs report 0 MiB used, 29–30 °C, 0% utilisation as of the June 4 inspection.

Two models stand out as actionable next steps requiring no additional download:

  • DeepSeek V4-Flash at reasoning_effort="xhigh" — already installed (149 GB), costs nothing to test, and evidence shows it reaches Claude Sonnet 4.6 Max-mode quality (Artificial Analysis Intelligence Index 47) at maximum thinking budget. The underwhelming results seen at default effort are well-explained by this gap; testing high-effort is the immediate priority.
  • MiniMax M2.7 — already installed (215 GB, minimax-m2-7 profile). Scores 56.22% on SWE-bench Pro, competitive with the frontier MoE tier. Previously limited by a FP8 GEMM kernel bug on this node; the Triton fallback path (already configured in the profile) delivers ~17 tok/s — usable for agentic harness work.

Top new download candidate: Qwen3-Coder 480B/35B (FP8) — approximately 250 GB on disk, ~250 GB live VRAM footprint, leaving ~310 GB for KV cache. Apache 2.0 licence, purpose-built for coding agents, 67% SWE-bench Verified (open-weight state-of-the-art), fully supported by SGLang and vLLM on our H200 hardware.

Three otherwise compelling models do not fit the 4×H200 budget: GLM-5.1 (754 B/40 B, FP8 weights ≈ 756 GB — needs 8×H200), MiMo-V2.5-Pro (1.02 T/42 B, weights > 1 TB), and Kimi K2.6 (1 T/32 B, already tested — CPU-offload at 5 tok/s is too slow for interactive agent use).

§3 — Candidate Models: Full Review

3a. DeepSeek V4-Flash (installed)

Architecture: 284 B total / 13 B activated sparse MoE; CSA+HCA hybrid attention; FP4 experts + FP8 attention/dense; 1 M context. Weights 149 GB (already on GPFS). Measured throughput: ~110 tok/s on 4×H200 in the Group A reservation.

Reasoning effort: V4-Flash supports reasoning_effort values of low, medium, high, and xhigh (maps to maximum thinking budget). At default effort the model was previously found underwhelming for agentic tasks. Evidence from Artificial Analysis shows V4-Flash at xhigh reasoning reaches Intelligence Index 47 — identical to Claude Sonnet 4.6 in Max mode, at roughly 1/90th of the per-token cost. For simple agentic tasks V4-Flash at high effort performs on par with V4-Pro.

Recommendation: Test immediately. No download required. Set "reasoning_effort": "xhigh" (or equivalent thinking.budget_tokens parameter) in the SGLang serve call or client request. If this closes the quality gap the model is already deployed and the fastest option on node (~110 tok/s).

3b. MiniMax M2.7 (installed)

Architecture: 230 B total sparse MoE, ~10 B activated; 200 K context; FP8 native (float8_e4m3fn); GQA with 48 Q / 8 KV heads. 215 GB on disk. Measured throughput: ~17 tok/s via Triton fallback (FP8 blockwise GEMM kernel unsupported on sgl-kernel 0.5.x / H200 NVL — see profile notes).

Benchmarks: SWE-bench Pro 56.22%; Terminal-Bench 2 57.0%. These are frontier-tier MoE scores matching or exceeding GPT-5.3-Codex on the open-source leaderboard at the time of publication (April 2026).

Recommendation: Redeploy with the existing profile. Throughput at 17 tok/s is adequate for agentic harness use (agent turns are not latency-critical at the human oversight timescale). When sgl-kernel ships a working CUTLASS FP8 path the throughput ceiling rises substantially.

3c. Qwen3-Coder 480B/35B — top new candidate

Architecture: 480 B total / 35 B activated sparse MoE; hybrid attention; 7.5 T training tokens with 70% code focus; Apache 2.0 licence. FP8 checkpoint available as Qwen/Qwen3-Coder-480B-A35B-Instruct-FP8 on Hugging Face. Disk size ~250 GB (FP8). VRAM footprint at TP=4 on H200: ~250 GB total, leaving approximately 310 GB for KV cache — substantial long-context headroom.

Benchmarks: SWE-bench Verified 66.5–67.0% (open-weight state-of-the-art as of July 2025, still highly competitive in mid-2026); matches Claude Sonnet 4 on multi-turn agentic coding benchmarks. Purpose-built for coding agents — training was structured around tool-rich, long-horizon software engineering tasks.

Inference: SGLang and vLLM both have first-class support with vLLM Recipes providing an explicit Qwen3-Coder deployment guide. TP=4 is standard; no known kernel compatibility issues on H200 NVL with sgl-kernel 0.5.x.

Download: Must be fetched from a standard compute node (outbound network; betelgeuse GPU nodes have no egress). Submit a download job to sirius/rigel partition pointing the HF cache at /work/projects/imas_gpu/agents/qwen3-coder/. Estimated download ~250 GB from Hugging Face Hub.

Recommendation: Add a TOML profile and submit download job. This is the highest-capability model that fits the 4×H200 budget cleanly without CPU offload.

3d. MiMo-V2.5 (310B/15B)

Architecture: 310 B total / 15 B activated sparse MoE; 256 routed experts; hybrid SWA+global attention (5:1 ratio, ~6× KV reduction); 1 M context; native omnimodal (text, image, video, audio); FP8 weights. Disk/VRAM ~310 GB (FP8). MIT licence. Released 2026-04-22 by Xiaomi as XiaomiMiMo/MiMo-V2.5.

Benchmarks: SWE-bench Pro 56.1%; Terminal-Bench 2 65.8%. The Terminal-Bench 2 score at 65.8% is especially strong — terminal/shell tool use is the primary interface for a physics-simulation harness.

Inference: SGLang recommended (official quickstart uses tp=8 / dp=2); TP=4 is viable given 64 Q-heads / 8 KV-heads both divide evenly. No known compatibility issues. Has an MTP speculative-decoding head (329 M params) that can boost throughput.

Note on MiMo-V2.5-Pro: The Pro variant (1.02 T / 42 B activated) posts stronger scores (SWE-bench Pro 57.2%, SWE-bench Verified 78.9%, Terminal-Bench 2 68.4%) but requires >1 TB VRAM — does not fit the 4×H200 budget without CPU offload.

Recommendation: Viable alternative to Qwen3-Coder if omnimodal input (vision, audio) becomes relevant to the harness. Download ~310 GB.

3e. Mistral Medium 3.5 (128B dense)

Architecture: 128 B dense transformer; FP8 pre-quantized (E4M3, vision tower + lm_head in BF16); 256 K context; multimodal (vision). Released 2026-04-30 by Mistral AI. Apache 2.0 licence. EAGLE speculative decoding available (+1.41× throughput, 4 GB overhead). Disk ~134 GB (FP8).

Benchmarks: SWE-bench Verified 77.6% — the highest SWE-bench Verified score among models that fit 4×H200, though this is the original (easier) Verified benchmark rather than SWE-bench Pro which better differentiates frontier agentic performance. Supersedes Devstral 2 as Mistral's primary open coding model.

Inference: vLLM and SGLang both officially supported. Fits 4×H200 with massive VRAM headroom (~427 GB free for KV cache at FP8). Minimum production recommendation from Mistral is 4×H100 80 GB, which we exceed.

Recommendation: Strong contender if you want a dense model with a simpler deployment profile. Lower complexity than MoE routing. Consider as a comparison point alongside the MoE candidates.

3f. Devstral 2 (123B dense)

Architecture: 123 B dense transformer; 256 K context; Apache 2.0. Built in collaboration with All Hands AI (OpenHands scaffold). Disk ~123 GB (BF16), ~62 GB (FP8 if quantized). SWE-bench Verified 72.2% — SOTA open-weight agent at time of release (December 2025), still competitive in mid-2026. Devstral Small 2 (separate model) scores 68.0% at 5× smaller scale.

Recommendation: Now superseded by Mistral Medium 3.5 (same licence, same family, 5 points higher SWE-bench Verified). Prefer Medium 3.5 unless you have a specific reason to use the purpose-built agent variant.

3g. GLM-5.1 (754B/40B) — does not fit

Architecture: 754 B total / 40 B activated sparse MoE; 200 K context; FP8 weights ≈ 756 GB disk. MIT licence. Released 2026-04-08 by Z.ai (formerly Zhipu AI). The first open-weight model to hold #1 on SWE-bench Pro (58.4%), surpassing Claude Opus 4.6, GPT-5.4, and Gemini 3.1 Pro at release.

Memory verdict: FP8 weights alone are 756 GB > 561 GB 4×H200 VRAM. The reference deployment guide specifies 8×H200 or 8×H100 SXM5. Does not fit the Group A 4×H200 reservation. Would require Group A + Group B combined (full 8-GPU node) — a scheduling negotiation outside agent scope.

3h. Kimi K2.5 / K2.6 (1T/32B) — too slow on CPU offload

Both K2.5 (January 2026) and K2.6 (April 2026) are 1-trillion-parameter sparse MoE models with 32 B active per token. K2.6 scores 58.6% SWE-bench Pro and 76.8% SWE-bench Verified, reaching frontier agentic capability. K2.5 similarly strong at 76.8% Verified.

The K2.6 weights (555 GB) fit in GPFS but require KTransformers CPU offload on 4×H200 (560 GB VRAM just barely short of full GPU serving). This results in ~5 tok/s — confirmed in deployment. At 5 tok/s a 2,000-token agent turn takes 6–7 minutes; this is not viable for an interactive harness. K2.5 has the same constraint.

3i. MiniMax M3 — not yet available

MiniMax released M3 on June 1, 2026 — three days before this review. Parameter count is not yet disclosed. Architecture: new MiniMax Sparse Attention (MSA) giving ~15.6× faster decode at 1 M context vs M2; SWE-bench Pro 59.0% (best of the publicly available MoE tier); 1 M context; native multimodal. Open weights are due on Hugging Face "within ~10 days" of release (estimated ~June 10–11, 2026). Deployment size and 4×H200 fit cannot be assessed until weights are published. Watch for the HF release.

3j. Qwen3-Coder-Next (80B/3B) and Qwen3.6-27B

Qwen3-Coder-Next is a compact 80 B total / 3 B activated MoE (hybrid attention, from the Qwen3-Next base) purpose-built for coding agents and local development. It achieves performance comparable to models with 10–20× more active parameters on long-horizon tool use and recovery from execution failures. Trivially fits on a single H200. Qwen3.6-27B is a 27 B multimodal model scoring 77.2% SWE-bench Verified, within 3.7 points of Claude Opus 4.6.

Both are useful as lightweight scaffolding agents or sub-agents in a multi-agent harness (e.g. fan-out workers in a physics sweep) while a larger orchestrator model handles complex reasoning. Apache 2.0 licence.

The OpenRouter rankings page reports weekly token volume across all models. Direct extraction of the live leaderboard was not possible via automated fetch (page requires JavaScript rendering), but search results and secondary sources confirm the following open-weight models are actively trending on OpenRouter as of June 2026:

  • DeepSeek V4-Flash — high volume due to low cost; widely used for coding and agent workflows. The API exposes reasoning_effort with values low / medium / high / xhigh.
  • Qwen3-Coder 480B/35B — top open-weight coding model by token volume on Together AI and similar hosted platforms.
  • GLM-5.1 — trending strongly after topping SWE-bench Pro in April; primarily cloud-hosted given the 8×H200 hardware requirement.
  • MiMo-V2.5 / MiMo-V2.5-Pro — both listed on OpenRouter; the Pro variant (1T MoE) is more widely cited but requires large GPU clusters for self-hosting.

§6 — MiMo-V2.5 vs MiMo-V2.5-Pro: Which is on OpenRouter?

There are two MiMo models released April 22, 2026 by Xiaomi:

  • MiMo-V2.5 (XiaomiMiMo/MiMo-V2.5) — 310 B total / 15 B activated, MIT licence. Fits 4×H200. This is the self-hostable variant reviewed in §3d.
  • MiMo-V2.5-Pro (XiaomiMiMo/MiMo-V2.5-Pro) — 1.02 T total / 42 B activated, MIT licence. Stronger benchmarks (SWE-bench Verified 78.9%) but >1 TB VRAM. Does not fit 4×H200.

The OpenRouter listing at openrouter.ai/xiaomi/mimo-v2.5 points to the 310 B variant; openrouter.ai/xiaomi/mimo-v2.5-pro is the 1T Pro served via OpenRouter's cloud infrastructure. For self-hosting, only the 310 B base is viable on our hardware.

§7 — DSv4-Flash: Higher Reasoning Effort Assessment

The "underwhelming results" observed at default reasoning effort are consistent with the documented performance gap between V4-Flash default and V4-Flash-Max modes. Evidence:

  • V4-Flash-Max (reasoning_effort=xhigh) achieves Artificial Analysis Intelligence Index 47 — identical to Claude Sonnet 4.6 in Max mode, at ~1/90th of the per-output-token price.
  • For simple agentic tasks, V4-Flash at high effort performs on par with V4-Pro (the 2× larger model).
  • For complex agentic workflows, V4-Pro maintains an advantage due to its larger parameter scale — but V4-Flash-Max is substantially closer than default effort.

How to enable: In the SGLang serve request or client, set "thinking": {"type": "enabled", "budget_tokens": 32768} (or the equivalent reasoning_effort: "xhigh" if the DeepSeek-compatible API route is used). The existing deepseek-v4-flash profile may already support this — check the serve script for any --disable-thinking flag and remove it if present. No re-download required.
