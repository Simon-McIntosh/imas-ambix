§1 — Why: the machine changed and our geometry layer cannot see it

The census-crossval RCA (connectivity-topology-reader-engine-crossval-rca) exonerated the solve chain and localised the remaining real systematic to machine history: reconstruction residuals degrade ~2.5–3× in every topology class on later campaigns, and even the linear disc-seed read misplaces the field null there. This plan closes the root cause: we solve every shot with a machine description that stopped evolving at shot 13370, while the real machine kept changing underneath it.

The three-layer finding (evidence: corpus survey + literature chronology + FAIR-MAST API)

  • The modeled machine is frozen. The efm setup signature is a single constant value from shot 13370 to 30463 (~96% of the corpus; 3 signatures total, all transitions ≤13400). The energised coil complement (P1 solenoid, P2–P6, TF, error-field correction) is identical in every era — no PF or central-solenoid module was ever added or removed on MAST; the solenoid rebuild belongs to the MAST→MAST-U upgrade (2013–2020), outside this archive. The EFIT reference grid is 65×65 throughout. The magnetics geometry descends from detectors.dat_M4 — a pre-2004 configuration file.
  • The real machine changed. The 2007-08→2008-04 shutdown installed 12 in-vessel RMP/ELM coils between P4 and P5 (M7 start, shot ≥19031; Kirk/Nardon PPCF 51 124010); the set was upgraded to 18 coils (6 upper + 12 lower) at the M7/M8 boundary (~25404, 2011; Kirk NF 53 043007) — new in-vessel conductors (eddy-current paths) the passive model does not contain, and non-axisymmetric applied fields an axisymmetric solve cannot represent when they are energised. Off-axis NBI on MAST was achieved by displacing the plasma vertically up to 0.3 m (M7+), stressing position reconstruction in exactly those campaigns.
  • The data layer drifts. Working magnetics erode monotonically from ~103 channels (M5) to ~74 (M9), with named ccbv*/obr*/obv*/fl_* losses accumulating each era. The amm passive-structure group is absent from the shots' own zarr over a 21k–29k availability hole (0% at 23–25k, back to 100% at ≥29000) — a data gap, not hardware, and the residual does NOT recover where amm returns, so it is not the primary driver. MSE appears at ~20400; the error-field channels were relabelled at ~16–18k; the passive model itself was coarsened once at ~13455 (55→21 structures, 167→101 circuits).

§2 — Deliverable 1: the per-shot configuration registry (the shot map)

One versioned artifact mapping every archive shot to its machine and diagnostic configuration, with an accessor module so every consumer asks the registry instead of hard-coding shot thresholds. Per-shot record:

  • Campaign + era: campaign label (API), configuration era (registry-defined boundaries: 13370 geometry-freeze, 19031 RMP-12, ~20400 MSE, 25404 RMP-18, plus the amm-availability bands) — eras are the registry's own enumeration, each with a mechanism note and citation.
  • Coil/conductor state: geometry signature digest; RMP era (none / 12-coil / 18-coil); RMP energisation per shot where determinable (API rmp_coil for M8+; the RMP coil-current signals for M7 — signal identification is a rung task).
  • Sensor inventory: working pickup/flux-loop channel set (names) per shot from the local zarr scan; counts per group (amb/ama/amc/amm presence).
  • Diagnostics: MSE availability, Thomson era, per-shot signal-quality flags (API signals endpoint) for the channels the engine consumes.
  • Heating & scenario (future consumers): NBI SW/SS power fields (all eras), heating/plasma_shape/scenario/divertor_config (M8+ from the API; earlier eras from NBI power fields + preshot text where needed).
  • Tier provenance: L1 vs L2 membership per shot (L2 = the Ip-filtered, calibrated physics set: 11,865 shots vs L1's 15,969 — counts per campaign in the research notes §2b), including the 292 L2 rows with campaign "Unknown" (16332–25365) to resolve; per-shot free-text shot logs (preshot/postshot descriptions) retained as registry text fields for scenario mining.

Calibration cross-check instrument (from the tier survey): the engine consumes L1 raw sensors under our own absolute-calibration layer, while UKAEA's L2 magnetics carry their independent calibration — comparing the two per configuration era is a cheap, data-only test for the late-campaign sensor-calibration hypothesis, and belongs in the §3 validation rung alongside the vacuum-shot residuals.

Sources fused: FAIR-MAST bulk parquet + REST API (note: filters use $eq/$geq; several mcs_* fields 500 on select; plasma_shape/heating/rmp_coil/scenario null before M8), the local level-1/2 zarr scans (the corpus-survey scripts are the seed), and the literature chronology. Storage: a parquet/JSON manifest under the project's data manifests with the accessor in imas_ambix; exact location is an open decision below.

§3 — Deliverable 2: era-aware geometry and the unmodeled-conductor fix

  • Registry-driven tables. build_table_for_shot / campaign representatives key on the registry era, not the (too-coarse) efm signature alone: a table request for shot 26000 must know it is an 18-coil RMP-era machine even though its efm signature equals shot 13370's.
  • RMP conductor remediation. Add the in-vessel RMP coil casings/conductors to the passive model for shots ≥19031 (12-coil) and ≥25404 (18-coil): geometry from the FAIR-MAST geometry files/configuration PDFs (fair-mast GitHub); validate on vacuum/known-drive shots per era (the sensor-model residual instrument from the connectivity-topology-reader data-layer followup — that audit becomes this plan's validation rung).
  • RMP-energised handling. Registry flags RMP-energised shots; the axisymmetric solve either excludes them from gates or treats the n>0 applied field as a known nuisance (measured coil currents through their Green's columns for the axisymmetric component; the rest documented as out-of-model).
  • Sensor-set hygiene. Per-era channel sets from the registry (drop long-dead channels instead of fitting them; audit surviving channels' calibration on vacuum shots per era).

§4 — Deliverable 3: evaluation and metric integration

  • Stratification by configuration era. The census, crossval, label factory, and benchmark suites consume registry eras; the ad-hoc VALIDATED_BAND_MAX_SHOT = 23000 constant retires in favour of registry-defined bands (geometry-freeze / RMP-12 / RMP-18 × amm-availability).
  • Centroid-frame tolerance calibration. The measured current centroid is the locked stable datum for boundary metrics (decision below; implemented as centroid_dmed_cm in the crossval harness, commit 5393ded). Re-score the validated cohorts (the 128-slice spine split and the census validated-era band) in the centroid frame to calibrate its tolerance, then gate boundary quality on it.
  • Cohort cards. Every future evaluation reports its era composition (the RCA showed per-class numbers are meaningless without it).

§5 — Scope & non-goals

  • MAST only (shots 11695–30473). MAST-U (new solenoid, +17–19 coils, Super-X) is a different registry when we get there — the schema should not preclude it.
  • No solver-physics changes in this plan: the interior-null/axis work stays with interior-closure-hardening; ramp coupling with gpu-accelerated-labeler. This plan fixes what the solver is told about the machine.
  • M1–M4 out of scope (not in the archive).
