COCOS 17 / DDv4 Hardening

Ambix and Nova now expose one canonical scientific contract: Data Dictionary 4.1.1 with COCOS 17. Facility data remains immutable. Small reviewed maps describe source bindings and transforms; Ambix compiles them once per shot and applies the fused affine operation only to requested slices.

Landed outcome

Shipped. The obsolete COCOS-11 premise was replaced throughout the active geometry and Green-operator paths. A content-addressed MAST magnetics map, read-only lazy array view, exact DD/COCOS artifact checks, corrected Nova DDv4 probe authoring, and regression coverage now make the boundary explicit and fail-loud. No raw Zarr or IMAS data was changed, copied, or eagerly materialised.

DDv4 defines the probe projection as B_R cos(theta) - B_Z sin(theta). A MAST source angle of +90 degree therefore maps to -pi/2 rad and still reads +B_Z. The map requires a DD target path and structure index now; standard_name may remain null until the relevant Standard Name is accepted.

2 — Map ownership, storage, and versioning

imas-codex discovers; Ambix distils and applies. imas-codex receipts may carry candidate source paths, units, convention evidence, and calibration epochs. Nova contributes measured machine geometry and correction evidence. Those receipts are opaque review inputs, not runtime dependencies. Ambix publishes the accepted result at imas_ambix/data/maps/<machine>/<system>.json.

Each map has a semantic set_version and a canonical SHA-256 digest; Git versions the human review and the digest gives cache and artifact identity. A binding records source group/array/unit/COCOS, target DD path/index/unit/COCOS, conversion factors, evidence, blocked signals, and optional shot-valid affine calibration intervals. Compilation resolves an interval once and fuses unit, convention, and calibration factors into one scale and offset.

3 — Virtual Zarr interface decision

VirtualiZarr is well suited to inventorying existing chunks from metadata and expressing their references, but its virtual references do not by themselves perform the scientific affine transforms required here. Ambix therefore exposes a small read-only, Virtual-Zarr-style transform view: metadata access performs no chunk read, view[index] forwards exactly that index to the physical array and transforms only the returned values, while implicit whole-array conversion and all writes fail loudly. A future native VirtualiZarr manifest can carry the same map digest without moving transformation authority out of Ambix.

4 — Performance contract

On 98dci4-clu-3141 with Python 3.14.2 and NumPy 2.4.4, an 8192 × 64 float32 slice (2 MiB) took 0.603340 ms through a scale map versus 0.578455 ms for the exact direct NumPy multiply: 24.885 microseconds overhead, ratio 1.0430, and 3.476 GB/s effective throughput. A fused affine map took 0.922165 ms versus 0.882755 ms for the matching multiply-plus-in-place-add baseline: 39.409 microseconds overhead and ratio 1.0446. Packaged map load-plus-validation took 63.182 microseconds; shot compilation took 20.322 microseconds. The hot loop contains no schema walk or evidence parsing.

5 — Reader, cache, operator, and Nova hardening

  • The Green operator and every production projection site use one project_poloidal_field implementation; tests and diagnostics share it.
  • Machine artifacts require DDv4/COCOS 17, read through imas-python at the manifest's exact dictionary version, and disable Access Layer autoconversion.
  • The legacy geometry-table cache remains byte-for-byte untouched. Its source angles are transformed in memory and its canonical signature is recomputed; newly written cache metadata includes the map digest, DD target, and COCOS target.
  • Nova authors MAST source probe directions correctly into DDv4. Its published machine artifact now has semantic identity sha256:ec2f7c6015ac4b193e2f9bb4594b2a90e7ff9650bb5566d214c3aec39f179c88; Ambix pins the corresponding Nova commit.

6 — Calibration discovery and the remaining distillation

The evidence already supports the convention map: 11,154 MAST shots give unanimous sigma_Bp = -1; sigma_rho_theta_phi = -1 is near-unanimous; and 2,662 flux-loop slices across 60 shots give a 2pi ratio of 6.3007. Nova has also identified a seven-rung acquisition-scale ladder and measured candidate static gains including obr17 = 0.5011, obv04 = 0.8571, obv05 = 0.9449, and ccbv35 = 0.9474.

Those candidate gains are evidence, not automatic authority. The pulse-dependent obr05 = 1.1043 candidate and withheld obv11 are not promoted. The queued follow-up will distil exact per-campaign source paths, acquisition epochs, reviewed gains, and explicit blocked states into the same lightweight map schema without touching source data or waiting for stable Standard Names.

7 — Validation receipt

Nova's machine-description suite passed 60 tests. Ambix map and lazy-view tests passed 42 tests. The one-hour full Ambix run produced 2,487 markers before the scheduler stopped the last 1%; its two failures and five setup errors all traced to stale Nova pin constants and passed as a seven-test repair gate. The exact 25-test unexecuted tail then passed separately. The stitched receipt therefore covers all 2,512 collected tests: 2,490 passed and 22 skipped. The package was also built from a clean archive and inspected to contain the map, COCOS helper, lazy-view modules, and agent assets.

§ Decisions

Which convention is the canonical internal contract for Nova and Ambix?

DDv4 defines COCOS 17. Raw facility data remains immutable; source-specific conventions are normalized lazily through reviewed maps at the Ambix read boundary.

The user requires Nova and Ambix to be canonical COCOS 17/DDv4. imas-codex discovers source mappings; Ambix distils, versions, compiles, and applies them lazily without rewriting raw data. This supersedes the obsolete COCOS-11 premise.
