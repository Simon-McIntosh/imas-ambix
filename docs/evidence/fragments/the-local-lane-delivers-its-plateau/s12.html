The wait bound's figures read from a committed log

The ten-seed table and the think-time-drop sentence in §5 were true of a run whose log was never committed: it cites logs/margin-seeds.log, logs/s5-probe-early3.log and logs/s5-gate.log, and none of the three is in the repository. The figures themselves reproduce: the merged tree at this revision measures every value the table states, so the repair is the instrument, not the numbers.

What the landed revision measures

The think-time-drop run measures 16.0 s in both arms, not 35.25 s. The pool settles under the bound, so neither arm closes a slot for the wait and the two arms carry the same worst settled window. The 35.25 s figure was measured on the early-window calibration (mean think time 17.9 s) at an earlier revision of the rule; the landed revision calibrates from the committed fed window 04:45–06:40 UTC and runs the rule that is in the tree now, and on it the lane settles well inside the bound. 16.0 s is therefore the figure the plan section's done-when is asking for, and 35.25 s describes neither the current calibration nor the current rule.

The instrument

bound_seeds.py sits beside this fragment. Its run mode simulates the calibrated lane at the bound's demonstration margin (2.6), over the ten fixed seeds, both arms, and then the think-time-drop run at the default margin in both arms, and writes logs/s5-ten-seeds.log: each seed's bounded and bound-disabled maximum settled window, the number of settled windows over 45 s in each arm, the bounded arm's count of documents closed for the wait, and the think-time-drop run's worst settled window in both arms. Its check mode reads that log and the §5 fragment and fails unless every figure the fragment states is the log's and every log the fragment cites is a file in the repository. The run was made on all_debug; the log's header records the module path and working directory it resolved from.

check also holds the reuse itself. Two nearest-rank rules agree on every input, so a second one written into this script would produce a log indistinguishable from the owner's and no figure could betray it; the check therefore asserts where the window percentile comes from — that the callable is lane_utilisation.percentile_or_none, that the window function calls it, and that this file defines no percentile body beside it — and fails if a copy has grown back. The guard was proved both ways: a copy cutting its windows with a restored local body is refused, and so is a copy carrying a spare body that nothing calls, while the shipped script passes.

The reproduction is exact: at margin 2.6 seed 0 carries 34.50 s bounded and 47.00 s bound-disabled, seed 4 carries 43.25 s and 49.50 s, seed 9 carries 44.00 s in both, and the bound-disabled arm crosses 45 s on seeds 0, 1, 2 and 4 and on no other seed. Every bounded arm stays under 45 s in every settled window.

Negative control

The same check, run on the §5 fragment as this node found it, fails naming the three logs it cites and the log it is told to read: none of the four exists. That is the state the section was written against, and it is why the table could not be checked against a committed run.
