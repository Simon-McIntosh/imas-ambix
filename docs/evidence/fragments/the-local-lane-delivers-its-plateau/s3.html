imas_ambix/agent/lane_sim.py holds the lane simulation and its calibration from router receipt rows: think time between a run's requests with the gate wait taken out, per-request completion tokens and time to first token, requests per run, and the per-stream rate at each in-service count. Its rule mode publishes slots by calling the router's _AdmissionLedger, and the worker count a reproduction is held at is the mean live_runs that ledger publishes over the same rows, so neither the slot arithmetic nor the liveness rule is a copy. The committed test data are three windows of 18 November receipts (00:00-02:00, 02:00-04:45, 04:45-06:40 UTC) with the caller address, session and account fields removed, under tests/data/lane_receipts/.

Measure, the fed window reproduces. Calibrated from the committed 04:45-06:40 rows and held at the 23 live runs the ledger publishes for that window (mean 23.43), the simulation delivers 444.1 tok/s against the excerpt's 434 tok/s (+2.3%, inside 5%) at a median gate wait of 3.75 s against 2.5 s (1.25 s over, inside 2 s), with 11.68 requests in service against the 11.10 measured. Negative control: the same run with every think time set to zero returns the plateau at 445.9 tok/s but at a median gate wait of 11.17 s, 8.67 s from the measured figure, so the reproduction's wait criterion fails on it.
