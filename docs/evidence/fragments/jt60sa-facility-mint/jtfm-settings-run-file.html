Settings, the write command and the run file

Node jtfm-settings-run-file · date 2026-10-07 · plan jt60sa-facility-mint §8 · base 9b440888

One new module, packages/imas-alambic/src/imas_alambic/settings.py, owns resolution. resolve_settings(flags) is the only reader of IMAS_ALAMBIC_HOME, IMAS_ALAMBIC_MAP_PATH, IMAS_ALAMBIC_IDS_ROOT and IMAS_ALAMBIC_CACHE, and resolves each setting at the highest precedence that names it: a flag, then the variable, then a default derived from IMAS_ALAMBIC_HOME (maps/current and ids). Every setting is a Setting carrying its value and the source it came from, so imas-alambic config prints each value beside its origin. The cache falls back, past the variable, to the bundle's eddb_cache store role and then to ~/.cache/imas-alambic. The machine is never a variable: it is inferred when exactly one machine is reachable through the bundles, and left unset naming --machine when several are.

machine_map.discover_bundles no longer reads the environment: it takes the resolved map search path as a parameter, asks resolve_settings when none is passed, and the _BUNDLE_ENV_VAR constant moved to settings.py. The store-root owner resolve_description_store_root is renamed resolve_store_root; it gains kind (the refusal still says “description store root”) and an optional form that returns nothing for an undeclared role, which the cache lookup uses. Its callers moved: machine_map.py's description_store_root_path and catalogue load, and imas_ambix/data/description_reader.py. imas_ambix/data/bundle.py's _STORE_ROOTS gains eddb_cache from paths.JT60SA_ROOT, so the development cache stays where it was.

pulse_writer.py gains the public pulse_path(out_root, pulse, run) returning <out_root>/<pulse>_<run>.nc (e.g. 101154_0.nc), and write_pulse writes one imas.DBEntry netCDF file per pulse and run holding every description IDS of the shot's phase, refusing an existing file without --overwrite through PulseWriteError. Its hard-coded resolve_description_store_root("JT60SA_ROOT") lookup retires in favour of the resolved cache setting, and scripts/figures_jt60sa_signals.py's _read_pulse_ids reads through pulse_path. imas-alambic write takes positional pulses with --run, --machine, --maps, --out, --cache and --overwrite, and imas-alambic config prints the resolved settings.

Two defects the gate exposed. First, this node's earlier ruff format, at the repository's py314 target, rewrote two except (KeyError, ValueError, OSError): clauses in eddb.py into PEP 758 form, a SyntaxError on the Python 3.12 the engine declares (the wheel then failed to import virtual_zarr, eddb and pulse_writer in the clean venv while a 3.14 run hides it); the parentheses are restored and the whole engine parses under 3.12. The repository guards this class of defect for imas_ambix/agent/*.py but not for the engine. Second, imas-alambic declares imas-python without a netCDF backend, so a clean install cannot write netCDF; the demonstration therefore additionally installed netCDF4, and the packaging gap is recorded as a follow-on.
