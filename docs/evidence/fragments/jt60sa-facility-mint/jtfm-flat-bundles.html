Flat single-machine bundles: one machine named in bundle.json

Node jtfm-flat-bundles · date 2026-10-07 · plan jt60sa-facility-mint §9

A bundle may now name its one machine with the singular "machine" key in bundle.json instead of the "machines" list. Which key is present selects the addressing: a flat bundle holds machine_map.json and maps/<ids>.json directly under the bundle, while a multi-machine bundle keeps machine_maps/<machine>.json and maps/<machine>/<ids>.json. In packages/imas-alambic/src/imas_alambic/machine_map.py, MapBundle gains a single_machine flag that load_bundle_descriptor sets from the key present; machine_map_path and signal_map_path branch on it. A descriptor naming its machines both ways or neither way is refused with the existing MachineMapError, naming the bundle. Store roots stay declared under role names and resolve relative to the bundle, so resolve_description_store_root is unchanged.

The multi-machine addressing ambix ships is untouched: the ambix bundle.json declares machines (mast, diii-d, jt-60sa) and resolves exactly as before.

Tests in packages/imas-alambic/tests/test_flat_bundle.py pin both addressings, the two refusals, resolution of a synthetic flat bundle's catalogue, every signal map and its description store by machine name, and the cross-layout duplicate-machine refusal. The whole packages/imas-alambic/tests package passes in a clean uv venv --python 3.12 built from the imas-alambic and nova-cocos wheels alone, with no imas_ambix importable (25 passed).

Negative control: making signal_map_path ignore the single_machine key and always return the multi-machine maps/<machine>/<ids>.json path turns two flat-bundle signal-map tests red, proving the address branch is what the tests rest on.
