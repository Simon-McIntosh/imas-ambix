the local bundle version is written only after the push succeeds, atomically

Node jtfm-release-version-after-push · date 2026-10-08 · plan jt60sa-facility-mint §18 · node 98dci4-clu-2002 job 1281970

In imas_ambix/maps_cli.py, release no longer writes the local bundle.json before the push: stage_bundle already carries the version into the staged copy, so the local descriptor is written only after push_tree returns, and the read-and-restore of the original bytes on push failure is removed because nothing local changes before the push. _write_bundle_version writes to a sibling temporary file in the same directory and moves it over the original with os.replace, so neither a concurrent reader nor an interrupted write sees a partial descriptor.

Measure: tests/test_maps_cli.py runs whole at base 033d84d6 (27 passed) and head 640ea2fc (29 passed), each to a log ending in the pytest summary and an EXIT= line; the two added tests are a stubbed-push_tree test that reads the local descriptor mid-push and asserts it still names the deployed version, and a test whose os.replace raises and that asserts the original bytes are intact. The existing failed-push test still passes.

Negative control: moving the local write back before the push makes the during-push test fail (EXIT=1, test_release_leaves_the_local_bundle_unpublished_while_the_push_runs). uv run --no-sync ruff check imas_ambix tests packages exits 0. All tests use the stubbed registry with no network call.
