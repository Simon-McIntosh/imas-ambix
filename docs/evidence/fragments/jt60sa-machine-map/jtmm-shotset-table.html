jtmm-shotset-table: the frozen shot sets are keyed by machine, with a JT-60SA row

Node jtmm-shotset-table · date 2026-10-08 · plan jt60sa-machine-map §7 · imas_ambix/spine_bench/shots.py, imas_ambix/spine_bench/parity.py, imas_ambix/spine_bench/machine_artifact_arm.py

imas_ambix/spine_bench/shots.py now carries one table of frozen shot sets keyed by machine (FROZEN_SHOTSETS), each row bundling its shots and its version label. MAST's FROZEN_SHOTSET and SHOTSET_VERSION are kept as the names of its MAST row. A new JT-60SA row is the sixteen 2023 OP1 shots whose EDDB PSRC record is populated (the OP1 shot survey), labelled v0-jt60sa-op1-16. resolve_shotset_version resolves the set through the machine the shots declare, never from their digits, so a JT-60SA shot whose number coincides with a MAST id resolves against JT-60SA's row and can never be stamped under MAST's label, and a JT-60SA run resolves to its own label rather than AD_HOC_SHOTSET_VERSION. The parity guard (parity.py check_admissibility/evaluate/compare_paths) reads the row for the machine the caller declares and refuses an unmapped machine by name; MAST's labels and verdicts are unchanged, so every committed stamp reads as before. The artifact arm's resolve_geometry_source takes its evidence shot and channel shots from the declared machine's row instead of MAST's.
