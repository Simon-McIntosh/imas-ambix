The one SELENE PSRC reader returns the boundary above the X-point in metres

Node jtmm-selene-psrc-loader · date 2026-10-09 · plan jt60sa-machine-map §7

imas_ambix/data/selene_psrc.py reads a shot's SELENE reconstruction from the EDDB PSRC category and returns it as one frozen value, read_psrc_record. One PsrcRecord carries the boundary above the X-point, the X-point (calRX, calZX), the magnetic axis (calRp0, calZp0) and the plasma current (calIp), each with its own time base. The boundary is a PsrcBoundary holding one contour per time slice as a 1-D array in metres.

Packing and decode

surfABVxp is one packed record per slice in a 604-wide slot: a type marker and a point count, a 300-slot R block in millimetres, a second marker and count, a 300-slot Z block, the remainder zero fill. The decoder reads each block's count and keeps only the valid points, so no fill entry survives into the returned contour, and divides each block by 1000 so the record is returned in metres.

A uniform multi-entry unit list is served, a disagreeing one is refused

A packed multi-channel PSRC surface record returns a per-channel unit list whose entries all name the same unit. Both the client-side normalise_unit and the reader script's _unit inside REMOTE_SCRIPT now collapse a multi-entry list whose entries all agree to that one unit, and still refuse a list naming several distinct units. The two are kept in step by executing REMOTE_SCRIPT and running both over the same cases, so they cannot drift: the client mirror raises EddbRemoteError, the script raises a bare RuntimeError, and both name the multi-entry unit refusal.

Gate

tests/data/test_selene_psrc.py seeds a temporary on-demand cache by copying the real cached PSRC arrays for shot 100599 read-only out of /work/projects/imas_gpu/jt60sa/100599.zarr, and adds a synthetic surfABVxp packed in millimetres with zero fill. It asserts the boundary is in metres with the fill entries dropped, that the axis and X-point and current match the cached arrays at a sample time and carry the source time bases, that a stub extractor serving surfABVxp writes it through fetch_channels once and the record then reads it, that a stub extractor refusing the channel raises an error naming the shot and channel, and that an uncached channel with no extractor is likewise refused. Nothing under /work is written, and no test opens ssh.

tests/data/test_eddb_cache.py runs both the client mirror and the script's _unit over the agreeing and disagreeing cases, and serves a uniform ["mm", "mm"] unit list end to end through the reader script.

The node's declared negative control returns surfABVxp without the mm-to-m conversion. Under it test_boundary_is_in_metres_with_fill_entries_dropped fails (the first contour reads [1000., 1100., 1200.] against the expected [1.0, 1.1, 1.2]) at EXIT=1, while the head arm passes the same gate at EXIT=0.
