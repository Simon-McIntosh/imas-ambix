Blocked: the OP1 pf_passive loops carry no name for the struct-array selector to match

Node jtmm-catalogue-per-coil · date 2026-10-06 · plan jt60sa-machine-map §4

The per-entry selector landed by jtmm-static-entry-selector reads one named entry of the first struct array on a binding's dd_path and consumed that level (transform_engine._select_struct_array_entry). The pf_active coil-element arrays can be addressed this way, because the converter names each pf_active/coil. The OP1 pf_passive vessel cannot: the converter writes one loop per contiguous resistivity block (63 filaments at 7.76e-7 and 57 at 7.20e-7 ohm m) with no loop.name, and the two loops are ragged, so neither the selector nor an unselected read can materialise the 120 vessel filaments the section's identity test requires.

Reproduction (positive control and failure)

Read against the real store /work/projects/imas_gpu/jt60sa/machine_description through the netcdf / static-over-map engine. One binding, dd_path = pf_passive/loop/element/geometry/rectangle/r, source_rank = 1: OP2 reads, OP1 does not, and no selector value can be supplied because no loop carries a name.

The absence is confirmed at the store, not only through imas: OP1 pf_passive.nc carries no string variable under pf_passive/loop except ids_properties.version_put.*, and the only loop leaf written is the numeric pf_passive/loop.resistivity. The loops are genuinely unnamed, and struct_array_entry refuses the empty string.

Log: runs/r-20261006T031641983435-jtmm-catalogue-per-coil/jt60sa-passive-repro.log.

What unblocks it

Reading the OP1 vessel needs one of two changes, both outside this node's write paths: the converter (imas_ambix/data/selene_deck.py build_pf_passive) names each loop so the existing selector can address it (loop.name = "V1" / "V2", then a re-conversion of the store); or the engine's selector (imas_ambix/data/transform_engine.py _select_struct_array_entry) accepts an index for an unnamed entry. The catalogue cannot close the gap on its own, so it is not committed.
