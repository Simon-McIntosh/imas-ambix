Why the shape refusal blocks the goal

The EDDB wrapper returns a multi-channel array flattened time-major, and the extractor's remote reader folds a one-dimensional record to one flat row, so surfABVxp arrives as data width n_time × 604 with a time base of n_time. The on-demand cache's write path requires the data width to equal the time-base length, and the PSRC reader's decoder expects a (604, n_time) block. Neither matches the flat record, so fetch_channels raises before writing and the reader cannot cache surfABVxp through the extractor. This is the same reach the §6 inventory recorded: those multi-channel arrays "were read instead by a direct eddb_pwrapper probe", because the sanctioned reader could not reach them. The unit-test stub for the reader supplies a (604, n_time) record directly, so the suite passes while the live extractor produces a different shape.

Every quantity the reference loader needs beyond the boundary — the X-point (calRX, calZX), the magnetic axis (calRp0, calZp0) and the plasma current (calIp) — is already cached for these shots; only surfABVxp is outstanding, and it is the one the extractor cannot cache.
