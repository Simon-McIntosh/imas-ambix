The 26 type-6 magnetics/flux_loop entries are now named FL<L>-FL7 (FL1-FL7 … FL27-FL7, no FL7-FL7) in place of FL7-FL<L>, so the name reads as the difference the entry stores. Every other field of every entry is unchanged: the order, the indices_differential [7, L] pairs, the values, and the empty position and area all stay as they were. The OP1 and OP2 description stores and the maps/jt-60sa/machine_map.json per-entry bindings are regenerated under the new names.

Why the old name read backwards

DD 4.1.1 defines magnetics/flux_loop/indices_differential as loop(second index) − loop(first index) over the 1-based flux_loop array. Loop 7 is the reference, so each type-6 entry stores ψL − ψ7 and carries the indices [7, L] — reference written first. The old name FL7-FL<L> spelled the pair in the opposite order, so it read as ψ7 − ψL, the negative of the stored value; the new name FL<L>-FL7 reads as the stored difference itself. The rename moves no index, sign or value.

Regeneration and the array-equality check

The stores were rewritten in place through selene_deck.write_phase_description, after verifying each source deck's sha256 against the value its receipt records. The run directory script regenerate_jt60sa_store.py then read every flux_loop array back through imas at DD 4.1.1 and compared it with the pre-rename store: type, indices_differential, position, area and flux are equal element for element, and the only changed array is name, over indices 27–52, for both phases (regenerate_jt60sa_store.log, EXIT=0). The four non-magnetics netCDF files of each phase were hashed before and after and are unchanged.

The per-entry bindings in machine_map.json were regenerated with rename_map_flux_loop_bindings.py in the run directory (an adaptation of the staged-map flux-loop binding builder, not a hand edit). It rewrites the entry-name token FL7-FL<L> → FL<L>-FL7 and the binding-id token fl7-fl<L> → fl<L>-fl7 across the live map, refuses if any old-pair token survives, and re-serialises the JSON; it reports 26 entry tokens and 26 binding-id tokens rewritten (rename_map_flux_loop_bindings.log, EXIT=0). maps/jt-60sa/maps/magnetics.json is untouched: its flux-loop rules select by index, so the rename does not reach them.

Measure and the negative control
