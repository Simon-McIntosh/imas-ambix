EDDB FAME q scalars, read through fetch_channels

The FAME category (EDDB code 1850) holds 100 scalar channels, /FAME/APAVE … /FAME/ZZLI, enumerated with eddbreadTable(shot="E101154", cat="FAME"). It carries signed q scalars but no grid: QAXIS, Q95, QSURF, QEFF and the FBI variants QSURFFBI and QEFFFBI, beside TTCU (plasma current) and BTV (F=R·BT, the only BT-bearing scalar in the bank). Answer: the reachable OP1 equilibrium carrying both psi and q is a single shot

No store reachable from intr26-2 holds an OP1 equilibrium that explains the identified list's psi and q together. The pair exists on disk for exactly one OP1 shot — 101011, in /home/d240034/fbequ/EFIT95.DATA and LOCALDB/EQDSK/10/101011 — and for the whole list only in the decommissioned dbsvr17p EQDB (and its EQRV/EQEFIT siblings), whose eqdb=0 index resolves but whose fields return IRET 300. What is reachable for every listed shot with an eqdb=0 index, E101154 included, is the FAME EDDB bank's signed q scalars — enough for the q-handedness product, but not a flux grid or a q profile. The Web API serves discharge time series, not EQDB records, and is a separate SSL-VPN host.
