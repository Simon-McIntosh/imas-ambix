description store addressing: the map a shot selects names the store

Node jtmm-description-store-addressing · date 2026-10-05 · plan jt60sa-machine-map §4

Each packaged machine catalog now declares how its machine description is addressed: the store format (netcdf or zarr), the symbolic root name (resolved to a path defined in imas_ambix.data.paths), the layout (per-shot or static-over-map), and the source of a directed probe angle (acquisition-address or description). The StoreEngine.open seam receives the map the shot selected and the declared layout, so a static store reads {root}/{map name}/{ids}.nc for every shot in the map's range while a per-shot store keeps reading {root}/{int(shot)}/{binding}.nc. read_geometry_table takes format, root and angle rule from the loaded catalog and holds no comparison against a machine name; MAST returns its unchanged GeometryTable against its existing expectations.

The three description-store slots form one unit. A catalog that has no description store (a source-only catalog such as DIII&D) declares all three null; a partial set is refused at load, and a read against a catalog with no store raises DescriptionReadError naming the machine rather than resolving another machine's root. The zarr engine, which opens a directory per shot, refuses a static-over-map declaration instead of silently reading it per shot.
