Why re-authoring MAST no longer reproduces the pinned identity

tests/gs/test_artifact_resolution.py::test_re_authoring_reproduces_the_identity_the_package_pins fails on main because re-authoring MAST's description yields semantic identity sha256:f20d64dbde63756150fecd5a41d34a0d7a055900877370aae40a594ca7d039d5, while imas_ambix/gs/artifact_resolution.py PINNED_DESCRIPTIONS["mast"] pins sha256:8df7a0a6c3f6162dbe0f226660bc069f37de8eb69f0f7c80bbfedc2bd4be220c. Exactly one semantic field differs, in one entry, and it is a deliberate nova change — so the pin is stale, not the code broken.

What was compared

MAST's description was authored afresh with the package's own route, nova.imas.mast_geometry.publish_refined_artifact (what author_mast_machine_artifact calls), into a cache under this run's directory, never ~/.cache. The pinned artifact was read read-only from ~/.cache/imas-ambix/machine-artifact/sha256/16cb20357da22dac498813c7953c380871e3429648f793d6c87aad6c09937ebc (the object the failing test resolved; its own semantic identity recomputes to the pin, 8df7a0a6…, confirmed by parsing its manifest.json). The two manifests were compared over every field MachineArtifactManifest.semantic_identity() covers — the method hashes as_dict() minus files and oci, i.e. schema, dd_version, physical_digest, registry_digest, complete, unresolved_gaps, shot_ranges and field_evidence/channel_drive. The comparison is anchored to that computation rather than to field names, so no field is judged by name alone.

The single difference is sufficient and necessary. So no other semantic field moved, and no second change contributes to the drift.

The commit that changed it

The test's own docstring calls the pin "a tripwire against drift"; the tripwire fired correctly.

The plan's named suspects are ruled out. aff62b24 ("lift content-addressed store out of machine_artifact") touches only nova/database/content_store.py, nova/imas/machine_artifact.py and its tests; 28a8247b ("compose verified object publication") touches nova/database/content_store.py and nova/database/layer_fetch.py only. Recommendation

The physical and registry digests are unchanged, so the description still names the same machine; only its recorded semantics advanced.
