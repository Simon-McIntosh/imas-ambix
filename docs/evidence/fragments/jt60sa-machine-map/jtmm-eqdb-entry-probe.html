The callable entry, with no Fortran build

The EQDB record is readable through a shipped Python package that wraps a prebuilt shared library with ctypes. No rebuild is needed: the shared object is already on disk. Three source lines are load-bearing.

  • eqread_pac/default/Fledd.py sets the library path: 
    self.LibraryPath = fledd_dir + "/libFLEDD.so"   # fledd.pac/libFLEDD.so
    That default file does not exist there (only libFLEDD.so_rebuild lives in fledd.pac/). The prebuilt library that does exist is /analysis/lib/libFLEDDPIC.so, and it is passed explicitly through the constructor's libpath argument.
  • eqread_pac/db/Fledd.py loads it: 
    self.fledd_lib = ctypes.cdll.LoadLibrary( default.LibraryPath )
  • eqread_pac/db/FleddTool.py exposes the readable record: 
    def GetTimeList( self, eqdb, shot ):  out = self.Fledd.Eqlist_Get( eqdb, shot, nmax )
def GetEqData(  self, eqdb, shot, time ): out = self.Fledd.Eqdata_Get( eqdb, shot, time )
def GetEqItem(  self, name, *options ):  # by field name, int / float / string

Signature and environment. Python package: eqread_pac at /analysis/src/edas2/v2.2.1/edas_share/eqread_pac. Entry:

Module environment: the server Python 3.5.6 (conda env edas_dev at /analysis/anaconda3/envs/edas_dev, activated by the /analysis/bin/eslice and /analysis/bin/egis launchers). The underlying C symbols in the shared library are Fortran-underscore names: eqlist_get_, eqdata_get_, eqdata_set_, eqitem_get_, eqint_get_, eqdbl_get_, gtmfld_ (all in libFLEDDPIC.so). The transport beneath is /analysis/lib/JT60SAEQDB/libEQDBMSPIC.so (EQDBMS: eqdb_get_, eqdb_set_, eqdblist_, eqdbio_, eqdbsockclient_connect). The higher-level equilibrium entry is eqread_pac/eqread_main.py EQreadMain(fledd_tool).exec_( shot, time_s, eqdb, *psi_types ), with _connect_method="locallib" calling eqread.Eqdbget_direct( self, shot, time, eqdb ). Older prebuilt front-ends also exist (/analysis/bin/saeqread, saeqdb, and the SELENE pair getseldata + sel), but they are Fortran-driver wrappers, not a record-field reader.

Record fields (the reader's own schema)

The reader declares the record fields in eqread_pac/default/Fledd.py (NameList). Every field below is what GetEqItem(name) reads; integer fields are int32, floats float64, strings char. Grid geometry: NSR×NSZ points, from the two library variants (libEQDBMS.a and libEQDBMS_1025.a) either 129×129 or 1025×1025; NV is the SIV (flux-surface) mesh size.

Read through the entry: E101154

tool.GetTimeList(eqdb, 101154) was called for eqdb = 0..5. The FAME database (eqdb=0) returns 105 time slices, from 500 to 11500 ms (e.g. 500, 800, 900, 1000, 1100, 1200, …, 11300, 11400, 11500). The SELENE/eqdbms numbers (eqdb = 1..5) return zero slices — E101154 holds no SELENE EQDB record on this host, only FAME.

A populated field read could not be completed on this host: every tool.GetEqData(0, 101154, t) returned IRET = 300 (not 0), so GetEqItem then returned empty arrays for every field. The transport layer reaches alleqdbio with eqtyp=0, which dispatches to FMEQDBIO for FAME; the FAME data lives on the database server (echoFameHost = dbsvr17p, echoFameDir = /JT60SA_EQ/FAME3), and /JT60SA_EQ does not exist on intr26-2. So the record's field shapes above are the reader's declared schema and mesh variants, not a populated dump of E101154; the field names, groups and units are authoritative (quoted from NameList), and the 105-slice time list is a live read through the same entry.

Follow-on for the transport node: reading a populated record needs the FAME database server reachable (the socket client eqdbsockclient_connect in libEQDBMSPIC.so, or a synthetic record via Eqdata_Set(eqdb, time, path, len) from a supplied data directory). The 129×129 vs 1025×1025 choice maps to the libEQDBMS.a vs libEQDBMS_1025.a variants and is not selectable per-record at read time.
