The JT-60SA artifact producer

A single public entry, imas_ambix/gs/description_artifact.py::author_jt60sa_machine_artifacts, authors one verified machine artifact for each JT-60SA operating phase (OP1, OP2) from the phase description stores under maps/jt-60sa/machine_description/. It reads each phase's five IDSs through imas, writes them into a fresh IMAS HDF5 entry (imas:hdf5?path=<staging dir>, mode "x") — the directory form MachineArtifactGeometryReader opens and the same form nova's nova/imas/mast_geometry.py::write_and_reopen produces — and calls nova's generic layer to assemble, materialize and resolve the manifest. Only the five IDSs are staged, so the store's converter receipt.json and the source netCDF files are never artifact members: the netCDF is re-written in the IMAS HDF5 form rather than copied.

The identity the manifest carries is derived, not accepted as input for the geometry, registry and shot extent. One registry digest is built over a JT-60SA geometry registry spanning both phases; each phase's physical digest comes from that phase's own geometry content, taken through the same extractors the geometry reader uses — not from the container bytes, so library write metadata does not move it; each phase's shot range comes from that phase's first_shot and last_shot in the packaged machine_map.json, and its shot-range evidence is stated per phase: OP1 is observed (its description was checked against acquired OP1 pulses) and OP2 is inherited (EDDB holds no OP2 pulse, so its identity comes from the declared description alone).

The operator-ready evidence layer is not authored here. The producer supplies no field-evidence ledger and derives no channel drive map from the phase's drive topology in machine_map.json, so each phase artifact is created incomplete and its unresolved_gaps name both absences:

  • no field evidence ledger is authored — the same text on both phases.
  • the channel drive map is not authored from the OP1 drive topology (jt60sa-pf-drive-op1) in machine_map.json — for OP1; the OP2 gap names jt60sa-pf-drive-op2.

Completeness is derived, not hard-coded: the gaps are built from the evidence the phase actually carries, and the artifact becomes complete only when both are supplied — which this producer does not do. The final resolve_machine_artifact call therefore passes allow_incomplete=not manifest.complete.

The gate and what it measures

tests/gs/test_description_artifact.py holds eight tests, one per done-when claim, and exits 0 at the delivered head:

  • test_authoring_twice_gives_same_semantic_identity_and_physical_digest — authoring the same store twice carries one physical digest and one semantic identity.
  • test_phases_differ_in_physical_but_share_registry_on_disjoint_ranges — OP1 and OP2 carry different physical digests, one shared registry digest, and non-overlapping shot spans.
  • test_moving_one_pf_coil_changes_only_that_phase_physical_digest — moving one PF coil rectangle in a tmp_path copy of the OP1 store changes OP1's physical digest and leaves OP2's unchanged, so the digest follows geometry content rather than store layout.
  • test_each_artifact_resolves_with_its_own_expected_digests — resolve_machine_artifact verifies each artifact against its own expected physical and shared registry digest (at allow_incomplete=not manifest.complete, since the artifact is incomplete by design).
  • test_artifact_directory_reopens_through_imas_hdf5 — every artifact directory reopens through imas.DBEntry at its manifest's dictionary version with pf_active, pf_passive, wall and magnetics present.
  • test_artifact_members_are_the_five_ids_and_master_only — each manifest's member names are exactly master.h5 plus the five IDS .h5 files, with no receipt.json and no .nc file.
  • test_each_artifact_is_incomplete_and_names_both_gaps — each artifact is complete=False and its unresolved_gaps name the missing field evidence and the missing channel drive map. This is the test the negative control breaks.
  • test_op1_shot_evidence_is_observed_and_op2_inherited — OP1's shot-range evidence is observed and OP2's is inherited.

Gate commands, both run in the fleet allocation and captured once:

Evidence that could have failed

The declared negative control is: restoring complete=True with an empty unresolved_gaps makes the incompleteness test fail, logged with a non-zero EXIT and the failing test id. Applied literally — the producer's complete=complete, unresolved_gaps=gaps replaced by complete=True, unresolved_gaps=() — the incompleteness test fails while the other seven pass:

The failing test is the one that holds every phase artifact to the two absences this producer does not close, and it passes at the delivered head. The mutation was reverted and the head gate re-run green (8 passed, EXIT=0) before the deliverable was committed.
