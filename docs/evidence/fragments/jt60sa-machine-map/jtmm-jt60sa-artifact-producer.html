The JT-60SA artifact producer

A single public entry, imas_ambix/gs/description_artifact.py::author_jt60sa_machine_artifacts, authors one verified machine artifact for each JT-60SA operating phase (OP1, OP2) from the phase description stores under maps/jt-60sa/machine_description/. It reads each phase's five IDSs through imas, writes them into a fresh IMAS HDF5 entry (imas:hdf5?path=<staging dir>, mode "x") — the directory form MachineArtifactGeometryReader opens and the same form nova's nova/imas/mast_geometry.py::write_and_reopen produces — and calls nova's generic layer to assemble, materialize and resolve the manifest. Only the five IDSs are staged, so the store's converter receipt.json and the source netCDF files are never artifact members: the netCDF is re-written in the IMAS HDF5 form rather than copied.

The identity the manifest carries is derived, not accepted as input. One registry digest is built over a JT-60SA geometry registry spanning both phases; each phase's physical digest comes from that phase's own geometry content, taken through the same extractors the geometry reader uses — not from the container bytes, so library write metadata does not move it; each phase's shot range comes from that phase's first_shot and last_shot in the packaged machine_map.json, and each artifact is written complete with no unresolved gaps.

The gate and what it measures

tests/gs/test_description_artifact.py holds five tests, one per done-when claim, and exits 0 at the delivered head:

  • test_authoring_twice_gives_same_semantic_identity_and_physical_digest — authoring the same store twice carries one physical digest and one semantic identity. This is the test the negative control breaks.
  • test_phases_differ_in_physical_but_share_registry_on_disjoint_ranges — OP1 and OP2 carry different physical digests, one shared registry digest, and non-overlapping shot spans.
  • test_moving_one_pf_coil_changes_only_that_phase_physical_digest — moving one PF coil rectangle in a tmp_path copy of the OP1 store changes OP1's physical digest and leaves OP2's unchanged, so the digest follows geometry content rather than store layout.
  • test_each_artifact_resolves_with_its_own_expected_digests — resolve_machine_artifact verifies each artifact against its own expected physical and shared registry digest.
  • test_artifact_directory_reopens_through_imas_hdf5 — every artifact directory reopens through imas.DBEntry at its manifest's dictionary version with pf_active, pf_passive, wall and magnetics present.

Gate commands, both run in the fleet allocation and captured once:

Evidence that could have failed

The declared negative control is: deriving the physical digest from file bytes instead of geometry content makes the authoring-twice test fail after a rewrite of the same store, logged with a non-zero EXIT and the failing test id. Applied literally — the physical digest recomputed from the staged container bytes in place of the geometry payload — the gate fails:

FAILED tests/gs/test_description_artifact.py::test_authoring_twice_gives_same_semantic_identity_and_physical_digest
FAILED tests/gs/test_description_artifact.py::test_moving_one_pf_coil_changes_only_that_phase_physical_digest
========================= 2 failed, 3 passed in 25.54s =========================
EXIT=1

The failing test is the one the geometry-content digest exists to pass, and it passes at the delivered head. Two authorings of one store differ in container bytes (the manifests' file digests are unequal) while describing one machine; the bytes-derived digest moves with them, the geometry-derived digest does not. The mutation was reverted and the head gate re-run green (5 passed, EXIT=0) before the deliverable was committed.
