jtmm-machine-keyed-selection: the selection route is keyed by machine, with JT-60SA pinned per operating phase

Node jtmm-machine-keyed-selection · date 2026-10-09 · plan jt60sa-machine-map §7 · imas_ambix/gs/artifact_resolution.py, imas_ambix/gs/machine_identity.py, imas_ambix/gs/machine_selection.py

The resolution, identity and selection path was written for one machine: the pinned description was three module constants (PINNED_SEMANTIC_IDENTITY, PINNED_PHYSICAL_DIGEST, PINNED_REGISTRY_DIGEST), the registry was a cached MAST loader, and ArtifactMachineSelector resolved a description without ever naming a machine. JT-60SA has two physical identities — OP1 and OP2 are separate physical identities of one device — so a single pin and a single registry cannot express it.

The three constants retire into one table keyed by machine, PINNED_DESCRIPTIONS. Each row carries the semantic identity that survives re-authoring, the physical and registry digests resolution enforces, and the route that authors the row. resolve_machine_description and author_pinned_description take the machine and the shot's physical digest; the digest may be omitted only for a single-row machine, is refused by name when a two-row machine omits it, and a digest the machine does not hold is refused by name. default_registry takes the machine and caches one registry per machine: mast resolves to Nova's packaged registry and jt-60sa to build_jt60sa_registry_from_stores(), which derives the two phases' physical digests from their description stores. Any other machine is refused by name. identity_for_shot and the bare-digest form of identity_for_representation gain a required machine; and the table-based resolvers read the machine from the signature they are given. ArtifactMachineSelector gains a required machine, resolves its registry, acquisition read and geometry reader from it, and looks the shot's identity up first so the pin row and the artifact follow from the shot's own physical digest. A machine with no pin row or registry is refused when the selector is built. The JT-60SA shot set and the tests move to the jt-60sa slug the registry and the description artifact already use; imas_ambix/spine_bench/shots.py and the three spine_bench test modules were the outlier spelling jt60sa.
