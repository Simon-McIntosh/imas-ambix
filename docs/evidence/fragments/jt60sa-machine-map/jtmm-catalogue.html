Blocked: the static netCDF engine cannot materialise the coil-element array

The JT-60SA catalogue cannot be declared against the converted description store as it stands. Reading the store through the existing netcdf / static-over-map engine fails for every binding under pf_active/coil/element/…, which geometry_table_from_description requires to build the conductor families. The failure is in engine code outside this node's write paths, so the node stops rather than editing it.

Reproduction

A minimal catalogue naming the two maps, the netCDF store and a pf_active binding set was loaded and driven against the real store /work/projects/imas_gpu/jt60sa/machine_description/OP1. One non-ragged leaf reads cleanly, which is the positive control; the element-geometry leaves fail. RAggedness is visible directly: the twelve pf_active/coil entries carry element counts [40, 40, 40, 40, 16, 16, 16, 16, 16, 16, 6, 6].

The failure is raised by _read_ids_path at imas_ambix/data/transform_engine.py:210 (np.stack(rows) at the coil level) through _NetCDFStoreArrays.read, reached from transform_machine_description. The consuming caller is geometry_table_from_description → _conductors (imas_ambix/data/geometry_adapter.py:302), which walks families under pf_active/coil/element/geometry/.

Why no catalogue declaration avoids it

The static engine reads each binding by its Data Dictionary target and reconstructs the structure from that target, so every binding into the element geometry inherits the coil-level raggedness. There is no per-coil selector: a static-over-map binding resolves {root}/{map name}/{ids}.nc and reads the whole IDS path. The MAST catalogue's per-conductor binding families do not transfer, because each such family relies on the zarr engine returning a distinct per-binding array; a static netCDF binding that shares the target path returns the same whole array for every family.

A repair needs a change in transform_machine_description's engine (read ragged structure arrays, or accept a per-coil selector) or in geometry_table_from_description, neither of which is in this node's declared write paths, or a re-conversion of the store to a uniform representation. This node added only the store-root path constant JT60SA_DESCRIPTION_DIR and stopped.
