E101011 as the sign cohort's psi-carrying row

The cohort's psi half is implemented and tested. A G-EQDSK now reads into the typed EfitLabels record the convention audit consumes, and the cohort script adds E101011 as the one row whose equilibrium carries a poloidal-flux grid. The row's data half — the file itself and the cached channel series — could not be produced: the JT-60SA host was unreachable for the whole node, so 101011.geqdsk is absent from the corpus root and the row is omitted from the regenerated report rather than scored against fabricated numbers.

What landed

change
path
imas_ambix/challenge/loader.py load_geqdsk(path, *, time_ms=0.0) reads one G-EQDSK through eqdsk.EQDSKInterface.from_file into an EfitLabels record — flux grid, R and Z coordinates, boundary, magnetic axis, q95 interpolated at 0.95 normalised flux, and the vacuum field scalar. The file is read as positive-phi, psi-per-radian and the record keeps the stored psi, so the poloidal-flux relation is scored from the file's own values rather than a converted copy. The record carries the identified COCOS index.
scripts/jt60sa_sign_cohort.py Adds E101011 (E101011_EQDSK) as a row whose equilibrium half is that record, and reports the file's COCOS index and flux exponent in the fragment prose. The row is added only when the G-EQDSK is present at the corpus root; when it is absent the script prints that the psi row is omitted and still exits 0.
tests/challenge/test_loader.py Two tests write a small G-EQDSK under tmp_path and read it back: the record shape, grids, boundary point count, scalars and identified COCOS, and a second test asserting the file's psi sign is carried through rather than assumed.
tests/data/test_cocos_convention.py test_geqdsk_flux_row_scores_the_poloidal_flux_relation reads a synthetic G-EQDSK into the record and scores it as a cohort row: the poloidal-flux relation is scored, its sign matches the plasma-current sign, the flux exponent reads per radian, and the opposite-sign candidate is reported violated.

Gate evidence

The loader tests and the flux-row cohort test pass. The negative control negates psi in the tmp_path G-EQDSK and the flux-row test then fails with poloidal_flux_sign == -1 where the head arm reads +1, on a non-zero exit — so the scored relation is being read from the file rather than asserted.

Blocked

The G-EQDSK copy from /home/d240034/fbequ/EFIT95.DATA on the JT-60SA host did not happen. ssh -F ~/.ssh/config jt-60sa reached the login node and then failed opening the reverse tunnel at localhost:2222 — the remote end answered Connection refused, and every attempt over the node repeated it. The corpus at /work/projects/imas_gpu/jt60sa/ carries no 101011.geqdsk and no 101011.zarr, so neither the file copy nor the cached plasma-current, loop-7 and TF-coil series could be produced. Consequence: the regenerated sign report scores the poloidal-flux relation on no row, and the declared flux exponent stays undetermined. The jt60sa-source-cocos decision (COCOS 1 per EFIT G-EQDSK, contingent on psi reading per radian) is unchanged and unsettled by this node.
