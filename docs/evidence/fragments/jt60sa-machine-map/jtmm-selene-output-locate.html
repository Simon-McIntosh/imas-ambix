Location of the plasma-shape equilibrium for E101154

Three candidate locations were tested; the equilibrium record E101154 actually holds is the FAME index of the equilibrium database, an EQDB index other than eqdbms. The three results, each with its command and its return:

  • EQDB. The index-to-database map is the .eqdbms config files under /analysis/lib/JT60SAEQDB/eqdbms/ read by eqdball_path_put; eqdb_path_put prints the default root /JT60SA... as /JT60SA_EQ/EQDB (return 0). Listing the SELENE/EQDB index for the shot, eqdball 1 -s 101154, prints * No DATA *; eqdb -s 101154 likewise prints * No DATA *; and a sweep of every index through the reader (tool.GetTimeList(eqdb,101154) for eqdb in -3..8) returns 0 slices for every index except eqdb=0, which returns 105 slices. So the SELENE/EQDB index (eqdb=1, EQDB_PATH /JT60SA_EQ/EQDB) holds no E101154 equilibrium reachable from intr26-2, while eqdball 0 -s 101154 lists the FAME record's 000500 000800 ... 011500 ms (eqdb=0 is FAME; its .eqdbms/echoFameDir path is /JT60SA_EQ/FAME3 on dbsvr17p). Three source lines anchor this: eqdbget.f CALL ALLEQDBIO ( NEQDB1, 1, ISH, ITIME, IRET, 0 ) with NEQDB1 = MOD(NEQDB,100); echoFameDir prints /JT60SA_EQ/FAME3; eqdball maps eqtyp==0 to /JT60SA_EQ/FAME3.
  • EDDB. eddbreadCatTable() returns the 73-category catalogue ['CAM','CO2','Cryo',...,'FAME','...','VV','VVGS'] (irc 0); there is a FAME category but no SELENE category. Direct reads of candidate categories (SELENE, SEL, EQ, EQU, EQDB, FAME, MHD, EQL) for E101154 each return irc=1022 (name or category not in the catalogue). No EDDB category carries a SELENE equilibrium.
  • Run-directory file tree. The SELENE run directory is /analysis/src/SAselene_v2.0_forPSRC/RUN/ (referenced by the lead's ~/work/efit_jt60sa/extract_jt60sa.py as eqsle_path = "/analysis/src/SAselene_v2.0_forPSRC/RUN/EQSLE.DATA"). A bounded find /analysis -maxdepth 5 -iname "*101154*" returns nothing, and find ~ -maxdepth 6 returns only ~/work/efit_jt60sa/E101154_signals.npz (an EDDB signal export, not an equilibrium). The reader that consumes it

The equilibrium reader is the shipped eqread_pac Python package (/analysis/src/edas2/v2.2.1/edas_share/eqread_pac), which binds the prebuilt /analysis/lib/libFLEDDPIC.so through ctypes and exposes db/FleddTool.py GetTimeList(eqdb,shot), GetEqData(eqdb,shot,time) and GetEqItem(name); its selene/ subpackage holds the SELENE record readers (eqouta, eftout, eqbnd, eqgrd, flxfun, ...) and EQreadMain(fledd_tool).exec_(shot,time_s,eqdb,*psi_types). On the Fortran side the FAME reader is /analysis/lib/JT60SAEQDB/eqdbms/eqdbget.f SUBROUTINE EQDBGET(ISH,TIM,NEQDB,IRET), which dispatches through ALLEQDBIO. SELENE's own front-ends are /analysis/exec/getseldata.ex (driven by /analysis/bin/getseldata SHOT TIME) and /analysis/exec/SAeqread.ex. For E101154 the record the reader returns is the FAME one (eqdb=0); getseldata E101154 5.0 runs but reads only SELENE's EDDB inputs (e.g. dname 1626 S005, irc 0), not an EQDB equilibrium.

FAME read through the EQDB socket client from intr26-2

The EQDB transport carries a network client — the shared object /analysis/lib/JT60SAEQDB/libEQDBMSPIC.so defines eqdbsockclient_connect, eqdbsockclient_joinlist, eqdbsockclient_joineqio, eqdbsockclient_joinimage, eqdbsockclient_ftp, eqdbsockclient_close (confirmed with nm -D). It is reached from the Fortran reverse readers client_eqdbms.EQ32.Rev1/eqdbms/EQDB/eqdb_get_rev.f call SOCKET_EQDBLIST(1, s_shot, listwk, nlistwk, errcd) and eqdbio_rev.f call SOCKET_EQDBIO(3, ...), whose .eqdbms server is SERVER_NAME:dbsvr17p. The FAME record for E101154 does not read through this client from intr26-2. The call GetEqData(0,101154,500) returns IRET = 300 (quoted above), and its cause is that the server is not reachable from this host: the FAME server host echoFameHost = dbsvr17p has no DNS resolution on intr26-2 (getent hosts dbsvr17p empty), TCP port 22 to it is closed/filtered, and its data root echoFameDir = /JT60SA_EQ/FAME3 is not mounted (/JT60SA_EQ is absent). The FAME 105-slice time list is served from the local index (it lists), but the slice data is refused (IRET 300). A distinct return code from eqdbsockclient_connect itself could not be captured separately: the transport fails before a distinct socket RC is produced, because dbsvr17p is unresolvable. The socket client is therefore present and callable, but not usable from intr26-2 for E101154 while the FAME database server is unreachable.

Implication for the transport node: the SELENE equilibrium this section wanted to bind does not exist for E101154 in any form reachable from intr26-2 (no eqdbms slice, no EDDB category, no run-tree file). The only E101154 equilibrium record present is FAME's EQDB index (eqdb=0, 105 slices), and even that is unreadable here because its database server dbsvr17p is unmounted/unreachable. Scoping an EQDB transport to SELENE's record for E101154 needs a shot on which SELENE was actually run, or a mount of the FAME server.
