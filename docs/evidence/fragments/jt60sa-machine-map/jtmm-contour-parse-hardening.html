The coil_vv contour parse refuses any deck it would mis-slice

Node jtmm-contour-parse-hardening · date 2026-10-06 · plan jt60sa-machine-map §4

imas_ambix/data/selene_deck.py found the coil_vv contour block by shape alone: a bare positive integer whose next numeric row held five or more numbers. Any other bare count matched too, and the block that followed was sliced by label with no check on the runs, so a deck whose count line preceded an unlabelled row, whose run label was unrecognised, whose run held fewer rows than its =N declared, whose skins were absent, or whose chords did not form one closed polyline parsed to a wrong or open vessel skin without complaint. The header search and the block parse now refuse each of those decks.

Each refusal names the deck line it read. The skins returned from both real decks are unchanged (50 chords each, inner and outer, per phase), so the store is not re-converted and nothing under /work/projects/imas_gpu/jt60sa/machine_description is written.
