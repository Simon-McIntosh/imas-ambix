A lane that cannot size its engine now reads as open, bounded by the router gate, instead of publishing nothing. The selection is one pair of functions in imas_ambix/agent/lane.py, beside availability_percent: engine_headroom returns the engine's own figure — the published headroom when it sized, otherwise the numeric withheld.headroom estimate — and lane_headroom bounds that by the gate's admission.headroom, with the gate's figure standing alone when there is no numeric engine figure. RouterApp._publish_gate_snapshot uses it to set the top-level headroom and records the engine figure that entered the minimum as engine_headroom. live_panel.lane_block uses the same function when it derives availability for a document that predates the rule. withheld, sizing_verdict and sizing_reason are published unchanged, so a reader can still see that the engine refused to size. availability_percent follows from the clamped headroom and is published whenever the effective width is positive.

The worker-slot figure no longer goes null when the measured ratio cannot be formed. _AdmissionLedger.snapshot now assumes one request per run on a thin window — fewer than the minimum live runs, less than the minimum history, no keyed busy time, or a ratio that rounds to zero — so worker_slots is max(0, effective_width − live_runs), or 0 under a congested, full or paused verdict, and the per-session figures divide the same assumed capacity. requests_per_run stays null in that case and a new field worker_slots_basis reads assumed or measured, copied into the live block with the other worker-slot fields. The measured case keeps its figure and its basis, so a reader can tell a level from an upper bound. One request per run is the most a run can hold, so an assumed figure never overstates the measured one.

Interface decision, stated because it narrows the rule. The gate-bounded headroom is published for a lane reading — a document carrying a headroom, a withheld block or a sizing verdict. A document with none of the three (state: unavailable, the engine could not be read at all) keeps publishing no headroom rather than borrowing the gate's figure: the gate being open says nothing about a lane whose engine could not be reached, and a dispatcher reading "open" at an unreadable lane would dispatch into a refused request. This is the one place the implementation is narrower than the rule read literally; the rule's own rationale — a withheld reading falls through the dependency graph, so open is okay — does not hold when there is no reading to withhold.

Measure: the declared gate ran 187 passed across the lane, router and live-panel test files, the serving-interpreter parse guard passed (2 passed, 7 deselected), and uv run --no-sync ruff check imas_ambix tests exited 0. The new lane-publish tests assert by literal: usable engine 20 with gate 13 gives headroom 13; withheld estimate 27 with gate 13 gives headroom 13 and availability 81.25 with withheld and sizing_verdict still present; withheld estimate 3 with gate 10 gives headroom 3; a withheld block with no numeric estimate gives the gate's headroom; and effective width 0 publishes no availability. The worker-slot tests assert that 2 live runs with 100 s history at width 16 give worker_slots 14 with basis assumed and requests_per_run null, that the measured case keeps basis measured, and that a paused verdict gives 0. The declared negative control — publishing no top-level headroom when the engine sizing is withheld — failed three tests including the withheld-27 case, with EXIT=1.
