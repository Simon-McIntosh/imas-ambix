The lane document's admission object now answers the question a dispatcher asks — who is using the lane and how much room is left — beside the gate's own headroom. A trailing busy-time ledger keyed by the run id the request declared in its run-id header derives live_runs, requests_per_run and worker_slots, with window_seconds and samples published so no reader has to assume the averaging window. The key is the caller's declared identity, never the connection: one harness process on one login node resolves to a single caller bucket, so a connection-keyed count collapses a whole fleet into one run. A request that declares no usable run id is excluded from the ratio and reported as unkeyed_share, a share of busy time. The derived figures are withheld rather than guessed below three live runs or under the history floor, and an in-flight request counts to the moment of publication. The queue's four-field demand signal is unchanged; the lane document publishes the merged object, so the slot count and the headroom describe the same gate.
