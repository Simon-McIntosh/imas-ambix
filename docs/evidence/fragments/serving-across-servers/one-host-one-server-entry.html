One host is one server entry, however the registration spells it

Work at 814675eb, node one-host-one-server-entry. Placement accepted a registration's host only in the spellings the site's declaration itself carried, so a registration naming the node the way the node reports itself — the fully qualified 98dci4-gpu-0003.iter.org — resolved to no declared server. endpoints.json then published a second server entry named by that raw host while the declared entry sat empty: one machine listed twice, and every reader that iterates the servers array counted two places to look.

Reproduced before the repair. On the base revision, server_for_registration resolved 98dci4-gpu-0003 to the declared server and 98dci4-gpu-0003.iter.org to None, with the two spellings also giving different engine ids (gpu-0003:18810 and gpu-0003.iter.org:18810) because the cluster component is dropped only on a hyphen and never across a dot.

The change. registry._host_name returns the node name a spelling denotes — the domain suffix and the cluster component both removed — and both the declared-server index and the lookup of a registration's server and host go through it. An engine id is unchanged and still carries the spelling its registration recorded, because it names a port on one allocation rather than making a statement about the node; the grouping is the only place the two spellings are reconciled. Nothing is filled in that the declaration does not state: an engine on a genuinely undeclared host still appears under its own entry with an unknown family and card count.

The measure. tests/test_agent_site_servers.py gains both cases. A site whose single declared server is 98dci4-gpu-0003 with one registration on 98dci4-gpu-0003.iter.org:18810 publishes exactly one server entry, named 98dci4-gpu-0003, whose engines are ["gpu-0003.iter.org:18810"]; a registration on the undeclared another-node.iter.org keeps its own entry. The declared mutation — comparing hosts by their raw spelling again — publishes two entries and fails the first test with Left contains one more item: '98dci4-gpu-0003.iter.org', against one entry at the head. The three gate suites pass (61 tests) and whole-tree lint is clean.
