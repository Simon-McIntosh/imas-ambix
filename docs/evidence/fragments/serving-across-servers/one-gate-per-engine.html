The router keeps one _GenerationGate per engine instead of one for the whole lane. Each gate owns its own FIFO, width, width controller and admission ledger, and each is fed only the reading taken from its own engine, because the throughput knee is a property of that engine's hardware and configuration rather than of the lane. A gate that is full therefore delays only work bound for its own engine.

  • Resolution before queueing. A request's owner is resolved from the model id before it queues, and the engine's identity is the registry's own spelling — host short name and port, via engine_id_for_origin. A request whose engine is not up yet has no identity to key on, so it waits at a gate that belongs to no engine; the first engine to be gated takes over the process's original gate instead, which is what keeps a one-engine router queueing exactly where it did. Once an engine advertises the model, the request releases that engine-less wait and is admitted at the gate of the engine it is bound for, so it is never held to a peer's width nor refused naming a peer.
  • The control file. The flat keys remain the defaults for every engine. An engines map keyed by engine id overrides width, wait and pause for the map's own engine. A top-level paused is applied after the engine's entry and so still pauses every engine, which is what keeps the lane-cycle runbook working as written. A malformed engines map, or an entry that is not an object, is refused as a whole: the read warns and the gate keeps the flat defaults, so a typo never yields a partly applied map the operator would mistake for a completed retune.
  • Cut, shutdown and refusals follow the gate. _relay now reads its cut form and shutdown flag from the gate the request was admitted at, and every gate is stopped on the shutdown signal. A refusal row keeps the (router) upstream sentinel and names the engine it waited at in its reason column (gate expired; engine=gpu-0003:18800), the only free-text field a receipt carries.
  • The lane publisher feeds each gate its own engine. The primary engine's reading is taken exactly as before; every further engine's metrics are read and folded into that engine's gate, and a peer that cannot be read is skipped rather than blanking the document, whose subject remains the primary engine.

Measured. Two fake upstreams gated at widths 2 and 4 take six concurrent requests each: the narrow gate holds in_flight=2, waiting=4 while the wide gate reaches in_flight=4, waiting=2, so the wide engine runs at its own width while the narrow one is saturated — impossible under one shared queue at either width. The arrivals are stamped as well as counted: the wide engine's four land as one burst while only two of the narrow engine's six have been admitted, so the narrow queue held none of them back at any point in their wait. A request whose engine has not appeared yet reaches a width-4 engine that appears later while a width-1 engine is full and stays full, rather than timing out behind that engine's queue. An automatic-width reading fed to the first engine moves its width 16 → 36 and leaves the peer at 16. A gate expiry at a named engine writes one row with upstream="(router)", status="failed" and that engine id in its reason. The five pre-existing gate, admission, width-controller, worker-slot and router tests pass unchanged (84 tests across the gate, admission, width-controller, worker-slot, router and absent-upstream files).

Negative control. Applying an engine's own paused entry to every gate makes test_a_pause_in_the_engines_map_holds_only_its_own_engine fail — the peer's settings().paused reads True — while a top-level paused holds both engines either way.
