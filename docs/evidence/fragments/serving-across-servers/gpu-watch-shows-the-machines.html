gpu-watch renders the declared servers from the node probe

The renderer lives in imas_ambix/agent/gpu_watch/ and is reached through the gpu-watch console script. For each server declared in the published endpoint document it draws the card table (utilisation and memory, now and window mean), the host row, the conditions line moved from the serve grid, the node's SLURM job table, and one dim identity row per engine pointing at llm-watch. --server NAME limits the view; the default stacks every declared server. The reservation-group label is read from the server's own declaration, and a document that declares none renders a dash.

The on-node readings come from node_probe.NodeProbe, not from a private sampler: the card, host and job sections are the same ones the recorder and the retention pass consume, so physical card numbering and the meaning of an unread job table have one owner. NodeProbe.stream is the entry point a long-lived on-node step runs; a one-shot run takes a bounded window of it. The style module is the watch_style llm-watch already reads.

A declared server with no running job has no allocation for a card query to see through, so its block prints no job to sample rather than an empty card table, and a server on another host is reported as not sampled here rather than drawn from the local node's figures.

Repair: the declared power cap is a watt reading

SiteServerConfig.power_cap_watts is watts, while the draw beside it in the conditions line is a kilowatt figure. The line used the declaration unscaled, so a declared cap rendered as a figure a thousand times too large and the share of cap a thousand times too small — reproduced on the landed module with the reported values:

$ python -c '…conditions(reading, 700)…'   # 420 W draw, 700 W declared
{'kilowatts': 0.42, 'cap_kilowatts': 700, 'cap_percent': 0.1}
'conditions  temperature — mean / — max    power 0.42 kW / 700.00 kW cap    0% of cap'

The declaration is now divided before it is compared with the draw, and the same call returns what the truth is:

{'temp_mean': 58.0, 'temp_max': 61.0, 'kilowatts': 0.42,
 'cap_kilowatts': 0.7, 'cap_percent': 60.0}
'conditions  temperature 58.0°C mean / 61°C max    power 0.42 kW / 0.70 kW cap    60% of cap'

The regression test pins that arithmetic on the reported values (tests/test_gpu_watch.py::test_a_declared_power_cap_is_a_watt_reading_scaled_to_kilowatts). Reverting only the scaling line makes it fail on assert 700 == 0.7 with the same EXIT=1 the other controls report; the log is negative-control-repair.log in the run directory.
