RouterApp._select_engine places a key with no pin, follows the pin on later requests, and lets the pin go only on a pause, on the engine leaving the catalog, on a queue wait past the operator's bound, or on the key going idle past its 180-second horizon. Fifty consecutive requests under one session header all reach the same engine (test_fifty_requests_from_one_session_all_land_on_one_engine), measured against two engines bound to distinct loopback aliases so the pair is a pool rather than one server's rotation.

Placement counts pins per unit of gate width. A new key goes to the engine carrying the fewest pinned keys divided by its gate width, using an exact rational so two engines are never separated by floating-point rounding; a paused gate is skipped, and a tie falls back to the ranking that already decides a rotation — wider engine, then newer. The three departures are each recorded. A request row now carries routing: placed when its key had no pin, pinned when it followed one, failed-over when the pin no longer held, and null when no engine was chosen. The wait bound defaults to 30 s and is set in the gate control file. DEFAULT_FAILOVER_WAIT_SECONDS is 30.0 and a per-engine failover_wait_seconds entry overrides it, validated as a finite non-negative number at read time so a malformed value stops the read rather than silently pulling an engine's sessions (test_the_failover_bound_defaults_to_thirty_seconds_and_the_file_sets_it).
