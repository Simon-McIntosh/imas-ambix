A receipt row now carries the engine whose generation gate it queued at in a column of its own, gate_engine, rather than as a suffix inside reason. The two answer different questions: gate_engine names the queue, and reason names the event that ended the row. Until this change the engine rode in the free-text reason as gate expired; engine=<id>, so a reader counting refusals per engine had to split a prose field, and the reason column could not state anything else without colliding with it.

  • What the reason column holds now. Only what the shutdown release puts there: router shutdown for a gate that answered a held request because the process was stopping, router shutdown cut the relay for a relay the grace outlasted, and null everywhere else. The helper that composed the engine into it is gone.
  • Who writes the engine. RouterApp records it at the one refusal path that knows the queue: the gate-expiry and shutdown release, from the gate's own identity. Rows that never met an engine's gate -- relays admitted at once, requests refused before an owner was chosen, and callers that left mid-upload -- carry null rather than a guessed identity.
  • The identity is the registry's spelling. Host short name and port, so the field keys exactly as an operator reads that engine on an endpoint record or a control file's engines map. Pinned by a test that asserts the literal gpu-0003.iter.org:18810 for the origin http://98dci4-gpu-0003.iter.org:18810, written out rather than read back from the helper that composes it, so a regression in the spelling rule is caught instead of compared against itself.

Measure. The gate command over the router, receipt and telemetry suites ran at this tree and passed, 132 passed, EXIT=0; whole-tree ruff check imas_ambix tests passed. At the base revision the same gate fails on test_shutdown_signal_answers_every_gate_waiter_with_overload, because the shutdown row's reason read router shutdown; engine=<id> instead of the release's text alone. The negative control restores that suffix and the same test fails again, together with the gate test that reads the new column.
