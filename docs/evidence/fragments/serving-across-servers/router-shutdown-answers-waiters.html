A router restart now answers what it is holding instead of dropping it. serve_router chains the router's release in front of uvicorn's own signal handler, so on SIGTERM or SIGINT the generation gate stops admitting and every request waiting in its FIFO is answered 529 with Retry-After: 5 — the same retryable refusal the gate's wait bound already produced — before uvicorn begins closing connections. The lifespan handler keeps its existing cleanup.

The release is installed on the signal rather than in the lifespan handler because uvicorn reaches lifespan.shutdown only after it has waited timeout_graceful_shutdown on open connections, and that launch setting was unset, which means wait forever. The launch now sets it, defaulting to 30 s, and that is the grace an already streaming relay gets; one that outlasts it is cancelled and its receipt row records aborted with the reason router shutdown cut the relay.

  • The gate. _GenerationGate.initiate_shutdown() sets a flag and schedules a condition wake onto the loop, because the signal handler runs on the main thread outside the event loop. The flag outranks the disabled-width bypass, so a gate with admission turned off does not relay into a process already going away.
  • The receipt. Rows gained a reason field. The two shutdown paths set it (router shutdown for a gate expiry, router shutdown cut the relay for a cut); every other row leaves it null. Without it a shutdown expiry and an ordinary wait expiry both read failed, and a cut relay and a caller that left both read aborted.
  • A cancelled relay now records at all. The row for a relay was written after the cleanup awaits in its finally, and a task cancelled from outside raises CancelledError at the first await there — so the one row the shutdown exists to produce was the one skipped. It is written before the cleanup now.

The gate runs the router under a real uvicorn server in a subprocess against a fake upstream, holds three requests behind a full gate, and sends that process SIGTERM. All three answer 529 with Retry-After: 5 and their three receipt rows carry the shutdown reason; the relay in flight completes with 200 inside the grace. A second test sets the grace to 0.5 s, keeps the upstream blocked past the process's exit, and asserts one aborted row whose reason names the cut.

Negative control. With app.initiate_shutdown() removed from the chained handler, both tests fail and the waiters are answered 200 as the FIFO drains instead of 529 at the signal; the cut test fails on the missing shutdown reason. Logs: gate-head.log, negative-control.log, ruff-head.log in the run directory.

The runbook's restart budget is now a measurement rather than a warning. On 98dci4-clu-2068 (8 cores), process start to the first answered /v1/models against a fake upstream on a free port took 4.34 s cold and 1.30 s warm. Two samples, quoted as a range: the cold figure is the one a restart after a code deploy sees.
