A serve records the checkpoint it loaded

A registration carries a new optional checkpoint field, written by the generated serve script from its profile as <hf_repo>@<revision>. The profile's hf_repo and revision are joined at script generation (slurm.py); a profile that pins no revision writes <hf_repo>@unpinned, so an absent pin is visible rather than passed off as an identity. The published endpoint republishes it from the registration (_endpoint_from_catalog), for the same reason the topology is republished: the launch owns what it loaded, and the served name is deliberately held stable across a rotation, so the name cannot carry it. A record written before the field existed reads null and the document still builds. The recorder's serve_config gains model_path, read from the engine's own /server_info report rather than from the launcher, because every checkpoint has its own directory and the engine's resolved path is what identifies the weights a row was measured against.

In-scope measure: ruff check imas_ambix tests exits 0, and the 12 checkpoint- and serve-config-shaped tests across the three declared files pass (12 passed, 69 deselected). Negative control: with _merge_serve_config mutated to let the caller's (profile) model_path win over the engine's report, the as-reported test fails on a fixture whose engine path differs from the profile, giving 1 failed, 1 passed and EXIT=1 in the red run and naming test_record_receipts_records_the_engine_reported_model_path. The red log is the run's logs/negative-control-model-path.log.

Blocker — the declared gate cannot pass within this node's write scope. Publishing checkpoint on the endpoint entry is required by this section's own done-when, but the launcher rejects any such entry: clive.py validates each entry with set(entry) != required (imas_ambix/agent/clive.py:328), an exact seven-key equality, so the eighth key makes every entry read as incomplete and the launcher fails closed. Eight tests in tests/test_agent_endpoint_discovery.py drive the launcher and fail for that one reason (8 failed, 73 passed over the three declared files). clive.py is outside this node's write fence, so the required relaxation -- fail only on a missing key, as in not required.issubset(entry) -- is reported rather than applied. The guard lives inside the generator's launcher template (the template = r"""...""" block at imas_ambix/agent/clive.py:65-1020), not in a module-level function: import imas_ambix.agent.clive exposes only generate_clive_script, so the edit belongs in that template and reaches consumers on the next agent clive --deploy. That also fixes the release order: the deployed launcher fails closed on any unfamiliar entry, so the template fix has to be deployed before a serve writes the first checkpoint-carrying document, or every consumer's launcher refuses the catalog in the interval.
