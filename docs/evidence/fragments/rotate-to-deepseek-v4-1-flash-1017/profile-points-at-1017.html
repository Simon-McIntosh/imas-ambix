The profile names the 1017 release

ModelConfig gained an optional revision field, and the deepseek-v4-1-flash profile now declares the 1017 release by repository (deepseek-ai/DeepSeek-V4.1-Flash-1017), by the commit 1bae0e1088993b9b82de08f59de5be5a34e42170, and by a weights directory of its own (weights_slug = "deepseek-v4-1-flash-1017"). The directory matters because the update publishes weights at a commit of a repository rather than under a new repo id: one directory per release is what keeps two releases from sharing a shard set. served_name is unchanged, so the release answers to the one client-visible name deepseek-v4.1-flash.

The generated serve script moves exactly one line for this change, its MODEL_DIR, now /work/projects/imas_gpu/agents/deepseek-v4-1-flash-1017/model. The test asserts equality modulo the weights directory rather than a substring, so a serving setting that moved alongside the checkpoint would fail it. Against the base revision the profile's [model] block differs in three keys — hf_repo, revision and weights_slug — and only weights_slug is read by the serve generator, which is why one line is the whole difference.

The 48 shards already in that directory were verified against the repository's own listing at the pinned commit — size and SHA-256 per shard, all 48 matching — by SLURM job 1294295 on sirius. The log is shard-verify.log beside this fragment; its slurmstepd warnings are inherited TMPDIR noise from the five-day-old allocation the job was submitted from, not a fault of the run, whose last line reads EXIT=0.

The generated download script resolves the pin before it transfers anything and passes it on: the client is asked for --revision "$REVISION", and a models info --expand sha call through that same client runs first and ends the job if the repository does not publish the revision. Both call the same variable, so the check and the transfer cannot disagree about what was published. The refusal matters beyond a fast failure: a client that cannot resolve a revision follows the repository's default stream, which is the substitution the pin exists to prevent. Profiles declaring no revision are untouched — all nine were compared against the previous generator at a7d24c5a and generate byte-identical scripts, while this profile's script differs only by the REVISION line, the check and the flag (download-script-delta.log).
