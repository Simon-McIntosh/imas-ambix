Two backup profiles, pinned and downloading

Two candidate profiles exist in the catalogue carrying identity and weights, with their card count, host memory and engine tuning deliberately undeclared until a deployment is chosen, and both checkpoints are being fetched as resumable SLURM jobs on sirius. Revisions were read from the Hugging Face API at dispatch time, not inferred from a branch name.

Two catalogue invariants do apply to a profile nothing is served from yet, and both are declared in [slurm]: an endpoint no other profile holds (kimi-k3 18811, mimo-v2-6-pro 18812, against 18800–18810 already in use) and a core request inside the shared 30-core reservation (cpus = 12). Leaving them to the schema defaults made both profiles resolve to no port and to 30 cores, which the catalogue suite refuses: it requires every profile to hold a distinct port, and it refuses a device-resident engine that claims the whole reservation, since host cores are not the work for a vLLM serve and taking the ceiling leaves a neighbour pending on cores. The CPU-offloading ktransformers profiles keep 30 because cold experts are computed on the host; these are not those.

Why the MiMo profile tracks -MOPD

Xiaomi publishes the family as two checkpoints, -RL and -MOPD. The -MOPD model card names itself the upgrade of the -RL checkpoint and gives the reason that makes it the release for agentic use:

“Following the release of MiMo-V2.6, tool-call repetition emerged as one of the most noticeable issues in agentic settings: the model would sometimes issue the same or highly similar tool calls repeatedly, consuming time and context without making progress. Nothing fails outright, so it tends to go unnoticed. The MOPD stage handles it efficiently, with a short specialized-teacher run that converges quickly.”

— XiaomiMiMo/MiMo-V2.6-Pro-MOPD, README, “Important” callout and §1

The -RL card carries no equivalent statement, so a candidate chosen for agent work takes the checkpoint that names the agentic failure mode and its repair. The variant is a checkpoint choice, not a distinct model: served_name stays MiMo-V2.6-Pro, and only weights_slug (mimo-v2-6-pro-mopd) names which checkpoint is on disk.
