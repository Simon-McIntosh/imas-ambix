Why the MiMo profile tracks -MOPD

Xiaomi publishes the family as two checkpoints, -RL and -MOPD. The -MOPD model card names itself the upgrade of the -RL checkpoint and gives the reason that makes it the release for agentic use:

“Following the release of MiMo-V2.6, tool-call repetition emerged as one of the most noticeable issues in agentic settings: the model would sometimes issue the same or highly similar tool calls repeatedly, consuming time and context without making progress. Nothing fails outright, so it tends to go unnoticed. The MOPD stage handles it efficiently, with a short specialized-teacher run that converges quickly.”

— XiaomiMiMo/MiMo-V2.6-Pro-MOPD, README, “Important” callout and §1

The -RL card carries no equivalent statement, so a candidate chosen for agent work takes the checkpoint that names the agentic failure mode and its repair. The variant is a checkpoint choice, not a distinct model: served_name stays MiMo-V2.6-Pro, and only weights_slug (mimo-v2-6-pro-mopd) names which checkpoint is on disk.
