Model store audit — what the checkpoint store holds

The store under /work/projects/imas_gpu/agents holds thirteen checkpoint directories (a model/ subdirectory each) totalling 7.21 TB. The audit records, per directory, its size, the Hugging Face repository and commit its download metadata names, whether every shard its index names is present at the size the repository lists, the first shard's SHA-256 against the repository LFS object, the profile whose weights_slug resolves to it, the last receipt whose serve_config.model_path names it, and a keep/backup/prune recommendation. Nothing was deleted or modified.

Result

  • 12 of 13 directories match their repository's file listing shard-for-shard and size-for-size; 12 of 13 first shards hash to the recorded LFS object. The exception in both counts is glm-5-3-w4a8, whose repository (camel-ai/GLM-5.3-W4A8) answers HTTP 401 to an anonymous listing, so its sizes and hash cannot be checked upstream.
  • Positive control passes: deepseek-v4-1-flash reads deepseek-ai/DeepSeek-V4.1-Flash at commit dba1be0a40aa45a94ad051997016db3960a90277 with first-shard hash 886aebdafa08cc27bbae2165ed35bdfe0de9370bf88c1411283c155c6ae4ff89. Negative control passes: the completeness check on a scratch copy of the mimo-v2-5-pro index reports full arm complete=True missing=0 and short arm complete=False missing=1 when the first shard is absent.
  • An index's total_size is not a completeness instrument. minimax-m2-7 declares 480.8 GB against 230.1 GB of shards named by that same index, and minimax-m3 869.2 GB against 854.2 GB — with the local tree and the repository listing agreeing exactly in both cases. A byte-total comparison would have called two complete checkpoints truncated.
  • Eleven keep, one backup, one prune. glm-5-3-w4a8 is backup: the four-card GLM-5.3 weights, at 399.8 GB, held only here, from a repository that will not serve an anonymous listing. deepseek-v4-flash is prune: 159.6 GB, superseded by -0731, named by no profile, receipts silent since 2026-09-15. deepseek-v4-1-flash is unreferenced by any profile but is the rotation's rollback target and the positive control, so it is keep rather than a prune candidate.
  • Two directories, glm-5-2-4x and glm-5-3-int4, hold a Hugging Face download cache and no model/; both are abandoned downloads of checkpoints another directory already holds in full, or that no profile resolves to.
