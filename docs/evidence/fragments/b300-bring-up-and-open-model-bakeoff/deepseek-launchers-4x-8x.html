The deepseek-v4-1-flash profile now renders a complete serve script for a B300 server at four and at eight cards through --server and --gpus, with no new CLI option. ModelProfile.server_gpu_variants is keyed by the declared server name and then by card count, for_gpus(gpus, server=None) prefers a variant for the pair over one keyed by the count alone, and _scale_profile hands the resolved server on both the serve and the restart path. A server the profile names has a closed set of counts: asking for one it does not declare is refused with the declared ones listed rather than rescaled into an unreasoned topology. With server=None the lookup is unchanged, and the default script is byte-identical to the base revision's — pinned by digest, not asserted by eye.

Each rendered script is pinned on the lines that decide where it runs and how wide it is: for --server b300 --gpus 4, TP4/EP4, four cards, fp8_e4m3 KV, auto MoE runner, DSpark depth 5, a 4,000,000-token pool, 524,288-token context and the pinned sglang-dev-dsv41.sif under /work; for --gpus 8 the same topology at TP8/EP8 with an 8,000,000-token pool and a 48-request bound. The four-card pool is sized to the bound and the context rather than auto-sized, because the fused-MoE workspace allocates lazily outside the memory fraction.

Every Blackwell setting carries its source in docs/research/b300-launch-recipes.html: the container whose torch build was inspected for sm_100 rather than inferred from a version string, the JIT kernel path that compiles per device, the vLLM Blackwell recipe for parallel shape and KV dtype, and the capacity projection for the starting request bound. The memory fraction is the one figure carried over from the Hopper measurement with no Blackwell counterpart, and the document says so.
