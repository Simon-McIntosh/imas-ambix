What changed

imas_ambix/agent/serving_receipts.py stated a contract its own row no longer kept. The module docstring, the ReceiptRow section and the ROW_SECTIONS comment all said that a probe which failed, is absent, or did not run contributes no key at all, and that a present key always means a measurement. The jobs section breaks both sentences deliberately: a tick whose squeue read was due but refused carries a jobs key holding the failed-read marker (unread) with no count and no rows. The behaviour was right and the contract was stale — the dangerous ordering, because a reader who trusts the removed sentence would treat a marker as a measurement. Both statements now name the marker as the one exception.

The recorded defect, and its reproduction

The stale contract was the defect; the behaviour was already correct and already covered in tests/test_node_probe.py at the section level. What was missing is the assertion a receipt reader depends on, at the record boundary. The two removed sentences, quoted before the edit:

"a probe that failed, is absent, or did not run this tick contributes no key at all"
"a present key always means a measurement and an absent one never reads as a zero"

Against those, the recorder already produced, for a refused read, a record whose jobs key carries {"hostname": ..., "unread": "command-failed"} — the very shape the docstring said could not exist.

Measure

New test file tests/test_receipt_section_contract.py, three cases over the serialized row:

  • test_a_refused_job_read_and_an_absent_source_are_different_records — a tick whose squeue refused and a tick where the read was not due serialize to different rows; the failed-read row holds jobs, the not-due row does not.
  • test_the_refused_job_read_carries_the_marker_not_a_measurement — the marker arrives alone: no count, no rows; the key set is exactly {hostname, unread}.
  • test_an_answered_job_read_records_a_measurement_the_marker_case_lacks — a positive control: an answered read carries count and rows and no marker, so the marker assertion cannot pass vacuously.

Negative control

Declared mutation: making a failed squeue read omit the job-table section exactly as an absent source does. Applied as a scratch edit to build_receipt_row (drop the jobs section when it bears the marker) and restored. Under it the two contract tests fail (2 failed, 1 passed), which is the guard firing; the log's first line repeats the mutation verbatim. Red log: logs/negative_control.txt.
