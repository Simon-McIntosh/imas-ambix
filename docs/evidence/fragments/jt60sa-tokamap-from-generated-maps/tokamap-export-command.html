JT-60SA hand-built tokamap export

imas-ambix maps tokamap jt-60sa --out /work/projects/imas_gpu/jt60sa/tokamap/hand-built --withhold-undeclared-cocos wrote 6 IDS groups, 2 shot partitions (100001 and 101174), 12 mapping files and 172 entries: 50 machine-description and 122 signal entries. Exactly two bindings were withheld: jt60sa-op1-magnetics-b-field-pol-probe-poloidal-angle and jt60sa-op2-magnetics-b-field-pol-probe-poloidal-angle, both targeting magnetics/b_field_pol_probe/poloidal_angle without a declared source COCOS. The tokamap validator reported “Validation completed successfully” for the configuration, root globals and every partition's globals and mappings file.

Both magnetics partitions carry 17 concrete probe keys b_field_pol_probe[0..16]/field/data; their data_source values match magPbTC1..magPbTC17 respectively. Neither partition carries a wildcard b_field_pol_probe[#]/field/data.

libtokamap expects zero-based indices. Its index parser uses indices.push_back(std::stoi(num)); with no offset, so a request for [0] means the first entry. Its mapping lookup tests mappings.contains(path) on the generalised [#] path before substituting the concrete index. A wildcard would therefore shadow these probe keys.
