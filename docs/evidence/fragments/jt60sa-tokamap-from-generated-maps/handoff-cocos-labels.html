The hand-off COCOS label read as a Data Dictionary label

The generated-mapping importer now reads each row's cocos_label as a Data Dictionary cocos_label_transformation value plus none. A one_like or none row imports with its label and cocos_label_source appended to the rule's evidence. A COCOS-dependent label (ip_like, b0_like, psi_like, q_like, pol_angle_like, tor_angle_like, dodpsi_like or a grid_type label) imports as a draft rule held out of the draft signal maps as pending, naming the label, its source and the machine's undeclared source COCOS as the open item; maps tokamap --draft-signals lists it as withheld, so no sign is assumed. Any other value is refused by name. A null or absent cocos_label keeps the previous behaviour.

Focused tests: tests/data/test_generated_mapping_import.py covers the one_like evidence, the none import, the pending-ip_like rule absent from the maps, the unknown label refused by name, and the null label unchanged; tests/test_maps_cli.py shows the tokamap command listing the pending rule as withheld; tests/data/test_handoff_score.py counts a pending rule as imported, scored on target, index, channel and |scale| with the sign unscored.
