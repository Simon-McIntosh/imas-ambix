The hand-off COCOS label read as a Data Dictionary label

The generated-mapping importer now reads each row's cocos_label as a Data Dictionary cocos_label_transformation value plus none. A one_like or none row imports with its label and cocos_label_source appended to the rule's evidence. A COCOS-dependent label (ip_like, b0_like, psi_like, q_like, pol_angle_like, tor_angle_like, dodpsi_like or a grid_type label) is held out of the draft signal maps as pending only while the machine's source COCOS is undeclared; it is named with its source and the open source COCOS, and maps tokamap --draft-signals lists it as withheld, so no sign is assumed. Where the source COCOS is declared the row imports into the maps as usual, and a time row always binds to its value partner, pending or not, because a time coordinate is never COCOS-transformed. Any other value is refused by name. A null or absent cocos_label keeps the previous behaviour.

Focused tests: tests/data/test_generated_mapping_import.py covers the one_like evidence, the none import, the pending-ip_like rule absent from the maps, a declared source COCOS importing the dependent label instead, a zero source COCOS still holding it pending, the time row binding to a pending value partner, the unknown label refused by name, and the null label unchanged; tests/test_maps_cli.py shows the tokamap command listing the pending rule as withheld; tests/data/test_handoff_score.py counts a pending rule as imported, scored on target, index, channel and |scale| with the sign unscored.
