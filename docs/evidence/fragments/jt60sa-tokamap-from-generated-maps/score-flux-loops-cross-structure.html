Score flux loops and cross-structure contradictions

Three flux-loop rules on the 11:21:44Z JT-60SA magnetics hand-off (jt-60sa-magnetics-handoff.json, sha256 2d6a95486c8777aacd380f04…, facility jt-60sa, dd_version 4.1.1) import as COCOS-pending and the hand-built magnetics.json holds 27 flux-loop rules, yet before the fix the score read 0 agreeing, 0 conflicting and 0 sign-unscored for the structure. This node names the cause and makes the score report it.

Cause: the raw channel binds to a different store entry than the hand-built map uses

The magnetics hand-off carries psi_like rows for magFlxLp1, magFlxLp2 and magFlxLp6 targeting magnetics/flux_loop/flux/data. The machine-description store (OP1/magnetics.nc) orders flux_loop as the 27 single loops FL1…FL27 at indices 0–26, then 27 type-6 differential entries FL1-FL7 … FL27-FL7 at indices 27–53. The importer resolves each row's member_identifier ("1", "2", "6") against the store member names, so it binds the raw channel to the single loop: magFlxLp1→0, magFlxLp2→1, magFlxLp6→5. The hand-built map instead binds the same raw channels to the differential entries the raw MDAC channel actually carries (its own evidence records “Raw MDAC magFlxLp1 is SELENE flux loop 1, whose type-6 differential entry in the 53-loop store names [7, 1]”): magFlxLp1→27, magFlxLp2→28, magFlxLp6→32.

Agreement and conflict both key on the exact (target_path, target_index) pair, so a rule whose index differs from every hand-built rule matches neither test and was dropped with no trace. The scales agree in magnitude (the sign is unscored because the row is COCOS-pending), so the index is the only separator:

magFlxLp10+1.027−1.0
magFlxLp21+1.028−1.0
magFlxLp65+1.032−1.0

The importer cannot repair this from the hand-off alone: the raw channel's identity as a differential entry is facility knowledge the hand-off does not carry. The fix therefore belongs in the score, which now names the case rather than dropping it.

Fix: cross_structure and a full sign_unscored

Two changes in imas_ambix/data/handoff_score.py:

  • sign_unscored now counts every imported rule whose sign the import leaves unscored, agreeing or not. It previously summed only the agreeing rules, so a pending rule that did not agree left no trace. On this hand-off it moves the total from 0 to 3.
  • A new cross_structure list (per IDS, per structure and in total) records an imported rule whose source channel (source_group, source_array) the hand-built map serves on a different structure or element index, naming the imported target and every hand-built target.
