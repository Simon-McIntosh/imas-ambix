Each tier carries a run's opening into the query layer

Node srw-tiers-carry-openings · date 2026-09-29 · worktree imas-ambix-0405601943d2/srw-tiers-carry-openings

A compacted row states the opening value of each counter at the start of the run's contribution to its window. That opening was reaching the minute tier only. Re-compacting minute rows into an hour took the first minute row's closing value as the hour's opening, so the whole first window of a run was dropped from the figure; and the query layer's partitioned_total ignored the open block entirely, so a window answered from compacted files alone totalled nothing. This closes the tier chain and the query path together, so a window totalled from any single tier's file gives the figure the raw rows would have given, and deleting a raw file no longer changes a total.

What changed

  • imas_ambix/agent/telemetry_store.py reads a source row's open block when a compaction stride opens its first window for a counter, so an hour takes the opening the minute tier carried rather than the first minute row's closing. Raw-to-hour and raw-to-minute-to-hour now agree.
  • imas_ambix/agent/telemetry_index.py reads a compacted row's opening measurement (open.<path>) alongside its closing value in partitioned_total, and differences each run between them. _counter_runs carries the opening through with the reading, so a run whose first sample is a compacted row still totalises as closing minus opening.
  • tests/test_telemetry_compaction_runs.py asserts the tier chain and the per-tier totals, each through a TelemetryIndex built from one tier's file alone.

Negative control

Making the second compaction level take the first source row's closing as the hour's opening — a scratch edit — fails the three tier-chain tests: the chained hour opens at 2,000 where the direct hour opens at 0, and the hour file's total collapses to 0 against the 520,000 and 600 the raw and minute files give. The raw and minute assertions stay green, so the mutation isolates the second level and the query layer's opening read rather than the record as a whole. The scratch edit was reverted; the fix was restored before the gate above ran.

What this closes (review 79). The predecessor node's residual caveat was that the 520,000 equality held only for its own re-derivation over compacted rows, because partitioned_total did not read a compacted row's opening and an hour opened at the first minute row's closing. Both are now fixed and asserted through partitioned_total at every tier, so the equality between a raw window and the compacted file that replaces it no longer depends on a neighbouring row being present.
