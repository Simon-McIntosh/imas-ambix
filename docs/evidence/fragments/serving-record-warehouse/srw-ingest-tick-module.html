§5 — The scheduled ingest ticks in its own module

Landed imas_ambix/agent/telemetry_ingest.py: the process that owns the telemetry index alone, so a reader only reads. It exposes tick(index, directory, previous=…) — one pass, no clock, no loop — and run(index, directory, cadence=…), the scheduled loop, with a main entry point that names the index it writes explicitly rather than defaulting to the reader's cache path.

A tick remembers each source's (inode, size, mtime_ns) from the previous tick and hands the index only the sources whose fingerprint moved, so a source unchanged since the last tick is never opened. The inode is part of the fingerprint so a roll that repoints the live name at a fresh file is read rather than mistaken for the bytes the old name held.

Measure. Over a two-source fixture, the first tick appends all three rows (files_read == 2); an immediate second tick reads none (files_read == 0, files_skipped == 2) and opens no source whose mtime and size are unchanged, counted by patching Path.open. The index rebuilt from the receipts equals the appended index row for row, and no receipts file is opened for writing.

Negative control. An ingest that discovers and opens every source on every tick fails the open-count assertion; applied as a scratch edit and restored. Console: negative-control.log in the run directory.
