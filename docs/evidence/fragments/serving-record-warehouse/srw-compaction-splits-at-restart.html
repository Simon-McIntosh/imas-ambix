Compaction splits a window at a serve restart

Node srw-compaction-splits-at-restart · date 2026-09-29 · worktree imas-ambix-0405601943d2/srw-compaction-splits-at-restart

A cumulative counter restarts whenever its serving process is replaced, and that replacement happens inside one compaction window, on one host, over one boot. Grouping a compaction stride by host and boot alone therefore merged the two serves in one window into a single row whose counter was not real. Compaction now splits a stride at exactly the place the query layer already partitions a total: a shared run-boundary predicate that both compact_rows and TelemetryIndex.partitioned_total call. The compacted row also carries an open block giving each counter's value at the start of its run's contribution to the window, so a window can be totalled onwards without reading the window before it.

What changed

  • imas_ambix/agent/telemetry_index.py exposes counter_run_continues — the run-boundary predicate — and row_job_id. _counter_runs is refactored to call the predicate, so the run boundary is defined once.
  • imas_ambix/agent/telemetry_store.py groups compaction strides by (host, boot, job) and splits each stride into runs with telemetry_index.counter_run_continues. Each compacted row now carries job_id and a flat open block of dotted counter paths to their opening values.
  • tests/test_telemetry_compaction_runs.py holds the two layers to that one boundary.

Negative control

Restoring the host-and-boot-only grouping — a scratch edit that merges the stride and disables the run split — makes the two-rows test fail with a single merged row (assert 1 == 2), confirming the guard is load-bearing rather than vacuous. The scratch edit was reverted. The log records the run and the failure assertion.
