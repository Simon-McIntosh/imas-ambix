live_panel._median_from_histogram read the receipt's time-to-first-token buckets as disjoint counts, so it summed the cumulative bucket advances, overstated the window total, and landed the median on a high bucket's upper edge. It now reads them as cumulative: the window total is the advance of the topmost bucket, and the median is interpolated inside the bucket whose cumulative advance first reaches half that total. Replayed against the real recorded pair (0.4: 46, 0.6: 9386, 0.8: 22300, 1.0: 26210, 2.0: 28895, inf: 29940; and the same rows 0.6 upward plus 100), the old code returned 1.0 s and the fixed code returns 0.5 s. The fixture buckets in tests/test_live_panel.py were converted to cumulative form, and a new test carries the real bucket pair and asserts the interpolated value.
