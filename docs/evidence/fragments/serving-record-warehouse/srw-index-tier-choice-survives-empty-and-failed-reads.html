The index's one-tier choice survives an empty raw file and a failed read

Node srw-index-tier-choice-survives-empty-and-failed-reads · date 2026-10-02 · worktree imas-ambix-0405601943d2/0c4316b2-553f-4a0a-ae02-c42d88de747c/srw-index-tier-choice-survives-empty-and-failed-reads

The retention block's reading that “an empty or unreadable raw file counts as absent” was not satisfied by the tier selection, which chose the finest tier by filename alone. A raw receipts file the recorder has created but not yet written to therefore pinned the job to a file holding no sample, and its window read as uncovered while the minute tier that held the rows went unread. The samples dropped when a job moved off a tier were also removed before the newly selected tier was read, so a read that raised stripped the job's held samples for a replacement that never arrived.

What changed

  • imas_ambix/agent/telemetry_index.py: ingest drops from the offered set any raw file carrying no record line (_raw_has_no_row, reading the first non-blank line lazily through _holds_a_record_line), so the per-job selection falls through to the finest tier that holds rows. The drop of a job's deselected tier moves to after the read loop, so a read that raises leaves the previously held samples in place.
  • imas_ambix/agent/telemetry_ingest.py: the standing loop's DEFAULT_CADENCE_SECONDS is 60.0, and the module and its entry point describe the loop the fleet allocation's supervisor keeps running rather than a scheduled pass.
  • tests/test_telemetry_index.py, tests/test_telemetry_ingest.py: the empty-raw fall-through, the failed-read retention, and the sixty-second default.
