§5 — The ingest runs as an agent command and a scheduled service

Landed imas_ambix/agent/cli.py and imas_ambix/agent/slurm.py. imas-ambix agent ingest runs imas_ambix.agent.telemetry_ingest.run against watch.default_record_dir() and the watch index path at a 5 s default cadence, with --once for a single tick and --cadence to override it. generate_ingest_script models the scheduled service on generate_router_script's placement parameters — one CPU, 4 GB, no GPU, a job comment prefixed ambix-ingest — and agent ingest --dry-run prints that script while --submit hands it to sbatch.

The scheduled service carries a finite walltime rather than the standing router and lane-refresher services' --time=0. Those run for the life of the allocation; an ingest pass runs and exits, so a finite limit lets the scheduler reclaim the node between passes. The limit is a separate finite constant used only by the ingest generator, leaving the standing services' unlimited value intact.

Measure. --once reaches the loop as a single iteration through a stub (iterations == 1, cadence 5.0); --cadence 0.5 reaches it as 0.5; the dry-run script carries --cpus-per-task=1, --mem=4G, --comment=ambix-ingest, no --gres=gpu, and --time=01:00:00. The one test that exercises --submit replaces the submitter with a stub, so no real sbatch runs under a test.

Negative control. Emitting time_limit 0 (unlimited) in the ingest script fails the dry-run test; applied as a scratch edit and restored. Console: negative-control.log in the run directory.
