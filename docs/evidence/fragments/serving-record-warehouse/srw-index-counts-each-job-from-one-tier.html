The index counts each serve job from one receipt tier

Node srw-index-counts-each-job-from-one-tier · date 2026-10-01 · worktree imas-ambix-0405601943d2/0c4316b2-553f-4a0a-ae02-c42d88de747c/srw-index-counts-each-job-from-one-tier

A serve job leaves a raw receipts file beside its minute and hour compactions, each naming the same job id and carrying the same window at a coarser resolution. The index ingested every file it was offered, and its key_kind column names how a host and boot were resolved rather than which tier a row came from, so a window covered by both a raw file and its compaction was answered from both — the same traffic counted once per tier. This node makes the index read one tier per job: the raw file when it exists, else the minute tier, else the hour.

What changed

  • imas_ambix/agent/telemetry_index.py: new receipts_tier reads (job id, tier) from a receipts filename, and one_tier_per_job selects the finest tier offered per job. TelemetryIndex.ingest reads only the selected tier and drops, before reading, any samples an earlier pass stored from a job's now-deselected tier (with their source rows), so the switch from raw to minute is not counted from both.
  • imas_ambix/agent/telemetry_ingest.py: a tick offers the index the whole discovered directory rather than only the files whose metadata moved, because which tier to read depends on which of a job's files exist. The index still leaves an unchanged source unopened, so this node did not cost the schedule its re-read avoidance.
  • tests/test_telemetry_index.py, tests/test_telemetry_ingest.py: the counted-once fixture, the fall-through-the-tier-chain assertions, and the tick-handoff contract.
