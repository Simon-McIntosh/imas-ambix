The 07:24 publication read a transient index state

The same window end, 1791184980.6, gives different answers depending on when the index was read. At the 07:24 publication's own now, the current index reports a day of 1.796G and a month coverage of 1,086,817 s (12.58 d); the 07:24 publication reported 29G and a month coverage of 16 d. A window end is a fixed point in the record; the totals and the coverage moving under a fixed end means the row set the reader saw moved, not the window. The inflation factor grows with the window (hour ×1.08, day ×16, week ×17, month ×11.6), which is the signature of a defect that adds advance once per counter run reached: a one-hour window reaches one run, a month reaches them all.

The code path that sums, and the write state that fed it

  • Where it sums. TelemetryIndex.partitioned_total (imas_ambix/agent/telemetry_index.py:1550–1611) reads every reading of the counter before the window's end — no lower bound in the query — splits them into runs with _counter_runs (:724–756), and sums, per run, closing − base. A run is one (host, boot_id, job_id) whose counter never falls (counter_run_continues, :694). base is the last reading at or before the window start, or, for a run whose first in-window sample is a compacted row, that row's own declared open.* value (_run_opening, :759; carried, :1604).
  • The state that inflates it. Two carriers of one job's counter visible in one read — its raw file and a compacted tier — interleave by timestamp; every key move starts a new run, and each compacted row then contributes its own window's advance as the base of a fresh run, adding that advance again. This inflates every window that reaches the overlap and leaves the hour nearly untouched, which is the 07:24 signature. The substrate exists: the live job 1280470's compacted tiers carry a declared "open" block in 63 hour rows and 3,672 minute rows (deepseek-v4-1-flash-1280470.{hour,minute}.jsonl), while the older 1278105's carry none — the openings feature post-dates that job.
  • How one reader can see it. ingest commits its samples in batches through the pass and drops a job's deselected tier only after the selected tier has been read (telemetry_index.py:1112–1116), so between those two moments the index can hold two tiers' rows of one job at once. The publisher's derivation takes about 85 s (compute_seconds=85.45 at 07:24:26) and watch_document issues its statements with no single read transaction across them, so a derivation spans at least one 60 s ingest tick.
  • The tick inside the 07:24 window. The 07:24 publication derived over 07:23:00.6 → 07:24:26. The ingest log shows the every-fifth-tick three-file scan landing inside it (ambix-ingest.log, line recorded at 2026-10-05T07:23:04Z ingest tick discovered=120 read=3 skipped=117 scanned=1 inserted=9 duplicate=0 malformed=0 bytes=33256); the neighbouring hundred-and-nineteenth ticks read one file (07:22:01Z … read=1, 07:24:05Z … read=1). The three-file ticks recur every five minutes (07:23:04, 07:28:09, 07:33:18).

What today's index holds

The current index loads only raw tiers: 32 distinct sample paths, all <job>.jsonl, with 0 rows under a .minute.jsonl or .hour.jsonl path and 0 measurements named open.%. So no declared opening is present now, and the two-carrier state the 07:24 read required cannot be reconstructed from today's rows — which is why the inflation does not reproduce at either end.
