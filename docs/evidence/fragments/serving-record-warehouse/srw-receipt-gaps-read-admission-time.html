imas_ambix/agent/cache_estimate.py now reads a request's arrival as the row's own timestamp, and scores or chains a row only when its status is completed. The router stamps a receipt at admission (started_at, router.py), so the timestamp already marks the moment the provider saw the request; the request duration is not subtracted from it. A row the record marks aborted, failed, or with no status neither scores as a hit nor anchors another request's chain, because its prompt reached the provider only uncertainly; it stays in the prompt-token denominator, so h remains over all the traffic. The caller rule is unchanged (run_id, else coordinator_session, else none).
