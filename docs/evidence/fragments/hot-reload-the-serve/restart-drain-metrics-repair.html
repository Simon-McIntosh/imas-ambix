Restart drain tolerates an undecodable scrape; lane capacity keeps its published zero

Two repairs on top of 10cb01e5, each with a test.

(1) A metrics fetch that fails while decoding a compressed body is an unreadable reading, never an exception that aborts the overlap. The shared exposition reader decodes Content-Encoding: gzip... gzip with gzip.decompress and deflate with zlib.decompress. A truncated gzip body raises EOFError and a corrupt deflate body raises zlib.error, and neither is an OSError or a ValueError. Both therefore escaped the drain reader's existing except clause. The drain reader (imas_ambix/agent/cli.py, _engine_running_requests) and the overlap's own guard (imas_ambix/agent/reload.py, run_overlap) now handle them, so the reading is unknown and the drain keeps polling to its ten-minute bound instead of raising out of the overlap after traffic has already moved to the replacement.

Reproduced at base 10cb01e5, before the repair, on a scrape whose gzip body is truncated by six bytes:

truncated gzip -> EOFError Compressed file ended before the end-of-stream marker was reached
corrupt deflate -> error Error -3 while decompressing data: invalid block type
cli._engine_running_requests -> ESCAPED EOFError
run_overlap -> ABORTED EOFError

After the repair the same probe returns None from the drain reader and run_overlap completes with old_drain_timed_out=True at its bound.

(2) The lane capacity reader keeps the absent-gauge default it has always published. engine_metrics.running_requests still returns None on absence — that is what the drain needs. But None is not a reading the lane document can express, so parse_lane_capacity (which fetch_lane_capacity delegates to) now applies the previous default, zero, with a comment stating why, and the two readings stay separate. Previously the shared reduction's None was turned into a ValueError, which broke three tests in tests/test_agent_lane_counter_series.py that supply partial SGLang expositions with no running-request gauge — the follow-on the predecessor fragment named.
