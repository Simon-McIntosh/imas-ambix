Lane publisher survives an undecodable compressed metrics body

A truncated gzip or corrupt deflate metrics body is now an unavailable lane publication, not an exception that ends the publisher loop. fetch_lane_capacity reaches the network through fetch_engine_metrics (imas_ambix/agent/lane.py), which decodes Content-Encoding: gzip with gzip.decompress and deflate with zlib.decompress. A body cut short raises EOFError ("Compressed file ended before the end-of-stream marker was reached") and a corrupt deflate stream raises zlib.error; neither is an OSError or a ValueError, so both escaped RouterApp._publish_lane's existing except tuple and ended the publisher task, freezing the lane document at its last reading — exactly the outcome the docstring promises will never happen. The handler now catches EOFError and zlib.error beside its transport and parse failures, so the corrupt body publishes the explicit unavailable state and the loop continues to the next scrape.

Reproduced at base 39bd6932, before the repair, on the two decode shapes the reader can meet:

truncated gzip  -> builtins.EOFError  Compressed file ended before the end-of-stream marker was reached
corrupt deflate -> zlib.error        Error -3 while decompressing data: incorrect header check
EOFError subclass of ValueError -> False
zlib.error subclass of ValueError -> False
