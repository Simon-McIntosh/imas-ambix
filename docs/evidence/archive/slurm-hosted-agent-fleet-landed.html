SLURM-Hosted Agent Fleet — Measured Evidence

Cumulative execution record for SLURM-Hosted Agent Fleet — take the clive lane off the four-core login slice. One anchor per landed node. The diagnosis of why the fleet dies with the connection that started it is a separate record and is not duplicated here: the session-scope teardown record.

Persistent allocation holder

Commits e0a990fb, 435e8965 and 5e3e0adc added imas_ambix/agent/fleet.py, registered imas-ambix agent fleet hold, and added the focused allocation tests. The generator calls the existing _sbatch_headers emitter and the explicit submission path calls the existing submit_script adapter; there is no second path to sbatch. The default command printed the script, while only --submit exercised the mocked submission seam. No live job was submitted during this implementation.

Placement is not hard-coded in the emitter. SiteConfig owns fleet_partition (rigel), fleet_account (iter), fleet_cpus (28) and fleet_memory (120G), each with an AMBIX_AGENT_FLEET_* override, and the generator resolves every directive from a site instance as the other script emitters do. The account differs from the GPU account deliberately: iter holds the site-default normal QOS, while grpa carries the GPU reservation's QOS, so a whole-node CPU allocation charges iter.

120G against the plan's 128 GB

The plan states a whole rigel node as 128 GB. The generated request is --mem=120G, because a rigel node reports RealMemory=128000 MB — a request at the nominal figure would sit at the node's whole real capacity, while one slightly below it leaves the node room for its own footprint and still covers the fleet. This is the trap the agent guidance records for --mem=0: a request at or above RealMemory is effectively an exclusive-node request that cannot start beside anything, and it reads to an operator as contention rather than as sizing.

Unbounded wall clock: asserted as a property, validated by the scheduler

The limit is emitted as --time=UNLIMITED through the shared header emitter, which takes the limit as a string and always emits the directive. The test does not compare that literal — it rejects any value matching the scheduler's finite-duration shape, so a value that expires fails while an equally unbounded alternative spelling passes. Both directions are shown below, because a test that can only agree with the constant it exempts proves nothing. Whether the emitted token is one the scheduler accepts is a separate question, answered by sbatch --test-only, which parses the whole header without submitting anything.

The generated script, quoted in full:

#!/bin/bash
#SBATCH --job-name=ambix-fleet
#SBATCH --partition=rigel
#SBATCH --account=iter
#SBATCH --cpus-per-task=28
#SBATCH --mem=120G
#SBATCH --time=UNLIMITED
#SBATCH --output=ambix-fleet-%j.log
#SBATCH --nodes=1
#SBATCH --exclusive
#SBATCH --comment=ambix-fleet

set -euo pipefail

export TMPDIR=/tmp

echo "[$(date)] Holding $(hostname) for the interactive agent fleet"
exec sleep infinity
