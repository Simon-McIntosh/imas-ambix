Why 95 findings were exempted rather than renamed

The naming family was 36% of the total, and clearing it by renaming would have damaged the code. The offenders in gs/filaments3d.py are segment_B and segment_A, where B is the magnetic field and A the vector potential; in statespace/baseline.py they are X, X_train, normalise_X — the design matrix. Eleven of the eleven N812 hits are functional as F, the standard PyTorch alias, and one is DistributedDataParallel as DDP.

The repository had already settled this question seven times: pyproject.toml carried seven commented per-file-ignores entries for the same rule set, each explaining that uppercase matches the mathematics. §4a extended that established pattern with ten more entries, taking naming findings from 96 to 5 without renaming a single symbol.

The five survivors were genuine and were fixed rather than exempted: the single-letter function alias mse_split as M, the OpenMagvit2Tokenizer as _OMT import, and two exception names.

The findings that were real bugs

An undefined name. imas_ambix/bench/cosmos_worker.py:123 reported F821 Undefined name 'torch' — a NameError waiting on that path, in a file last touched months earlier by unrelated work. Fixed with a real module-level import; a suppression was explicitly refused in the node contract. This single finding is the argument for the gate: nothing was watching that file.

Three redefinitions with a better root cause than expected. gs/filaments3d.py reported F811 three times on field. The cause was not the methods but an unused dataclasses.field import shadowing the public field() methods on Line, Arc and Conductor. Deleting the dead import cleared all three with no rename, no suppression, and no API change — and 238 GS tests still pass.

A consistency defect this work introduced, and reversed

The §4c worker renamed StreamAborted to StreamAbortedError in two bench modules to satisfy N818. But imas_ambix/data/stream_encode.py defines the same concept and deliberately keeps StreamAborted behind # noqa: N818 # not an Error-class, a control-flow unwind. That reasoning follows CPython's own precedent — StopIteration, GeneratorExit and SystemExit are all control-flow exceptions and none carries an Error suffix. The rename left two spellings of one concept across sibling modules, so it was reversed: all three definitions now carry the identical documented annotation, and StreamAbortedError has zero hits in tracked source.
