Boundary evidence — why the launcher failed

Measured 2026-08-25 against SLURM job 1252401 (deepseek-v4-flash, 98dci4-gpu-0003, partition betelgeuse, running 5 days at the time of the probe).

The served model was never at fault. GET /v1/models returned one entry with max_model_len 524288, POST /v1/messages answered "Hi! How can I help you today?", and claude -p driven with clive's direct-route environment variables replied OK. The fault was confined to the route clive selected.

Fault 1 — the auth-header mismatch

vLLM's API-key middleware honours exactly one scheme. Probing POST /v1/messages with the same valid key under three header forms isolates it:

HeaderStatus
Authorization: Bearer <key>200
x-api-key: <key>401
none401

LiteLLM 1.80.13's AnthropicConfig.get_anthropic_headers constructs anthropic-version, x-api-key, accept and content-type — and no Authorization header at all. Through the proxy the local model therefore returned {"error":"Unauthorized"} … Received Model Group=deepseek-v4-flash, code 401. The credential was correct: the systemd env helper wrote a 43-character AMBIX_LOCAL_KEY matching, byte for byte, what the same extraction produced by hand. The key was right and the header carrying it was wrong.

Fault 2 — the exhausted OpenRouter quota

All four or-* slots returned 403 "Key limit exceeded (total limit)" — or-opus-4.8 and or-sonnet-4.6 as an Anthropic permission_error, or-gpt-5.5 and or-glm-5.2 as a LiteLLM APIError. Account state rather than a code defect, but it left the four remaining picker entries dead alongside the default.

Both faults lived on the same route, and that route was selected by nothing the user typed — only by whether ~/.config/openrouter/key happened to be readable. Users without the file were unaffected, which is why the outage read as intermittent and user-specific rather than systematic.

Generator authority and artifact provenance

imas-ambix agent clive --print was byte-identical to the deployed /work/projects/imas_gpu/agents/clive, so the defect was in committed source and not a hand-edit of the deployed copy — every fix is version-tracked.

The deployed orclive script proved to be an orphan rather than a second managed launcher: its generator imas_ambix/agent/orclive.py (125 lines) was deleted in commit 7162db7 on 2026-06-26, the same day the unified clive superseded it, while the deployed copy written three hours earlier was never cleaned up.

Reuse map — scoping the proxy retirement

A read-only scout mapped every consumer of the proxy surface before the retirement node was authored: 8 governed files, 2 modules to delete (litellm_config.py, litellm_service.py), 3 surviving production symbols to edit (clive.py, cli.py, and SiteConfig's two launcher-path fields), and 2 affected tests.

Its decisive finding was an absence: no test imports generate_clive_script, and nothing exercised the OpenRouter branch. That is the reason a shared launcher could carry a dead default model — the fix's own gate is a grep run once by hand, and a grep nobody re-runs cannot prevent the route returning. The plan gained §4g for a regression test as a direct result.

§4c — Served context window

Commit 3d2cd35: the launcher parses id and max_model_len from a single /v1/models response and exports CLAUDE_CODE_MAX_CONTEXT_TOKENS. Gate passed against two stub payloads: {"data":[{"id":"deepseek-v4-flash","max_model_len":524288}]} exported exactly 524288; {"data":[{"id":"deepseek-v4-flash"}]} left the variable unset and cleared an inherited sentinel of 123456 rather than guessing. bash -n and scoped ruff exit 0.

The effect is larger than the diff. Claude Code does not recognise deepseek-v4-flash and was therefore assuming a 200k window against a model serving 524288 — more than half the available context discarded on every session, with only a startup warning to show for it.

§4g — The local-only fence
