§3 — Payload parity and the tensorizer seam

Seam VERIFIED. Cross-arm parity exact: 3/3 channels, 64/64 samples each, 192/192 scalar values identical under np.array_equal in both converted arms against native level-2. Commit b9fb2cf, merged as 0ff5be9; 4 tests added.

The question §3 posed was whether a zarr writer can be a sibling subclass of imas-python's tensorizer rather than a reimplementation of the Data Dictionary shape rules, because a hand-rolled twin would diverge silently at the next DD version. It can. IDSZarrWriter subclasses public imas.backends.netcdf.ids_tensorizer.IDSTensorizer — a sibling of imas.backends.netcdf.ids2nc.IDS2NC — and reaches no single-underscore attribute or method anywhere.

Every emitted zarr array carries its IDS-qualified DD path and units as attributes — summary/time [s], summary/global_quantities/ip/value [A], summary/global_quantities/power_radiated/value [W] — which is the property that makes DD vocabulary separable from the IMAS container.

Qualifications carried forward

  • The seam verdict is version-scoped. It was measured against imas-python 2.3.0 in an isolated environment, while the project environment resolves 2.2.0. The verdict is not yet established at the version the training path actually runs, so the measurement node re-runs both arms in the project environment.
  • The payload is a parity fixture, not a benchmark payload. One shot (11766), the summary IDS, 3 float64 channels over 64 samples. It proves equivalence; it carries no read-rate information, and the netCDF and zarr payloads were deliberately not retained.
