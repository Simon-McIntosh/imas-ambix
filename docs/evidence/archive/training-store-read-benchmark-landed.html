§3 — Payload parity and the tensorizer seam

Seam VERIFIED. Cross-arm parity exact: 3/3 channels, 64/64 samples each, 192/192 scalar values identical under np.array_equal in both converted arms against native level-2. Commit b9fb2cf, merged as 0ff5be9; 4 tests added.

The question §3 posed was whether a zarr writer can be a sibling subclass of imas-python's tensorizer rather than a reimplementation of the Data Dictionary shape rules, because a hand-rolled twin would diverge silently at the next DD version. It can. IDSZarrWriter subclasses public imas.backends.netcdf.ids_tensorizer.IDSTensorizer — a sibling of imas.backends.netcdf.ids2nc.IDS2NC — and reaches no single-underscore attribute or method anywhere.

Every emitted zarr array carries its IDS-qualified DD path and units as attributes — summary/time [s], summary/global_quantities/ip/value [A], summary/global_quantities/power_radiated/value [W] — which is the property that makes DD vocabulary separable from the IMAS container.

The seam verdict, corrected at the version the project runs

The zero-wrapper subclass seam is REFUTED at imas-python 2.2.0 and VERIFIED at 2.3.0. This is the correction the §3 qualification was carried for, and it changes the §3 headline rather than merely annotating it.

get_dimensions, get_attributes, get_shape_dimensions and get_shape_attributes are public in 2.3.0 and absent in 2.2.0. The writer remains a direct subclass of public imas.backends.netcdf.ids_tensorizer.IDSTensorizer calling inherited public include_coordinate_paths, collect_filled_data, determine_data_shapes, tensorize and filter_coordinates, with no private imas name reached at either version — but on 2.2.0 those four helpers must be defined locally over public NCMetadata/IDS metadata.

So the plan's stated trigger for reimplementation is not met: a four-method compatibility shim is not a hand-rolled twin of the DD shape rules. The shim is nonetheless pure version-lag cost, and it disappears on imas-python ≥ 2.3.0. Project environment measured: imas-python 2.2.0, numpy 2.4.4, xarray 2026.4.0, zarr 3.2.1, netCDF4 1.7.4.
