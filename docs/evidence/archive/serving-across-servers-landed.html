§16 — A router restart drops nothing

Landed in merge e24c9953 (worker commit 26cfc5d4).

  • serve_router now runs uvicorn.Server with timeout_graceful_shutdown set to 30 s.
  • On SIGTERM or SIGINT, the router chains RouterApp.initiate_shutdown in front of uvicorn's own exit handler. The gate then stops admitting and answers every waiter with 529 overloaded_error and Retry-After, before any connection closes.
  • Receipts gained a reason field: router shutdown for a held request answered at the signal, and router shutdown cut the relay for a relay that outlasted the grace.

§4 — One gate per engine

Landed in three merges:

  • 7edac339 (worker commit 7dc2825a);
  • 5f645391, the automatic repair round (f3736aaa, 6f073ee1, 8a702f63);
  • 2853a21e, a repair node (5d2e70d3).

What it does.

  • Each engine has its own _GenerationGate, with its own FIFO, width, width controller and admission ledger. A gate is fed only the reading taken from its own engine (RouterApp.observe_engine).
  • The first engine to be gated takes over the process's original gate, so a one-engine router queues where it always did.
  • A request whose engine has not resolved waits outside every engine's gate, and is handed to its own engine's gate once its owner appears.
  • The gate control file keeps its flat keys as defaults. An engines map, keyed by engine id, overrides width, wait and pause for one engine. A top-level paused still pauses every engine.
  • A malformed engines map, or a claim of a gate owned by another engine, is refused, and each refusal is tested.
  • A refusal row keeps the (router) upstream sentinel and names the engine in its own gate_engine field.

Integration fault. The first merge wrote the engine into reason, which broke §16's shutdown test at main once both had landed. The repair node moved the engine into its own field. 132 router tests pass at main 255a0f9c.

Reviews. All three scored 15 to 20 with no blocking finding. The residual non-blocking point: an owner-wait hand-off restarts the wait deadline, so a caller can wait up to twice the configured bound, and gate_wait_s omits the owner-wait part.

Not live until the next router restart.
