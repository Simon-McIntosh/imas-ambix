§8 — what fills the index, and why retention is idle

A read-only backup of the 8,669,601,792-byte index was taken to node-local scratch and measured with dbstat; the objects account for 99.99995% of the file. The measurement table and its two indexes hold 6,982,402,048 bytes (80.54%): 41,119,466 rows at 169.8 bytes each, 74.2 per sample. The sample table holds 1,658,011,648 bytes (19.12%), about 2,993 bytes per row of verbatim payload. Retention is not broken: a read-only scan finds 0 of 20 raw files eligible, because 19 old raw files carry no counter pairs to prove against, and the live job's file is younger than the 14-day threshold. The 105 closed receipt files would compress from 275,231,185 to 16,851,447 bytes.
