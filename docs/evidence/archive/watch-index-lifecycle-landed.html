§3 — an ingest tick reads the bytes it takes in

The ingest now skips a source whose size and verified mtime match its row without opening it. A changed source extends a running SHA-256 with its appended bytes and compares 64 KiB head and tail probes. A source changed since its last whole-prefix verification keeps its verified mtime until the hourly check, so a same-length rewrite before the interval is caught without a further append. Hash state is built lazily, once per changed source per process, and opening the index reads no receipt bytes for closed, verified files.

§5 — watch reads hourly rollups

The index gained a name and kind dictionary and an hourly_rollup table per source, measurement and hour, maintained by the ingest. A period sums whole hours from the rollup and reads raw samples only at its two edge hours, and all cards of a period are read in one statement.

On a fleet rebuild from the receipts (473,215 samples), watch_document equalled the raw computation exactly, field by field, with the live block frozen on both arms. A perturbed rollup row fails that comparison at $.ledger[1].utilisation. watch_document takes 3.96 s, against 1,306 s before. Rollup maintenance adds 0.024 s to a tick. The rebuilt index is 3,810,488,320 bytes, against 8,678,658,048 before and the 2.11 GB estimate.

One defect was found on the way. The cached-token tiers were stored as interval while the ledger totals them as counters, so their rollups were integrals. Classification is now shared and stores them as cumulative.
