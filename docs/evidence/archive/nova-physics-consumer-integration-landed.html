The alternatives were rejected on blast radius, not on taste. Renaming scripts would have churned imports across the 23 scripts the migration had just touched, plus tests and runtime consumers. Excluding Nova's package is Nova-side, outside the fence, and would risk Nova's own package users. Moving tests off scripts imports would have left script-to-script and runtime imports shadowable while testing a different surface. The marker changes package resolution; every alternative changes callers or test execution.

Two operational findings that cost more than the repair did. First, a 500-test suite with torch backward passes does not belong on a shared login node: it took 546 s on a dedicated debug node, 387 s on a momentarily idle login node, and 2.5 hours to reach 52% on the same login node under another session's load. That spread is the venue, not variance, and two nodes burned their entire fences before the third ran it where it belonged. Second, the SLURM job's terminal state is FAILED with ExitCode 1:0 and the run nonetheless PASSED — ordinary pytest exits nonzero for the three baseline failures, while the suite ran uninterrupted to its terminal summary. A gate keyed on job state rather than on the suite's own summary line would have rejected a passing run.
