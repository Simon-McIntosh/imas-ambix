§1 — What is serving

DeepSeek-V4-Flash-0731 on four H200 cards, tensor-parallel 4 with expert parallelism, FP8 weights with FP4 experts, serving the checkpoint's full native 1,048,576-token window with DSpark speculative decoding active. Job 1262952 on port 18800, behind the unchanged consumer origin on 18802.

DSpark needed no download: the dspark_* block (dspark_block_size 5, target layers 40–42) was already present in the weights on disk, and vLLM 0.28.0 is above the 0.25.0 floor. num_speculative_tokens is 5, taken from the checkpoint's own declared block size rather than from a published example written for other silicon.

The ordering has been stable in every sample taken, which makes the curve the more robust claim of the two; a value above 5 for num_speculative_tokens is worth probing on that basis.

Generation throughput peaked at 418.5 tok/s against the two-card serve's 120.5 on the same recorder. That figure should not be read as a routing quantity: measured agentic wall throughput on this lane is 22–33 tok/s, so the ceiling is turn count and thinking volume, not generation. More cards will not make an agentic node finish sooner.

Prefix caching is active and settles near 30% — 33.9% on a four-day-old two-card engine, 28.0% and 27.7% on two fresh four-card ones. Consumer-side usage records report zero cache reads, so the ~46× input amplification two peer sessions measured is substantially a reporting gap rather than pure wasted compute, though the headroom against metered lanes at 97–99% is real and structural.

§3 — The constraint that shaped the cutover

Both card counts publish one served_name by design, and the router refused a duplicate model id with HTTP 409. A second serve raised naively beside the first therefore breaks the endpoint rather than joining it. The fix ranks candidates by accelerator_count then start stamp, and _fetch_catalog's reachability check becomes the health gate: an engine still loading is simply absent, so traffic stays on the incumbent until the new process genuinely answers.

That worked on the relay path and the overlap ran as designed — the two-card serve answered throughout a 408-second weight load. The catalog path carried a second duplicate check the fix had not covered, so GET /v1/models returned 409 during the overlap while completions were served normally. Closed separately.

§4 — What running it exposed

Six defects surfaced only because the deployment was stood up and driven. Four of the six were passing a test at the time.

DefectWhy the gate missed it
The published endpoint document did not follow the serve to a new port, and nothing republished it Engine and router were both healthy throughout; only new consumer launches failed, so the fleet looked well right up to the moment it needed to grow
Speculative counters read zero against an engine publishing them Validated against a fixture its own author wrote, because the two-card endpoint exposed no such counters to check against
The integer coercion raised on the per-position label, which arrives as a string Masked by the naming defect above; both had to be fixed to see either
The benchmark folded each counter's _created timestamp gauge into its absolute value Survived because deltas across two scrapes cancel a constant; the per-scrape snapshot read 1.788626e+09 where the counter held 9,560
A read-only dry run was gated on live scheduler port state Latent until a serve occupied another profile's declared port, then a unit test's result depended on the cluster
The router's catalog path refused what its relay path ranked The node's measure named the relay; the gap was in the brief, not the work

The common shape is an instrument agreeing with the only thing it was ever pointed at. It applied to the recorder's fixture, to the benchmark's cancelling delta, and to the coordinator's own cutover check, which verified the router and a relayed completion — both healthy — while discovery was broken for every new consumer.

§5 — The local lane as a worker backend

Six nodes were dispatched to the deployed model, five of them fixing the serving infrastructure it runs on. Six of six landed inside their declared write fences with zero corrective redispatches, at walls of 7 to 53 minutes.

Three behaviours are worth recording because they are what a gate cannot show. One node ran an adjacent suite it was not asked to run, found the two assertions its own change broke, and attributed them to its commit by sha while correctly separating a third failure as pre-existing. One proved its defect empirically by loading the old function and running the new fixture through it, rather than asserting the defect existed. One was told to leave a failing test alone and did, rather than adjusting an assertion to reach green and hide a different defect.

Two costs stand against that, and the first was initially recorded here wrongly. Per-node ledger receipts are present, not absent. Five of six runs carry generation rate and token totals — 16.2, 17.1, 25.3, 25.4 and 33.0 tok/s, inside the 22–33 band two peer sessions measured independently. The sixth is null because it was promoted immediately on completion, before its terminal result record had been written to the stream. An earlier reading of "zero result records" here was taken while a stream was still being flushed and generalised into a structural claim about the lane; it was a mid-write measurement, which is the same error this record catalogues elsewhere. The operational rule is ordering: let a run go terminal, then crew observe, then crew complete. What is genuinely absent is cost_usd, which is null on every run of this unmetered lane, so a router ranking by cost per durable node reads it as free.

The second cost is that worktree isolation did not hold: two unrelated workers left formatter edits in the shared main checkout, outside their fences, each surfacing only as a refused merge. Both were AST-identical to HEAD, which is the check that made discarding them safe — a semantic edit arriving by the same route would announce itself neither way.

§6 — Configuration as it now stands

Deployment config remains TOML under imas_ambix/agent/profiles/; reckon's flight.yaml is the YAML surface and carries the routing retune. The local backend now declares sandbox, session_reuse, an advisory time_budget and the endpoint's advertised usable_input_window, each annotated with the measurement behind it.

The setting that matters has no schema key and is recorded as a routing comment: trust exact unsupervised, allow guided only when the measurement is handed over as established fact, never route open here. The governing variable is brief specificity rather than task difficulty, and the evidence is a controlled pair hours apart on one model — a brief naming a field, a formula, a sign rule and two fixtures produced an edit seventeen seconds in; one asking the worker to decide when it had measured enough produced nothing in forty minutes, then committed within minutes once handed the measurements.
