§18 — the released version is written locally only after the push

On the lead's instruction, the gap the earlier repair left between writing the local version and pushing it was removed rather than guarded. release no longer touches the local bundle.json before the push. stage_bundle already writes the version into the staged copy that is pushed, so the local descriptor is written only after push_tree returns. The read-and-restore branch is gone, because a failed push now leaves the file exactly as it was.

_write_bundle_version writes atomically, to a temporary file in the same directory followed by os.replace, so no reader and no interrupted write sees a partial descriptor. The temporary takes the old file's permission bits (stat.S_IMODE), because mkstemp would otherwise turn a 0644 descriptor into 0600. A temporary left behind by a killed write is excluded from released_paths, so it never reaches the tree digest or the published artifact. tests/test_maps_cli.py went from 27 to 32 passing. Each change has a negative control that fails when the change is reverted, including one that reads the local file during a stubbed push. That push runs while the file still names the previous version.

The reverse direction is accepted. A local write that fails after a successful push leaves the registry with a version the local file does not name until the next pull, and a facility cannot install a version that exists only on this machine.
