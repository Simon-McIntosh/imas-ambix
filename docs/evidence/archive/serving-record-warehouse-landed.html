§3 — The aggregation rule the reporter got wrong

What landed. TelemetryIndex.partitioned_total(name, start, end) returns a PartitionedTotal carrying the total, the number of contributing runs, and the coverage behind it. The total is the sum of the per-run differences; the coverage is the union of the contributing runs' spans clipped to the window. watch._span and watch.period_row both read through it, so no period figure the watcher prints is now a single outermost difference taken across a serve restart.

What a run boundary is

A run ends at a serve restart, a reboot, a run moving to another host, or any gap the record cannot bridge. The boundary used is the reading's identity — the receipt's job_id beside the sample's boot_id — plus a split on any reading that does not advance: a restart whose source key did not change is still a restart, and differencing across it is still the defect. The file inode is deliberately not part of the identity, because a serve that rolls its receipts file has not restarted and scanning the record would fragment one run into several.

What the coverage figure is

The coverage is the union of the contributing runs' own spans, clipped to the window, in seconds. It is never the window's nominal length. Where the record covers part of a window, the row reports the part it can stand behind; where no run of the window had two endpoints to difference, the total is None — absent, which is not the same answer as the 0.0 of runs observed and not advancing.

Negative control

The declared mutation — make the window total difference only the outermost pair of readings, ignoring run boundaries — reddens the coverage assertion, which is the behaviour the section exists to prevent. Log: negative-control.log; its first line is the mutation stated verbatim.

Repair after review

An independent review of the landed revision confirmed two defects, both fixed here. The coverage was accumulated as a sum. Each run's clipped span was added with += while the docstring promises the union of those spans, so two recorders whose runs overlap in time would double-count the overlap and inflate the denominator every throughput and utilisation figure divides by. The spans are now collected and reported through _union_length, which merges overlapping and touching intervals alike. A run with one reading in the window was differenced against itself. Its opening and closing are the same row, so the subtraction was x - x and the total moved from None to 0.0 — the answer a run observed and not advancing earns, which is not the same claim as no run had two endpoints to difference. A run now contributes only when it holds two distinct readings, so such a window reports None.

The union fix is a robustness fix, and the evidence should not overstate it. The contributing runs are contiguous slices of one time-ordered scan, so their clipped spans can touch but never overlap, and the sum and the union are numerically equal for everything the writer produces today. No fixture can build the overlap through the store; the test asserts the union arithmetic directly and asserts the caller routes coverage through it, which is the regression the arithmetic alone cannot see.
