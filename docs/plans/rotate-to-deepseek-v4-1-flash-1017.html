§1 — Why rotate, and the evidence

The lane serves deepseek-ai/DeepSeek-V4.1-Flash, downloaded on 2026-09-14 to /work/projects/imas_gpu/agents/deepseek-v4-1-flash/model. On 2026-10-17 DeepSeek published deepseek-ai/DeepSeek-V4.1-Flash-1017 (commit 1bae0e1088993b9b82de08f59de5be5a34e42170) and switched its own API to it. It is a weights-only update: the same deepseek_v41 model type, 48 safetensors shards and 510.3 GB, against our local copy's 48 shards and 510.3 GB.

Independent measurements agree with the vendor's claim:

Two caveats are carried forward rather than dismissed. 1017 is verbose: Artificial Analysis counted 210M output tokens on its index against a median of 140M. One review also rates its reliability 3/5. A user report says it keeps the earlier tool-call pattern while using about 20% fewer tokens at each reasoning effort, but no source tested our parsers. That is why §3 exists.

§2 — Download the 1017 release into its own directory

The release lands in its own directory, deepseek-v4-1-flash-1017, for the reason the profile already gives: a shared directory would leave one release's shards beside the other's index, with no record of which checkpoint a run loaded. The profile deepseek-v4-1-flash gains a revision field pinning the commit above. Its hf_repo, weights_slug and revision name the 1017 release, and served_name stays deepseek-v4.1-flash (decision served-name). The September directory is kept until §5 has held for a week, as the rollback target.

Changing the profile does not touch the running serve. It is read only at launch, and nothing relaunches until §5. The download runs through imas-ambix agent download deepseek-v4-1-flash as a SLURM job, which resumes if cut, and the generator passes the pinned revision to the Hugging Face client.

Write paths. imas_ambix/agent/profiles/deepseek-v4-1-flash.toml, imas_ambix/agent/profile.py, imas_ambix/agent/slurm.py, tests/test_agent_dspark_profile.py.

Done when.

  • The download job ends with 48 shards in /work/projects/imas_gpu/agents/deepseek-v4-1-flash-1017/model, and each shard's size and SHA-256 match the repository's listing at the pinned commit. The comparison is recorded.
  • imas-ambix agent serve deepseek-v4-1-flash --dry-run names the new weights directory and the pinned revision, and is otherwise byte-identical to the base revision's script.
  • Negative control: a profile whose revision names a commit absent from the repository makes the download script refuse before transferring anything.

§3 — The relaunch validates a tool call, not only a completion

imas-ambix agent restart already restores the saved script when the new engine fails readiness or a real completion. A completion is the wrong test for this rotation. 1017 ships a new prompt encoding (encoding.py and deepseek-recipe, no Jinja template), and every worker on the lane makes tool calls. A release that completes text but returns tool calls our parser cannot read would pass validation and then fail every worker.

The validation step gains three probes, each sent through the router to the new engine before resume:

  • Tool call. A chat request offering one tool must come back as a parsed tool_calls entry with arguments that parse as JSON.
  • Interleaved thinking. A multi-turn exchange with a prior tool result must keep reasoning out of the visible content and out of the tool arguments. This is the leak the a-tool-call-carries-no-model-markup plan tracks.
  • Anthropic dialect. The same tool call made through the dialect clive uses must return a tool_use block.

Any probe failing restores the saved script and resumes, exactly as a failed completion does today.

Write paths. imas_ambix/agent/cli.py (the restart validation), imas_ambix/agent/serve_probe.py (new), tests/test_agent_serve_probe.py (new).

Done when.

  • The three probes pass against today's served engine through the router, run once from the fleet node, as the positive control on known-good weights. The log is recorded.
  • Unit tests cover each probe's pass and fail on recorded fixture responses.
  • Negative control: a fixture whose tool call arrives as text in content, with no tool_calls, fails the tool-call probe and selects the rollback path in a restart test.

§4 — Record which release answered

The served name stays deepseek-v4.1-flash through the rotation, so the name no longer says which weights answered. The serve's registration therefore carries a release: <hf_repo>@<revision>, written by the serve job from its profile at start. endpoints.json publishes it on the engine's entry. A receipt already names its upstream engine, so a reader joins receipts to releases through the registration in force at the receipt's time. That needs no router change and no router restart. A registration written before this section reads release: null, which the reader reports as unknown and never guesses.

Write paths. imas_ambix/agent/registry.py, imas_ambix/agent/slurm.py, tests/test_agent_serve_registry.py, tests/test_agent_endpoint_discovery.py.

Done when.

  • A registration written by a generated serve script carries the profile's hf_repo@revision, and endpoints.json publishes it on the engine's entry.
  • A registration with no release key is read as null and the document still builds.
  • Negative control: a profile with no revision writes <hf_repo>@unpinned, never a commit read from the downloaded directory's cache.

§5 — The rotation itself

An engine relaunch under the lane-cycle runbook (ops/lane-cycle/AGENTS.md), run by the coordinator as a reported inline exception. A cycle is an operational action on a shared service, so it is never a worker node. The router does not restart: an engine relaunch drops nothing, because in-flight requests finish and later arrivals wait in the router's FIFO. The steps:

  1. Announce to the live coordinators, with the bound: a pause of at most 40 minutes.
  2. From the main checkout, run imas-ambix agent restart deepseek-v4-1-flash --reason "rotate to V4.1-Flash-1017". It pauses, drains to a measured zero, relaunches on the 1017 directory, waits for readiness, runs §3's probes, and resumes on every path.
  3. Record the cycle's four figures (pause start and end, peak held, final failures) in the landing record.
  4. Watch the first hour of receipts. The failed-request share and the gate-expiry count must stay at the previous day's levels.

Rollback is the same command with the profile pointed back at the September directory, which §2 keeps for a week.

Done when.

  • endpoints.json shows the engine's release as deepseek-ai/DeepSeek-V4.1-Flash-1017@1bae0e10…, and /v1/models still lists deepseek-v4.1-flash.
  • A reckon worker dispatched on the local lane after the cycle completes its node and promotes.
  • Over the first hour, the share of requests ending failed stays within one percentage point of the same hour the previous day.
  • Negative control: before the cycle, the restart is dry-run against a profile pointing at an empty weights directory, and refuses before pausing the lane.

§ Decisions

Under what name is 1017 served?

Keeping the name means clive, every reckon backend and the price table keep working with no change at cutover. A new name would have to change in all of them in the same cycle, or workers fail. The cost is that the name alone no longer identifies the weights, so §4 records the release on the registration and in the endpoint document.
