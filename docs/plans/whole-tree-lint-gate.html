§1 — What was found, and why it is worth a plan

Surfaced while shipping clive local-only routing. A worker node there was authored with the done-when clause uv run --no-sync ruff check imas_ambix tests exits 0. It cannot: that command reports 266 errors on main. The node was fenced to five files and correctly reported blocked rather than editing outside its scope, and the authored gate had to be corrected at integration.

The interesting finding is not the error count — accumulated style debt in a research repository is unremarkable. It is that whole-tree lint is unusable as a gate. Any future node that reaches for the obvious measure of "the linter is happy" will either block on debt it does not own, or silently narrow its measure to a scoped run and report a pass that means less than it appears to. The first costs a dispatch cycle; the second is worse, because it produces confident evidence for a weaker claim.

Representative files, all last touched between May and June 2026 by unrelated work: imas_ambix/agent/bench.py, imas_ambix/agent/slurm.py, imas_ambix/bench/cosmos_worker.py, imas_ambix/bench/loader.py. The bulk of the remaining count sits under the training and model code.

§2 — The decision this plan needs before any work

There is no point clearing 266 errors if the repository does not intend to hold the line afterwards, and no point declaring a gate the tree cannot meet. Three coherent options, in rising cost:

  • Scoped gate only. Accept that whole-tree lint is not a gate; require scoped lint over each node's own write paths, and say so in AGENTS.md so nobody authors the whole-tree clause again. Cheapest, and it removes the trap without touching the debt.
  • Ratchet. Record the current count as a ceiling that may only fall, so new code is clean and the debt drains opportunistically. Needs a checked-in baseline and a comparison step.
  • Clear and gate. Fix all 266, then require whole-tree exit 0. Highest cost, and it touches training and benchmark code whose behaviour is not covered by fast tests — the risk is a formatting change to code nothing exercises.

The trap is closed by the first option alone, which is why it is the recommendation: the value here is in not authoring an unachievable measure again, and that is a documentation change, not a cleanup campaign.

§3 — What the 266 actually are, and how clearing them works

Posture locked: clear and gate. Measured composition on the integration branch, which determines the method:

The naming family must be exempted, not renamed, and the repository already says so. pyproject.toml carries seven existing per-file-ignores entries for exactly this rule set, each commented with the reason — "uppercase matches the math". The violations are the same class: in gs/filaments3d.py the offenders are segment_B and segment_A, where B is the magnetic field and A the vector potential; in statespace/baseline.py they are X, X_train, normalise_X — the design matrix. Renaming segment_B to segment_b would destroy the physics meaning to satisfy a linter, and it would contradict a convention this repository has already written down seven times. Two import aliases fall the same way: functional as F (11 of the 11 N812 hits) and DistributedDataParallel as DDP are the standard PyTorch idioms.

A genuine bug was found in the process. imas_ambix/bench/cosmos_worker.py:123 reports F821 Undefined name 'torch' — a NameError waiting on that path. That single finding is worth more than the other 265 combined, and it is the argument for the gate: nothing was watching this file. Three F811 redefinitions of field in gs/filaments3d.py are the next most likely to be real.

A small residue of naming hits are genuine and get renamed rather than exempted: StreamAborted (N818, twice), mse_split as M (N812), and OpenMagvit2Tokenizer as _OMT (N814).

§4 — Implementation

The convention exemptions land first and alone, because they remove 95 rows that no source-editing node should waste effort on. The remaining work then partitions by file rather than by rule, so each node owns a disjoint write scope and its goal is simply "no ruff violation remains in these files".

§4a — Exempt conventional notation

In pyproject.toml only, extend [tool.ruff.lint.per-file-ignores] to cover the math, design-matrix and PyTorch-idiom naming rules for the twelve files that carry them, following the seven existing entries and giving each a comment naming the convention it preserves. Do not exempt the genuine residue in §3.

Done when no source file is modified and the naming-family count in ruff check imas_ambix falls to the genuine residue alone.

§4b — Clear the statespace cluster

baseline.py, sequential_da.py, filter.py, oracle_probe.py, integrated_inputs.py, internal_diagnostics_probe.py — the largest share, ~70 rows after §4a, mostly E501.

§4c — Clear the bench and agent cluster

bench/stream_worker.py, bench/cosmos_worker.py, bench/tokenizer.py, bench/loader.py, agent/slurm.py, agent/bench.py. Carries the F821 undefined-name bug, which must be fixed as a real defect and its resolution stated — not silenced with a noqa.

§4d — Clear the tokenizer, latent, gs, data and eval cluster

tokenizer/ (finetune_decoder.py, cli.py, patch_transformer.py, multimodal.py), latent/ (patch_encoder.py, patch_observation.py, encoder.py, boundary_moment.py), gs/filaments3d.py (the three F811 redefinitions), data/stream_encode.py, eval/metrics.py.

§4e — Clear the test tree

All remaining violations under tests/, ~16 rows, predominantly E501.

§4f — Install the gate

Record in the repository's AGENTS.md that whole-tree ruff check imas_ambix tests is now a valid done-when measure and is expected to hold, so a future node can rely on it — the absence of that statement is what let the unachievable clause be authored in the first place.

Done when uv run --no-sync ruff check imas_ambix tests exits 0 on the integrated branch and the full test suite still passes.

§ Decisions

What lint posture should the repository commit to?

Clear all 266 and gate. Chosen with the cost and the risk stated: the edits reach training and benchmark code that fast tests do not cover. Method follows from §3 — the naming family is exempted as convention (the repository already carries seven such entries, and renaming segment_B would destroy the physics), everything else is genuinely fixed, and the gate is then real rather than aspirational.
