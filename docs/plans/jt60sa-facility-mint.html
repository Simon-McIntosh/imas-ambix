JT-60SA Facility Mint: Public Engine, Private Maps

The machine map (jt60sa-machine-map) turns JT-60SA data into IDS paths, and jt60sa-pulse-ids §1 adds the writer that mints a pulse. Both run here, reading EDDB over ssh into a cache. This plan moves the mint to the facility. A slim public engine, imas-alambic, loads a private JT-60SA map bundle that it finds by machine name, and reads EDDB locally on the analysis server. The lead settled the route on 2026-10-06. The engine is a uv workspace member of this repository. The maps are one flat bundle, edited in place under /work/projects/imas_gpu/jt60sa/maps/ and released as private GHCR artifacts, which this machine relays to the server. There is no private git repository. The install starts as an editable checkout on the analysis server, to test, and moves to a wheel.

§13 — A failed write leaves no run file

write_pulse opens imas.DBEntry(path, "w") on the final <pulse>_<run>.nc and puts each IDS in turn. A failure part-way, such as a malformed map entry or an EDDB read error on the third IDS, leaves a partial file at the final name. A reader of the shared IDS folder takes it for a complete run, and a retry is refused as an existing file unless --overwrite is given. The remedy is to write to a temporary sibling in the same directory and os.replace it onto the final name only after every IDS is put. The temporary file is removed on any failure, and the existing-file refusal is unchanged.

One owner names both files. pulse_path owns the run file's name, and the same module owns the temporary's: a dot-prefixed .<pulse>_<run>.<random>.partial.nc. The .nc ending keeps imas-python on its netCDF backend. The leading dot keeps it out of ordinary listings, and it can never match pulse_path's <pulse>_<run>.nc, which is how a reader of the folder selects run files. The repository already has this pattern in about nine places, most fully in imas_ambix/agent/watch_publish.py's _write_atomic. The engine is a separate wheel that cannot import imas_ambix, and those helpers take a payload, while imas-python opens the path itself. So §13 adds one engine-owned context manager beside pulse_path that yields the temporary path and keeps _write_atomic's rules. It creates the temporary in the target's directory, gives it mode 0644 before the rename because mkstemp's 0600 would carry onto a run file that other users read, and unlinks it on any exception.

Write paths: packages/imas-alambic/src/imas_alambic/pulse_writer.py, packages/imas-alambic/tests/test_run_file_write.py and the node's evidence fragment.
