§1 — The producer exists; the consumers have not moved

A declared machine map now emits description through format-scoped engines with no machine-specific code, and an adapter turns that into the table the existing consumers expect. What has not happened is the move: 41 modules still invoke a legacy description-read API — 8 library modules and 33 scripts — so the per-machine reader the whole design exists to remove is still the one production uses.

This is deliberately a separate plan rather than the tail of the producer's. It is a migration across a wide surface, its risk profile is different, and it is gated on evidence the producer plan generated rather than on more design.

§3 — Migrate by seam, behind a facade

The census is the measure of progress and the definition of done: 41 call sites, falling to zero. A compatibility facade keeps both paths available during the move so each seam can be switched and verified independently, rather than requiring one cutover of 41 modules.

The 8 library modules carry more risk than the 33 scripts because the spine reaches them; the scripts are numerous but individually isolated. Order the work by that asymmetry rather than by count.

Done-when: the count of modules invoking a legacy description-read API reaches 0 from 41, reported at each step; the frozen spine stamp is re-run after each library-module seam and stays inside the budget the re-stamped baseline establishes, with the measured movement stated per step rather than only at the end; the compatibility facade is removed once the census reaches zero; and the raw per-machine reader is deleted, with a grep receipt showing no remaining reference.

Which budget must each migrated seam hold the frozen spine metric inside?

The plan's own §3 done-when and the sprint item's done-when both judge every migrated seam against 'the budget the re-stamped baseline establishes'.
