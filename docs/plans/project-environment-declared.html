One environment, rebuilt from what the project declares

Project Environment From Its Declaration

The shared project environment at .venv works only because it holds packages the project never declared. A plain uv sync, the command the repository's own instructions tell every agent to run, removes them. This plan makes the declaration match what the code and tests need, so a plain sync produces the working stack and nothing a session relies on lives outside pyproject.toml and uv.lock.

§1 — What a plain sync does today

Measured 2026-10-05 in the main checkout, while landing the tokamap exporter's new dev dependency: uv sync uninstalled 130 packages and installed one. The removed set included pytest, pytest-xdist, pytest-timeout, ruff, mypy, linkml and linkml-runtime, imas-ink, reckon-plans and the editable imas-ambix install itself, and the newly declared tokamap was not installed. Two causes account for all 130:

CausePackagesWhy a plain sync drops them
Declared only as extras61The dev, docs, viz, agent, data and train stacks are [project.optional-dependencies], which uv installs only with --extra or --all-extras; the environment had been built with all of them.
Declared nowhere68Absent from uv.lock: installed into the environment by hand at some earlier point, among them linkml, pytest-xdist, pytest-timeout, sphinx, mcp, sqlalchemy and reckon-plans (a path install of ~/Code/reckon).

The environment was restored the same day: uv sync --all-extras brought back the 61, the 68 were reinstalled at the versions the sync log recorded removing, and reckon-plans was reinstalled editable from ~/Code/reckon, which also brought playwright and pyee and matplotlib 3.11.2 (reckon requires matplotlib>=3.11.2; imas-ambix declares no matplotlib requirement of its own). uv pip check then reported all 296 installed packages compatible. That restore is the debt this plan retires: it put the undeclared packages back by hand, which is exactly what the project's rule against imperative installs exists to prevent.

§2 — Census: which libraries are truly default

A library is default when the repository cannot do its ordinary work without it: it is imported at module level by code under imas_ambix/ that an ordinary import or the imas-ambix console script reaches, or it is needed to run the test suite and the lint gate (pytest and its plugins named in the pytest configuration, ruff, and the packages the tests import). A library is optional when only a subsystem that runs on purpose-built hosts reaches it: documentation builds, GPU serving, the FAIR-MAST acquisition stack, the training stack. A library is unused when nothing in imas_ambix/, tests/ or scripts/ imports it.

The census node classifies every package in the restored environment by that rule. It scans imports statically (Python's ast over imas_ambix/, tests/ and scripts/, mapping each top-level module to its distribution through importlib.metadata.packages_distributions), separates module-level imports from imports inside functions, and records for each distribution its classification, the first importing file, and its current declaration (dependency, extra name, or none). It answers one question the rule cannot settle alone: whether anything in this repository imports reckon, and if so from which files, because reckon-plans is a sibling checkout and not a published package. The census writes its table as the evidence fragment docs/evidence/fragments/project-environment-declared/ped-census.html and changes no other file.

Done-when: the fragment holds one row per installed distribution with classification, first importing file and current declaration; it lists every default library that is not declared as a dependency or in a default-synced group, and every declared dependency that nothing imports; and it states whether and where reckon is imported.

§3 — Declare and relock

The declaration follows the census. Default runtime libraries go in [project.dependencies]. Default development libraries (the test runner, its plugins, the linter, the type checker, the tokamap validator) move from the dev extra into a [dependency-groups] dev group, which uv installs on a plain uv sync. The docs, viz, agent, data and train extras stay extras unless the census finds a default code path importing one of their members, in which case that member moves to the dependencies. A version constraint is added only where a known incompatibility requires it; nothing is pinned for its own sake. Path sources keep using [tool.uv.sources], as imas-ink and nova-stella already do.

The node edits pyproject.toml and regenerates uv.lock with uv lock only. It never runs uv sync against the shared environment, because a sync from a worktree repoints the shared editable install at that worktree. Its tests run with --no-sync against the restored shared environment, which already holds every package the census found.

Done-when: uv lock --check passes; every library the census classified default appears in [project.dependencies] or the dev group of uv.lock; the dev extra no longer exists; and the existing suite's collection (pytest --collect-only -q) reports the same number of tests with zero errors as before the edit, both logged.

§4 — Prove it on a fresh environment

The proof builds a new environment from the declaration alone, on node-local disk so the shared one is never touched: UV_PROJECT_ENVIRONMENT=/tmp/ped-fresh-<run> uv sync with no flags. Against that environment it imports every module under imas_ambix/, runs the imas-ambix console script's --help, collects the whole test suite, and runs ruff check imas_ambix tests. It then removes the fresh environment. Only after the proof passes does the coordinator run a plain uv sync in the main checkout, and it compares that sync's removal list with the census: anything removed must be a package the census classified optional or unused.

Done-when: in the fresh environment every module imports, the console script answers, test collection reports zero errors and the same test count as the shared environment, and ruff exits 0, all in one gate log; and the main checkout's plain sync removes no package the census classified default.

§ Decisions

Where do the test runner, its plugins, the linter and the validator live?

They are declared today as the dev extra, which a plain uv sync does not install.

Lead's direction 2026-10-05: plain uv sync must produce the working stack, with the libraries that are truly default declared as default. The test and lint tooling is what every agent session runs, so it belongs in the group uv installs by default. Rejected: keeping the extra, which leaves a plain sync without the test runner.
