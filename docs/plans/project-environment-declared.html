Project Environment From Its Declaration

The shared project environment at .venv works only because it holds packages the project never declared. A plain uv sync, the command the repository's own instructions tell every agent to run, removes them. This plan makes the declaration match what the code and tests need, so a plain sync produces the working stack and nothing a session relies on lives outside pyproject.toml and uv.lock.

§1 — What a plain sync does today

Measured 2026-10-05 in the main checkout, while landing the tokamap exporter's new dev dependency: uv sync uninstalled 130 packages and installed one. The removed set included pytest, pytest-xdist, pytest-timeout, ruff, mypy, linkml and linkml-runtime, imas-ink, reckon-plans and the editable imas-ambix install itself, and the newly declared tokamap was not installed. Two causes account for all 130:

CausePackagesWhy a plain sync drops them
Declared only as extras61The dev, docs, viz, agent, data and train stacks are [project.optional-dependencies], which uv installs only with --extra or --all-extras; the environment had been built with all of them.
Declared nowhere68Absent from uv.lock: installed into the environment by hand at some earlier point, among them linkml, pytest-xdist, pytest-timeout, sphinx, mcp, sqlalchemy and reckon-plans (a path install of ~/Code/reckon).

The environment was restored the same day: uv sync --all-extras brought back the 61, the 68 were reinstalled at the versions the sync log recorded removing, and reckon-plans was reinstalled editable from ~/Code/reckon, which also brought playwright and pyee and matplotlib 3.11.2 (reckon requires matplotlib>=3.11.2; imas-ambix declares no matplotlib requirement of its own). uv pip check then reported all 296 installed packages compatible. That restore is the debt this plan retires: it put the undeclared packages back by hand, which is exactly what the project's rule against imperative installs exists to prevent.

§4 — Prove it on a fresh environment

The proof builds a new environment from the declaration alone, on node-local disk so the shared one is never touched: UV_PROJECT_ENVIRONMENT=$TMPDIR/ped-fresh-<run> uv sync with no flags, where TMPDIR is the node's own scratch, the root imas_ambix/gs/artifact_resolution.py staging_cache_root() already uses for node-local work, so the environment dies with the run's scratch. Against that environment it imports every module under imas_ambix/. A module outside the optional subsystems must import; a module inside one must either import or fail with ModuleNotFoundError naming a distribution the census classed optional, and any other failure fails the proof. Which modules are optional, and which distributions, is not re-declared by the proof: it takes OPTIONAL_SUBSYSTEM_ROOTS and the census from tests/test_declared_dependencies.py, the module that owns both. Because build_census() maps imports to distributions through whatever the running interpreter has installed, it is run in the shared environment, where every declared distribution is present, and its optional set is written to the run's scratch and read by the import walk in the fresh environment, so the proof and the census share one definition of optional. The proof's driver is a run artifact kept beside its gate log, not a repository module, and the evidence fragment is the only file it adds, so it adds no public surface. It also runs the imas-ambix console script's --help, collects the whole test suite, and runs ruff check imas_ambix tests, then removes the fresh environment. The worker does only this. The coordinator then runs a plain uv sync in the main checkout and checks its removal list against the census: every removed package must be one the census classed optional, unused or transitive, and nothing classed default may go.

Done-when, for the worker: in the fresh environment every non-optional module imports and every optional module either imports or fails naming an optional distribution, the console script answers, test collection reports zero errors and the same count as the shared environment, and ruff exits 0, all in one gate log. For the coordinator: the main checkout's plain sync removes nothing the census classed default.

§5 — Triage the tests the 300 s bound reaches

The whole-suite run that §3 recorded, at -n 16 against the shared environment, aborted 37 tests at the 300 s per-test default; the list, with the phase each aborted in and the duration the --durations table records, is in docs/evidence/fragments/project-environment-declared/ped-declare-relock.html. The rule this plan set is that the default stays at 300 s and is raised only for a test whose measured duration needs more, so each of the 37 is measured, not waived. Some are long work under contention (the training and overfit smoke tests, the MAST corpus scans in tests/data/test_machine_map.py, the nova ledger fixture in tests/fluxstate/test_consumer_contract.py at 1294 s of setup); some are waits that should not take time at all, such as tests/test_agent.py::test_clive_unreachable_catalog_never_falls_back_to_openrouter, which is a network wait rather than work.

Each test is run alone on the fleet compute node with -p no:cacheprovider --timeout=3600 and its wall time recorded. A test whose own work takes longer than 300 s gets @pytest.mark.timeout(N) with N twice its measured time, and the mark's comment states the measurement. A test that spends its time waiting is a hang: its wait is removed or bounded in the test, or, where the fix belongs to another plan's code, it stays failing and that plan is named. Tests sharing a module- or session-scoped fixture are judged by the fixture's setup time. The 20 other failures in the same run (for example tests/agent/test_flight_placement.py, which raises KeyError: 'backends') are not timeouts and are not this section's; they are listed with their first error line so their owners can find them.

Done-when: a table in the section's evidence fragment gives each of the 37 tests its measured duration and its outcome (marked with N, wait fixed, or left failing with the owning plan named), and a whole-suite run on the fleet compute node at -n 8 reports no pytest-timeout abort that the table does not account for.

§ Decisions

Where do the test runner, its plugins, the linter and the validator live?

They are declared today as the dev extra, which a plain uv sync does not install.

Lead's direction 2026-10-05: plain uv sync must produce the working stack, with the libraries that are truly default declared as default. The test and lint tooling is what every agent session runs, so it belongs in the group uv installs by default. Rejected: keeping the extra, which leaves a plain sync without the test runner.
