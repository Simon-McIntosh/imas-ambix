§1 — The defect, measured

Some tool calls from the local lane (clive, serving deepseek-v4.1-flash) reach the Claude Code worker with the model's own tool-call markup inside an argument. Reckon's figure-review evaluation on 2026-10-22 found it in run r-20261022T124012688022-clive-judges-pair-fig-01. The run's first Read carried a file_path that began with the right directory and then continued as ... followed by <｜DSML｜ calls> and <｜DSML｜ invoke name="Bash">. The model had emitted a second tool call, and it arrived as text inside the first call's argument instead of as a second call. The harness answered File does not exist. Nothing reported a parse failure, and the run went on to make a correct Read.

Across the 1,381 clive runs in ~/.config/reckon/crew/runs/ from 2026-10-20 to 2026-10-22, 20 of 93,862 tool calls carried DSML in their arguments: 10 Bash, 6 Edit and 4 Read, in 20 runs. The rate is low, but every occurrence is silent, and it can turn a correct action into a failed one or, for Bash and Edit, into a different action. A second defect appeared beside it: in r-20261022T125056443470-clive-judges-pair-fig-07 a Read path was truncated to a literal .... That one carries no markup and may have a different cause.

The serve leaves parsing to the engine: [engine.parsers] tool_call = "auto" in imas_ambix/agent/profiles/deepseek-v4-1-flash.toml, which the engine resolves to deepseekv41. The profile records one correct tool-calling round trip as verification, which a single call cannot show to be false for this case.

§2 — Find the layer the markup survives

Why. The markup can survive in three places, and the fix is different in each. The engine's deepseekv41 parser can leave a second call's markup inside the first call's argument. The router can carry an unparsed fragment through when it translates the engine's response into the Anthropic tool_use blocks Claude Code reads (imas_ambix/agent/router.py, litellm_config.py). Or the model itself can write the markup into a string argument, where no parser is wrong to leave it.

Change. An investigation takes at least three of the twenty leaked calls named in the census below. For each, it recovers what the engine actually returned, from the request receipts or the engine's logs where they hold the raw completion; where they do not, it reproduces the call by replaying the run's conversation up to that turn against the serve. It then follows each one through the router to the tool_use block the worker received, and names the layer where the markup first appears as argument text instead of as a separate call.

Write paths: ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/report.md.

Done when the report lists the twenty leaked calls by run and tool (the census: clive runs whose worker.json names backend clive, from 2026-10-20, tool-use inputs containing DSML). For at least three of them it shows the engine's raw output and the router's translated block side by side, quoted, with where each came from. It names exactly one layer as the origin, or says which of the three it cannot rule out and why. It also says whether the truncated-path case in fig-07 shares that origin. Every log is written under the run directory, starts with its revision and the literal command, and ends in EXIT=. Negative control: three clean tool calls from the same runs, traced the same way, show no markup at any layer.

§3 — Stop the markup at the layer that leaks it

Why. Once §2 names the layer, the fix belongs there. A parser or router fix splits the markup into the calls it encodes, or refuses the response as malformed so the harness sees an error instead of a wrong action. A model-side cause needs a guard at the router instead.

Change. Written once §2 lands, against the layer it names. Whatever the layer, a tool call whose argument carries the model's tool-call markup is never delivered to the worker as a well-formed call. Either it becomes the calls the markup encodes, or it reaches the worker as an explicit error.

Done when replaying §2's captured leaked responses through the fixed layer delivers no tool argument containing DSML, and each response either yields the calls its markup encodes or an explicit error. Replaying §2's clean responses delivers byte-identical calls to before. A re-run of the census over clive runs made after the fix lands finds no leaked argument. Negative control: with the fix reverted, the captured leaked responses deliver the markup again.
