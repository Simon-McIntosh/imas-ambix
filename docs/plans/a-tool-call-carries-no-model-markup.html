§1 — The defect, measured

Some tool calls from the local lane (clive, serving deepseek-v4.1-flash) reach the Claude Code worker with the model's own tool-call markup inside an argument. Reckon's figure-review evaluation on 2026-10-22 found it in run r-20261022T124012688022-clive-judges-pair-fig-01. The run's first Read carried a file_path that began with the right directory and then continued as ... followed by <｜DSML｜ calls> and <｜DSML｜ invoke name="Bash">. The model had emitted a second tool call, and it arrived as text inside the first call's argument instead of as a second call. The harness answered File does not exist. Nothing reported a parse failure, and the run went on to make a correct Read.

The census is ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/census.py. It counts a tool call when its tool_use input contains the markup token <｜DSML｜, the opening of a DSML block. A search that merely names the format does not write that token, and runs belonging to this plan are excluded, since they handle the markup on purpose. Run over clive runs launched from 2026-10-20T00:00Z to 2026-10-22T19:00Z (log ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/census-baseline.log), it found 20 of 93,565 tool calls in 1,383 runs: 10 Bash, 6 Edit and 4 Read, one in each of 20 runs. The rate is low, but every occurrence is silent, and it can turn a correct action into a failed one or, for Bash and Edit, into a different action. A second defect appeared beside it: in r-20261022T125056443470-clive-judges-pair-fig-07 a Read path was truncated to a literal .... That one carries no markup and may have a different cause.

The serve leaves parsing to the engine: [engine.parsers] tool_call = "auto" in imas_ambix/agent/profiles/deepseek-v4-1-flash.toml, which the engine resolves to deepseekv41. The profile records one correct tool-calling round trip as verification, which a single call cannot show to be false for this case.

§2 — Find the layer the markup survives

Why. The local lane points Claude Code straight at the routing origin (imas_ambix/agent/clive.py, ANTHROPIC_BASE_URL="$GLOBAL_ORIGIN"), and the router relays each response body chunk unchanged (RouterApp._relay in imas_ambix/agent/router.py); the LiteLLM proxy rendered by litellm_config.py serves only clive's hybrid branch. deepseek-v4.1-flash is served by SGLang (type = "sglang" in its profile, launched from the container /work/projects/imas_gpu/containers/sglang-dev-dsv41.sif), and SGLang takes no middleware, so imas-ambix's OrphanThinkMarkerMiddleware, which only the vLLM launch adds, is not on this path. That leaves two places the markup can survive, each needing a different fix. SGLang's DeepSeek-V4.1 tool-call parser, which [engine.parsers] tool_call = "auto" resolves to, can leave a second call's markup inside the first call's argument. Or the model itself can write the markup into a string argument, where no parser is wrong to leave it.

Change. The primary instrument is deterministic. The investigation runs SGLang's DeepSeek-V4.1 tool-call parser, the class under /sgl-workspace/sglang/python/sglang/srt/function_call/ in /work/projects/imas_gpu/containers/sglang-dev-dsv41.sif, offline on raw completion text written in the model's DSML format. It feeds the parser cases built from what the leaked calls show: two well-formed calls in one completion; a second call that begins before the first call's argument closes; a call whose argument string contains the opening token. It records which inputs yield a single call whose argument carries the token. It cross-checks against the leaked calls themselves: for each leaked call §1's census names, it reconstructs the raw text the parser must have seen from the delivered argument in the run's stream.jsonl, and checks that the parser, given that text, delivers exactly that argument. Because the request receipts hold no response body (RequestReceipt in imas_ambix/agent/request_receipts.py), and a leak occurs about once in 4,700 calls, a live replay is a supplement and not the evidence: where it is run, up to twenty samples a call for at least three leaked calls, its outcome is reported. It confirms with one traced response that the router relays the body unchanged. Each parser input and its output is saved as a replayable fixture under ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/fixtures/, for the leaking cases and for three clean ones; §3 replays those fixtures.

Write paths: ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/report.md, ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/fixtures/.

Done when the report lists every leaked call §1's census finds over its baseline window by run and tool, the twenty in ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/census-baseline.log, and reports any later ones separately. It shows the parser run: the container and the parser class and file it imported, each input case, and the parsed calls it returned, quoted. For every leaked call, it states whether the parser, given reconstructed raw text, delivers exactly the leaked argument. It names one origin: the parser, when an input with two encoded calls yields one call carrying the token; or the model, when the parser splits every such input correctly and the leaked argument can only come from the model writing the token inside a string. It reports any replay outcomes and the router check. ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/fixtures/ holds each parser input and output, for the leaking cases and three clean ones. It also says whether the truncated-path case in fig-07 shares that origin; if it does not, §4 holds it. Every log is written under the run directory, starts with its revision and the literal command, and ends in EXIT=. Negative control: three clean completions, each with one well-formed call, parse to that one call with no token in its argument.

§3 — Stop the markup at the layer that leaks it

Why. Once §2 names the layer, the fix belongs there. A parser or router fix splits the markup into the calls it encodes, or refuses the response as malformed so the harness sees an error instead of a wrong action. A model-side cause needs a guard at the router instead.

Change. Written once §2 lands, against the layer it names. Whatever the layer, a tool call whose argument carries the model's tool-call markup is never delivered to the worker as a well-formed call. Either it becomes the calls the markup encodes, or it reaches the worker as an explicit error.

Done when replaying the leaked fixtures in ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/fixtures/ through the fixed layer delivers no tool argument containing the <｜DSML｜ token, and each response either yields the calls its markup encodes or an explicit error. Replaying the clean fixtures delivers byte-identical calls to before. ~/.config/reckon/crew/reports/imas-ambix/a-tool-call-carries-no-model-markup/census.py, run over clive runs launched after the fix is deployed, finds no leaked call, and its log is recorded beside the baseline. Negative control: with the fix reverted, the leaked fixtures deliver the markup again.

§4 — A truncated tool-call path

Why. In r-20261022T125056443470-clive-judges-pair-fig-07 a Read reached the worker with its path cut to a literal ... and no markup. §2 says whether it shares the DSML leak's origin. If it does, §3's fix covers it and this section closes as done with that evidence. If it does not, this section is written against the cause §2 reports.
