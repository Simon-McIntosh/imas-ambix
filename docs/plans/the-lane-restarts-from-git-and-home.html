§1 — Why: the lane's state lived beside its data, in one copy

At 00:08:00 UTC on 19 November a worker's cleanup command removed /work/projects/imas_gpu. The model server and the router kept running from memory, so the lane kept serving. Everything they would have needed to start again was gone, with the cost record and the weights. The code was in git and the engine environments were under home, which is the only reason the lane was recovered the same day without a snapshot restore.

Two further exposures were found while recovering. The engine environments under home are built by hand and have no committed record to rebuild them from (§7). The telemetry index on the fleet node's local disk had reached 6.08 GB of a 23 GB disk on which every queued crew request is held once free space falls under 4 GiB (§8).

The rules this plan implements are in the user-space agent guidelines under State Is Not Kept Beside Data: operator state under home with a dated copy, one credential file under home with mode 600, downloaded data read-only with its source recorded, and a launcher where workers cannot write.

§2 — The launcher lives where no worker can write

Deliverable. The deploy command writes the launcher under the service account's home, in a directory no group or other user can write. The shared project directory holds no launcher. Every consumer that resolved the old location resolves the new one, and the launcher records the command that regenerates it.

Done when. A test deploys into a temporary home: the launcher is written there with no group or other write bit on it or its directory, and its header names its regenerating command. A deploy whose target directory is group-writable is refused, naming the directory. Negative control: at the base revision the deploy writes into the group-writable target. On the workstation, the old location holds no launcher, a new shell resolves the launcher to the home path, and one crew watcher in each of two projects starts through it. The workstation steps change no running serve or router job. Write paths: imas_ambix/agent/cli.py, imas_ambix/agent/clive.py, imas_ambix/agent/AGENTS.md and tests/test_agent_launcher_location.py.

§3 — Credentials are read from one file under home

Deliverable. Serve, router and launcher read their keys from one file under home. A file readable or writable by group or other is refused. No code path reads a credentials file from the shared project directory, and a start with a required key missing fails before it submits a job, naming the key and the file.

Done when. A test with a temporary home shows: a mode-600 file supplies each named key; the same file at mode 640 is refused, naming the file and its mode; a credentials file placed in the temporary site directory is not read; a start with a required key absent exits before any scheduler call, naming the key. Negative control: at the base revision the site-directory file is read. The tests use made-up key values and read no real credentials file. The lead re-enters the keys once the section has landed; the section is done on its tests and does not wait for that. Write paths: imas_ambix/agent/cli.py, imas_ambix/agent/slurm.py, imas_ambix/agent/litellm_service.py, imas_ambix/agent/AGENTS.md and tests/test_agent_credentials_file.py.

§4 — The serve registry is rebuilt from what is running

Deliverable. The registry lives under home with a dated copy. One command rebuilds an entry for a running serve from the scheduler's own record of the job and the committed profile, and status and reload then manage that serve as they did before the loss. With no registry and no running serve, status says so and names the rebuild command.

Done when. A test with a stand-in scheduler listing one running serve job and an empty temporary home: the rebuild writes an entry whose model, port, node and job id equal the stand-in's, status reports the serve, and a second rebuild changes nothing. With the registry file removed, status names the rebuild command and exits non-zero. Negative control: at the base revision status with no registry reports no serve and exits zero. On the workstation the rebuild is run once for the running serve and status then reports it; nothing is restarted. Write paths: imas_ambix/agent/registry.py, imas_ambix/agent/cli.py and tests/test_agent_registry_rebuild.py.

§5 — The cost record reports one coverage, with the gap credited and marked

Why. The monitor showed coverage of 17 hours beside 6 days after the loss. The lead's decision on 19 November: credit the gap and show the full period.

Deliverable. A span in which the serve ran and no receipt was recorded is credited from the request log for that span where one exists, and otherwise at the mean rate of the recorded hours either side. The monitor reports one coverage figure for the period, with the credited share stated beside it. Recorded and credited amounts are stored apart, so a credit can be replaced by a measurement later.

Done when. A test builds a ledger with a seven-hour hole: the reported period is continuous, the credited hours equal the hole, the credited tokens equal the stand-in request log's total for the hole, and with no request log they equal the neighbouring mean times the hole. The recorded total is unchanged by the credit. With no hole the credited share is zero and no credit is shown. Negative control: at the base revision the same ledger reports two coverage spans. On the workstation the watch document then reports one coverage for the served model, with the span 00:08 to 07:14 UTC on 19 November marked as credited. Write paths: imas_ambix/agent/gpu_watch, imas_ambix/agent/serving_receipts.py and tests/test_agent_watch_credited_gap.py.

§6 — The restart tests read no file outside the repository

Deliverable. The two restart cases in tests/test_agent.py that read a model's weights from the shared project directory build what they need in a temporary directory, and assert the same restart behaviour.

Done when. Both cases pass on a node where /work/projects/imas_gpu is not mounted or is empty, and open no path outside the temporary directory and the repository, shown by a test that fails on any such open. Each still fails when the restart behaviour it guards is reverted. Negative control: at the base revision both fail on that node. Tests run on all_debug. Write paths: tests/test_agent.py.

§7 — An engine environment is rebuilt from a committed record

Why. The engine environments survived because they are under home. They are also the one part of a serve that cannot be recreated from git.

Deliverable. Each engine environment a profile names has a committed record from which it is rebuilt: the resolved package set with versions and digests, the interpreter, and every source patch applied. A serve submission is refused when the environment it would use differs from its record, naming the first difference. The record of each existing environment is taken from the environment as it stands.

Done when. A test builds a small environment from a record in a temporary directory, then alters one installed package: the unaltered environment is accepted, the altered one is refused naming that package, and an environment with no record is refused naming the missing record. Negative control: at the base revision the altered environment is accepted. The committed records cover every environment the committed profiles name, checked by a test over the profiles. Building an environment runs on rigel; no running serve is touched. Write paths: imas_ambix/agent/envs, imas_ambix/agent/slurm.py, imas_ambix/agent/cli.py and tests/test_agent_engine_env_record.py.

§8 — The telemetry index stays bounded on the fleet node's disk

Why. The index file was 6.08 GB on 19 November on a 23 GB node-local disk. When that disk falls under 4 GiB free, every queued crew request on the workstation is held.

Deliverable. The index on node-local disk holds at most a stated size, 1 GB unless measurement gives a reason for another figure, and returns the space it frees to the disk. History older than the index keeps is still answered from the snapshots under home. The monitor's figures for the retained period are unchanged.

Done when. A test fills an index past the bound in a temporary directory: after one retention pass the file on disk, with its write-ahead log, is under the bound, and the totals the monitor reads for the retained period equal those from before the pass. A query for a day outside the retained period is answered from a stand-in snapshot. Negative control: at the base revision the file stays above the bound after the pass. On the fleet node the index is under the bound after one pass and the monitor shows the same one-hour and one-day figures as immediately before. Write paths: imas_ambix/agent/telemetry_retention.py, imas_ambix/agent/telemetry_index.py, imas_ambix/agent/index_placement.py and tests/test_agent_index_stays_bounded.py.

§9 — The Kimi K3.1 Pro profile is sized on its hardware

Deferred until a node with eight B300 cards is available to this account. The weights (nvidia/Kimi-K3.1-Pro-NVFP4 at its pinned revision, 1.5 TB) were downloaded and made read-only on 19 November, and the profile is committed with its topology marked unverified against the published card specification.

Done when. On an eight-card B300 node the profile starts a serve that answers a completion, and the profile's memory, context and concurrency figures are replaced by figures measured there, with the unverified mark removed. A start on hardware the profile does not fit is refused before submission, naming the shortfall. Write paths: imas_ambix/agent/profiles/kimi-k3-1-pro.toml and tests/test_agent_candidate_profiles.py.

§10 — A restart from an empty project directory is rehearsed

Deliverable. A record of what a restart needs and where each item now lives, proved by a dry run that sees an empty shared directory.

Done when. The evidence record lists every file the serve, router, recorder and launcher read at start, each with its location, its second copy or regenerating command, and its mode. A dry-run start of serve and router with the site directory pointed at an empty temporary directory, and weights stood in by the read-only download, composes both job scripts with no missing-file error, and its output is in the record. The same dry run with the home copies also hidden fails, naming the first missing file: that is the negative control. No running job is stopped or restarted. Write paths: docs/evidence/archive/the-lane-restarts-from-git-and-home-landed.html.

§ Followups

Build §2 to §8, then rehearse the restart

§2 to §8 are independent. §3 and §4 remove the two things a restart cannot do today, so they go first. §10 runs last. §9 waits for hardware. The lead re-enters the lost keys in the home credentials file after §3 lands. Never stop or restart the running serve or router job for this plan.
