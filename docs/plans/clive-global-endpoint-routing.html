Corrective architecture · shared consumer service

One endpoint, one catalog, available to everyone

Replace user-scoped scheduler discovery with a site-owned, keyless vLLM catalog. Every Clive consumer polls the same base URL and sees exactly the models that endpoint currently reports ready.

§1 — Corrected authority boundary

Reuse scout landed. Twenty seams were classified: 8 keep, 6 adapt, 4 delete, and 2 replace. Installed vLLM 0.28.0 supports a pure-ASGI --middleware hook and extra model-card fields, so the global catalog can publish site-owned topology metadata without any consumer-side operator dependency. One active topology per release id is required until the global origin owns a separate routing discriminator.

The global endpoint configured by SiteConfig.default_url is the sole consumer authority. Clive polls GET <base-url>/v1/models; a successful, non-empty response defines availability. It never runs squeue, reads SLURM job ownership, opens batch scripts, imports model profiles, or inspects a user's repository, environment, home directory, or credentials.

Scheduler and deployment state remain operator concerns. Operators may use them to decide which backend the stable endpoint publishes, but those facts do not cross into the shared launcher. The consumer path is keyless and secret-free. Failure to reach the endpoint is fatal and cannot fall back to a personal or external provider.

§2 — Global model and topology catalog

Provider landed. Commit 8d27afa adds a pure-ASGI vLLM catalog middleware and launch-owned metadata wiring. Twenty-one focused tests pass, covering native-only intersection, 2/4/6/8 accelerator counts, explicit precision, invalid and duplicate fail-closed behavior, multi-frame response repair, and byte-preserving non-catalog passthrough. An independent worker repeated the suite at 21/21 and returned an unqualified pass.

Each /v1/models item carries the server-reported release id, context length when known, and site-owned topology metadata: accelerator family, GPU count, and checkpoint precision. The model id stays the release identity, while Clive renders the separate runtime topology as 2×H200, 4×H200, 6×H200, or 8×H200. Missing or invalid topology metadata is rejected rather than inferred from filenames, profiles, or scheduler state.

The global endpoint may report one model or route several ready backends behind the same origin. Clive always sends inference back to that same base URL with the selected model id. A future endpoint item whose id is glm-5.3 therefore becomes selectable without a Clive source or deployment change.

§3 — Standalone shared launcher

Remove the runtime dependency on the per-user imas-ambix operator CLI. The generated GPFS launcher embeds the site URL, performs its own standard-library HTTP and JSON handling, and offers a dynamic list and deterministic model/topology selector. It does not read the shared API-key file or any personal override for default discovery.

The selected model and the one global base URL feed both Claude Code and Codex. Multiple catalog items require an explicit selection in non-interactive use; a single item may be selected automatically. The explicit OpenRouter branch remains isolated and opt-in.

§ Decisions

What determines which models Clive makes available?

Only the successful model catalog returned by one globally accessible vLLM base URL.

Does discovery depend on a user's scheduler jobs, repository, or credentials?

No. The launcher is shared, standalone, keyless, and identical for every user.

Where does the 2×, 4×, 6×, or 8× H200 distinction come from?

From site-owned metadata in the global model response, separate from the release model id and never inferred client-side.
