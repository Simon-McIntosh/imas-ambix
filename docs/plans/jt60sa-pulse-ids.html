JT-60SA Pulse IDSs and Equilibrium Animation

The JT-60SA machine map (jt60sa-machine-map) holds the transformation from facility data to IDS paths: a catalogue that serves the machine description of each operating phase, and signal maps that carry EDDB channels to coil currents, the TF current and the plasma current. Nothing yet writes a pulse. This plan mints one, E101154 (OP1, plasma current near 1 MA), as IDSs on disk, then animates it from those IDSs alone. Each frame shows the flux surfaces, the separatrix, the O-point, the X-points and the strike points over the wall, the vessel and the coil outlines, drawn by imas-ink. Running the same mint at the facility is planned separately, in jt60sa-facility-mint.

§2 — The equilibrium IDS, with its topology

The animation draws equilibria, and the machine map's §7 owns mapping them: its second rung reads SELENE's equilibria from the facility's equilibrium database (EQDB) and maps psi on its grid, the boundary and the profiles into equilibrium, after §6 has fixed the source COCOS from data. This section does not read EQDB itself. It waits on that rung and mints E101154's equilibria through the same writer as §1, so the equilibrium joins the other five IDSs in /work/projects/imas_gpu/jt60sa/ids/101154/.

imas-ink renders topology and never computes it, so the minted IDS must carry it in the fields imas-ink reads (imas_ink/extract.py extract_slice): psi on profiles_2d[0] with its grid.dim1 and grid.dim2; global_quantities.psi_axis, psi_boundary, ip and magnetic_axis, which is the O-point; boundary.outline; each X-point in constraints.x_point[].position_reconstructed; and each strike point in constraints.strike_point[].position_reconstructed. Where the EQDB record already carries the X-points and strike points, the map binds them. Where it does not, they are computed from the mapped psi and the coil_vv first wall, and never by a new finder. Two owners can compute them. nova's equilibrium topology (nova/equilibrium) owns separatrix and X-point finding. In ambix, imas_ambix/latent/topology.py read_topology already finds the O-point and X-points from psi by critical-point search, and imas_ambix/worldmodel/camera_topology_targets.py _strike_points intersects the separatrix level set with a wall polygon for MAST's evaluator labels. The other ambix sites are not finders: imas_ambix/worldmodel/equilibrium_labels.py xpoint_null_set filters nulls a store already carries, and imas_ambix/challenge/convention.py _axis_and_boundary samples EFIT rows. The decision topology-source settles which owner serves, once the machine map's open question eqdb-reader fixes the record's fields. If it is computed, the decision says whether latent/topology.py serves as it is, or is set aside for nova and why.

Done-when: E101154's minted equilibrium reads back through imas.DBEntry at DD 4.1.1 with one time slice per SELENE record. For every diverted slice, a test asserts at least one X-point inside the vessel, two strike points within 1 cm of the first wall, and an O-point inside the last closed surface. For every slice, the psi at the reported O-point and X-point matches psi_axis and psi_boundary within 1 % of their difference. imas_ink.extract.extract_slice reads every slice without falling back to an empty field.

§4 — The E101154 animation, from IDSs alone

The animation is a second output of scripts/figures_jt60sa_geometry.py rather than a parallel script. ambix has two JT-60SA imas-ink drivers: scripts/figures_jt60sa_signals.py draws time traces from the EDDB cache, and scripts/figures_jt60sa_geometry.py opens a directory of {ids}.nc files at the catalogue's DD version and builds the geometry with extract_geometry. The animation reads only minted IDSs, whose directory has that same layout, so it belongs to the geometry driver. It gains one option naming the pulse, and retires nothing: the script takes no options today, and a pulse is a new input to it. With it, the script opens only the minted IDSs in /work/projects/imas_gpu/jt60sa/ids/101154/, builds the geometry from wall, pf_active and magnetics, and calls animate_pulse on equilibrium with the probes and flux loops left out. It draws nothing itself and holds no style constant, so a rendering change is an imas-ink change. The GIF is written to docs/figures/jt60sa-pulse/E101154.gif; it is raster by nature, so no SVG twin is written.

Done-when: the GIF exists with one frame per equilibrium time slice. The script refuses if any input is not a minted IDS, so no frame reads the cache, the store or EQDB directly. The evidence fragment docs/evidence/fragments/jt60sa-pulse-ids/ embeds the GIF and records its frame count, its time range and, per frame, the number of X-points and strike points drawn. The lead has looked at it.

§ Decisions

What does each frame of the pulse animation show?

The lead's ruling: flux surfaces with every topological feature (X-points, O-points, strike points); shading coils by current was rejected as decoration that carries no equilibrium information.

May nodes read SELENE equilibria from EQDB on the JT-60SA server?

Authorised by the lead for light load, searches included, provided the server is not hit hard: each record is fetched once into the cache and never refetched for timing.

Where do the X-points and strike points in the minted equilibrium come from?

Do the 17 probes and 27 flux loops appear in the animation frames?

The lead's ruling: the 17 probes and 27 flux loops are left out of the animation frames, which carry equilibrium information only. The pass-through this needs is imas-ink:geometry-figure-vessel-units §5, never a wrapper in ambix.
