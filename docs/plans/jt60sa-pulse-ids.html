JT-60SA Pulse IDSs and Equilibrium Animation

The JT-60SA machine map (jt60sa-machine-map) holds the transformation from facility data to IDS paths: a catalogue that serves the machine description of each operating phase, and signal maps that carry EDDB channels to coil currents, the TF current and the plasma current. Nothing yet writes a pulse. This plan mints one, E101154 (OP1, plasma current near 1 MA), as IDSs on disk, then animates it from those IDSs alone. Each frame shows the flux surfaces, the separatrix, the O-point, the X-points and the strike points over the wall, the vessel and the coil outlines, drawn by imas-ink. Running the same mint at the facility is planned separately, in jt60sa-facility-mint.

§2 — The equilibrium IDS, with its topology

The animation draws equilibria, and the machine map's §7 owns mapping them into equilibrium. As of 2026-10-08 that section supplies no E101154 psi. Its psi bindings and the reference loader's psi and axis reduction are scoped to E101011 alone, from a G-EQDSK file copied under /work. From PSRC, which carries no flux grid, it takes only the boundary, X-point, plasma centre and plasma current. Its search for an E101154 psi or signed-q source (EDDB FAME, EQDB, EQRV, EQEFIT, LOCALDB, LCDB/MBDB, the Experiment DB Web API, SELENE outputs) is still open. So this section is deferred until the machine map names a psi source that covers E101154. This section reads no equilibrium database itself. Once that source exists, it writes E101154's equilibria through the same writer as §1, imas-alambic write, so the equilibrium sits beside the pulse's description IDSs in the writer's output. The writer owns that layout; jt60sa-facility-mint §8 is moving it from one file per IDS to one run file per pulse. So this section reaches the output through the writer's own path rule and never names a path. If the writer exposes no such rule when this section is built, the section adds one to imas_alambic/pulse_writer.py rather than restating the layout.

imas-ink renders topology and never computes it, so the minted IDS must carry it in the fields imas-ink reads (imas_ink/extract.py extract_slice): psi on profiles_2d[0] with its grid.dim1 and grid.dim2; global_quantities.psi_axis, psi_boundary, ip and magnetic_axis, which is the O-point; boundary.outline; each X-point in constraints.x_point[].position_reconstructed; and each strike point in constraints.strike_point[].position_reconstructed. Where the EQDB record already carries the X-points and strike points, the map binds them. Where it does not, they are computed from the mapped psi and the coil_vv first wall, and never by a new finder. Two owners can compute them. nova's equilibrium topology (nova/equilibrium) owns separatrix and X-point finding. In ambix, imas_ambix/latent/topology.py read_topology already finds the O-point and X-points from psi by critical-point search, and imas_ambix/worldmodel/camera_topology_targets.py _strike_points intersects the separatrix level set with a wall polygon for MAST's evaluator labels. The other ambix sites are not finders: imas_ambix/worldmodel/equilibrium_labels.py xpoint_null_set filters nulls a store already carries, and imas_ambix/challenge/convention.py _axis_and_boundary samples EFIT rows. The decision topology-source settles which owner serves, once the machine map's open question eqdb-reader fixes the record's fields. If it is computed, the decision says whether latent/topology.py serves as it is, or is set aside for nova and why.

Done-when: E101154's minted equilibrium reads back through imas.DBEntry at DD 4.1.1 with one time slice per SELENE record. For every diverted slice, a test asserts at least one X-point inside the vessel, two strike points within 1 cm of the first wall, and an O-point inside the last closed surface. For every slice, the psi at the reported O-point and X-point matches psi_axis and psi_boundary within 1 % of their difference. imas_ink.extract.extract_slice reads every slice without falling back to an empty field. Negative control: the same topology test, run on a copy of one diverted slice whose stored constraints.x_point[0].position_reconstructed is moved 0.5 m outside the first wall, fails the X-point-inside-the-vessel assertion. The result is recorded in its own log. The control mutates a stored field the assertion reads, so it cannot pass through a recomputation.

§4 — The E101154 animation, from IDSs alone

The animation is a second output of scripts/figures_jt60sa_geometry.py rather than a parallel script. ambix has two JT-60SA imas-ink drivers: scripts/figures_jt60sa_signals.py draws time traces, and scripts/figures_jt60sa_geometry.py builds the machine geometry with extract_geometry from description IDSs. The animation needs that same geometry under the written equilibrium, so it belongs to the geometry driver. It gains one option naming the pulse, and retires nothing: the script takes no options today, and a pulse is a new input to it. With it, the script opens only the IDSs the writer wrote for that pulse. It reaches them in one function, through the writer's own path rule, so a change in the writer's layout is a change in one place. It builds the geometry from wall, pf_active and magnetics, and calls animate_pulse on equilibrium with the probes and flux loops left out. It draws nothing itself and holds no style constant, so a rendering change is an imas-ink change. The GIF is written to docs/figures/jt60sa-pulse/E101154.gif; it is raster by nature, so no SVG twin is written.

Done-when: the GIF exists with one frame per equilibrium time slice. The script refuses if any input is not a written IDS, so no frame reads the cache, the store or EQDB directly. The evidence fragment docs/evidence/fragments/jt60sa-pulse-ids/ embeds the GIF and records its frame count, its time range and, per frame, the number of X-points and strike points drawn. The lead has looked at it.
