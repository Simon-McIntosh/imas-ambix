§1 — Why this reopens a decision that was locked

clive local-only routing removed the OpenRouter surface on the premise that it was exposed on a shared cluster launcher. That premise was wrong, and checking it is what reopened this. The or-* models were never reachable by anyone but their key-holder, for three independent reasons:

  • The route was gated on [[ -r "$HOME/.config/openrouter/key" ]] — a per-user, mode-600 path. No other user had one.
  • clive --deploy installed the systemd unit into the deploying user's ~/.config/systemd/user/. Nobody else ever ran --deploy, so nobody else had the unit.
  • The unit's ExecStart was %h/.local/bin/litellm — a pipx install in one home directory.

So another user holding an OpenRouter key would not have seen extra models; they would have seen clive: could not start imas-ambix-llm.service and exit 1. The old design was not a leaky public surface — it was a private surface that broke the launcher for anyone else who tried to use it.

What actually caused the outage was narrower than the removal. The picker default was routed through the proxy, so a proxy-side auth fault took down the model everyone relies on. The four or-* 403s were an unrelated exhausted quota. Restoring the models is therefore compatible with the fix, provided the default invocation stops depending on the proxy.

§2 — The shape that makes this safe

Locked by owner directive: opt-in flag, and the default invocation never touches the proxy.

  • clive — unchanged from what shipped. Direct to the served model, no proxy process, no key-file check, identical for every user. This is the invocation the cluster depends on, and no OpenRouter state can affect it.
  • clive --openrouter (or CLIVE_OPENROUTER=1) — starts the per-user proxy and presents the local model plus the or-* slots.

The distinction that matters is between the two failure modes, because the old design conflated them:

FailureOld designThis design
OpenRouter quota exhausted4 of 5 slots deadclive unaffected; opt-in mode loses the or-* slots, local slot still answers
Proxy down or litellm absentclive fully dead (exit 1)clive unaffected; opt-in mode refuses with a message naming plain clive
Auth-header mismatchdefault model 401cannot reach the default model at all

Note what is not claimed: inside --openrouter mode the local model does traverse the proxy, because Claude Code has a single ANTHROPIC_BASE_URL and cannot split routing per model. The guarantee is about the default invocation, which is the one that was an outage.

§3 — The auth mismatch has to be fixed, not worked around

The proxy's local slot 401s because litellm's anthropic/ provider authenticates with x-api-key and vLLM accepts only Authorization: Bearer. Measured: Bearer → 200, x-api-key → 401, no header → 401. Two ways to give litellm a Bearer header for the local model, and they trade differently:

  • OpenAI-compatible form — declare the local model as openai/<name> with an api_base ending in /v1. litellm then sends Authorization: Bearer and it works immediately. Cost: the request is translated Anthropic → OpenAI → Anthropic, so Anthropic cache_control semantics are not carried end to end. vLLM's own automatic prefix caching still applies server-side.
  • Runtime header injection — keep anthropic/ and supply extra_headers with the Bearer value. The checked-in config stays secret-free only if the mode-600 runtime config is generated at service start, the way the env-file helper already works. Preserves Anthropic-native passthrough and cache_control; costs a secret-bearing runtime artifact and more moving parts.

Recommendation is the OpenAI-compatible form, on the grounds that opt-in mode exists to reach frontier models and the local slot there is a convenience — but the caching cost is real and measurable, so §4 measures it rather than assuming.

§4 — Implementation

§4a — Decide the local-model transport by measurement

Stand up the proxy with the local model declared both ways and measure whether a repeated large prompt reports cache reads. Report tokens and latency for each. This settles §3's open decision with a number instead of a preference.

§4b — Restore the routing config generator

Reinstate a routing-config generator carrying the local model on the transport §4a selects, plus the four or-* entries. Claude or-* models keep the anthropic/ + api_base form, which is where cache_control genuinely is preserved and was verified at 10,815 tokens. Secret-free: the key stays os.environ/OPENROUTER_API_KEY.

§4c — Restore the per-user service generator

Reinstate the systemd unit and env-helper generators. Install the unit only when the invoking user opts in, so a user who never passes the flag never acquires the unit — the property whose absence made the old design fail for other users. Refuse with an actionable message when litellm is absent, naming plain clive as the fallback.

§4d — Add the opt-in flag to the launcher generator

Add --openrouter / CLIVE_OPENROUTER to the generated launcher. Without it the script must be byte-for-byte what ships today. The existing regression tests assert exactly that invariance, so they are the guard: the flag must not perturb the default path.

The interface §4b landed, stated here so no node has to ask for it. imas_ambix/agent/litellm_service.py exports LITELLM_PORT = 18399, generate_litellm_env_helper(site) and generate_litellm_service(site). imas_ambix/agent/litellm_config.py exports generate_litellm_config(site, local_model). SiteConfig carries litellm_config_path (<base_dir>/agents/litellm_config.yaml), litellm_env_helper_path (same directory, imas-ambix-llm-env.sh) and litellm_service_path (~/.config/systemd/user/imas-ambix-llm.service). The unit is named exactly imas-ambix-llm.service and the proxy binds 127.0.0.1:18399.

Routing-config model ids are the served local model name plus exactly or-opus-4.8, or-sonnet-4.6, or-gpt-5.5 and or-glm-5.2. Picker mapping in opt-in mode: the haiku slot and ANTHROPIC_MODEL take the local served model, opus takes or-opus-4.8, sonnet takes or-sonnet-4.6, fable takes or-glm-5.2, and ANTHROPIC_CUSTOM_MODEL_OPTION takes or-gpt-5.5, each with its _NAME and _DESCRIPTION.

§4e — Extend the fence to cover both modes

The three local-only tests currently assert the generated script contains no proxy token at all, which the flag will break. Re-aim them: the default path must carry no proxy token and stay invariant to OPENROUTER_API_KEY, while the opt-in path may. A test must also assert the flag is the only way to reach the proxy — a readable key file alone must not.

§4f — Verify both modes against the live endpoint

Drive plain clive and clive --openrouter. The or-* slots need quota to answer; if the cap is still exhausted, record the 403 as the expected account-state result and verify the local slot answers through the proxy regardless — which is the property that distinguishes this design from the old one.

§ Decisions

How should the or-* models be reachable from clive?

An explicit flag, with the default invocation never touching the proxy. Auto-detection on a readable key file is what turned a personal proxy fault into an outage of the shared launcher, and it is rejected for that reason rather than because the models themselves were a problem — they were only ever visible to their key-holder.

In opt-in mode, how does the local model authenticate through the proxy?

Deferred to §4a, which measures whether prompt caching survives the OpenAI translation. Recommendation is the openai form unless the measurement shows a material caching loss.

§ Followups

Restore the or-* models behind the opt-in flag

Shape is locked; the transport decision is deferred to §4a's measurement rather than guessed. §4b-§4f restore the generators, add the flag, re-aim the fence to cover both modes, and verify against the live endpoint.
