JT-60SA Signal Figures From IDS

The signal figures that jt60sa-geometry-and-signal-figures §3 landed on 2026-10-06 were not drawn from IDS. scripts/figures_jt60sa_signals.py built imas-ink TimeSeries from bare arrays: PF coil currents and Ip came from the signal map's VirtualZarrView, the flux loops were raw PSRC and MDAC EDDB channels read through read_channel, and the caller supplied every label and unit string. The lead ruled on 2026-10-07 that imas-ink draws only from IDS inputs, or from signals carrying standard-name metadata.

The pulse mint has since written E101154 as IDS, at /work/projects/imas_gpu/jt60sa/ids/101154/ (run r-20261006T164055420259): pf_active carries the ten coil currents CS1–EF6 and magnetics carries Ip. This plan redraws from those IDS through imas-ink's extract_signal_traces, added by the imas-ink plan ids-signal-traces, and withdraws everything that has no IDS behind it.

§3 — E101031, the second pulse

On 2026-10-07 the lead chose E101031 as the second written pulse, in place of C060033. C060033 falls in no catalogue phase, drives the TF coil alone with the PF chain at the noise floor, and has no PSRC, so no ip. E101031 is an OP1 plasma pulse: ip holds 0.7 MA for 5.4 s without disruption, and the PF coils are driven. jt60sa-pulse-ids §6 wrote it on 2026-10-07 at 05:51 to /work/projects/imas_gpu/jt60sa/ids/101031/ (run r-20261007T034516340463): pf_active carries the ten coil currents CS1–EF6, and magnetics carries ip, peaking at 0.6984 MA.

This section draws E101031's coil currents and ip through extract_signal_traces, as §1 does for E101154, without copying §1's body. scripts/figures_jt60sa_signals.py fixes its pulse and figure name in module constants (SHOT, FIGURE, PULSE_FILE), and its _main() takes no pulse. So this section moves the open → extract_signal_traces → time_trace_figure_mpl → render_to_bytes path into one function that takes the run file's root, the pulse, the run number and the series to draw as (IDS name, path) pairs, and returns the figure. It writes nothing; the script's entry point renders each returned figure to SVG and writes it. E101154 and E101031 become calls to it with ("pf_active", "coil/current") and ("magnetics", "ip"), and §2's flux loops and probes become further calls rather than a second path. The constants fixed to E101154 are retired, and E101154's figure is unchanged.

The function reaches a pulse through the owners jt60sa-facility-mint §8 introduces, so it runs after §8 merges and never names a path. The file name comes from pulse_writer.pulse_path, which §8 migrates _read_pulse_ids onto. The root is resolved once, in the entry point. It takes imas_alambic/settings.py resolve_settings (IMAS_ALAMBIC_IDS_ROOT) when that yields a root. Otherwise it takes ambix's own development store root, imas_ambix/data/paths.py JT60SA_ROOT / "ids", which is where jtfm-write-dev-pulses wrote both files. Nothing in this repository sets IMAS_ALAMBIC_IDS_ROOT, so resolve_settings alone yields no root here. Its flux loops and probes follow §2's terms. Both owners landed with §8 (merge 106c1104, 2026-10-07): imas_alambic/settings.py resolve_settings and pulse_writer.pulse_path.
