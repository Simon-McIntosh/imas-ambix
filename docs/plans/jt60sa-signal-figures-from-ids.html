JT-60SA Signal Figures From IDS

The signal figures that jt60sa-geometry-and-signal-figures §3 landed on 2026-10-06 were not drawn from IDS. scripts/figures_jt60sa_signals.py built imas-ink TimeSeries from bare arrays: PF coil currents and Ip came from the signal map's VirtualZarrView, the flux loops were raw PSRC and MDAC EDDB channels read through read_channel, and the caller supplied every label and unit string. The lead ruled on 2026-10-07 that imas-ink draws only from IDS inputs, or from signals carrying standard-name metadata.

The pulse mint has since written E101154 as IDS, at /work/projects/imas_gpu/jt60sa/ids/101154/ (run r-20261006T164055420259): pf_active carries the ten coil currents CS1–EF6 and magnetics carries Ip. This plan redraws from those IDS through imas-ink's extract_signal_traces, added by the imas-ink plan ids-signal-traces, and withdraws everything that has no IDS behind it.

§1 — Redraw E101154's coil currents and plasma current from its IDS

This section waits on imas-ink's ids-signal-traces §1, which adds extract_signal_traces. That function does not exist until that section lands, so the dependency is declared on this section and on the plan, and no builder is released before it merges to imas-ink's main branch. The ambix environment serves imas-ink as an editable install, so the merged function is live here at once.

scripts/figures_jt60sa_signals.py is rewritten as a thin imas-ink caller:

  • One function, _read_pulse_ids(pulse_dir, ids_name), opens one IDS with imas.DBEntry and get(..., autoconvert=False), from JT60SA_ROOT / "ids" / "101154", where JT60SA_ROOT comes from imas_ambix.data.paths. The pulse-mint coordinator has announced a move to one netCDF per run, so the file layout is known in this one place and that move is a one-function change.
  • It calls extract_signal_traces(pf_active, "coil/current") and extract_signal_traces(magnetics, "ip"), and draws the series, one panel each, in one figure through time_trace_figure_mpl.
  • It writes that figure through render_to_bytes(format="svg") to docs/figures/jt60sa-signals/jt60sa-E101154-pf-coil-currents.svg, replacing the file of that name.

The script constructs no TimeSeries, passes no label or unit string, and imports nothing from virtual_zarr, signal_map, eddb or zarr. Every name and unit on the figure comes from the IDS through imas-ink.

The same node deletes the two figures with no IDS behind them:

  • jt60sa-E101154-flux-loops.svg, the raw PSRC-against-MDAC comparison. The lead withdrew it on 2026-10-07.
  • jt60sa-C060033-pf-coil-currents.svg, for which no IDS exists.

Two records embed those files today and would show broken images once they are deleted. Both belong to the shipped plan jt60sa-geometry-and-signal-figures, and the coordinator repairs them at this section's landing, because a worker never edits another plan:

  • docs/evidence/fragments/jt60sa-geometry-and-signal-figures/jtfig-signal-figures.html embeds the flux-loop and C060033 figures.
  • That plan's §3 landed summary embeds all three figures, with captions from the raw-array era.

The repair removes the two withdrawn images, re-captions the surviving figure as drawn from IDS, and points to this plan. The worker's own evidence goes in a new fragment for this plan, at docs/evidence/fragments/jt60sa-signal-figures-from-ids/.

The IDS opener stays local to the script. The idiom it uses, imas.DBEntry(path, "r") then get(name, autoconvert=False), recurs in scripts/figures_jt60sa_geometry.py (_read_ids), imas_ambix/gs/artifact_geometry.py and imas_ambix/bench/store_arms.py. Each of those reads a different on-disk layout, and none owns the pulse directory, so there is no shared owner to extend.

Done-when: the script opens only the two IDS files and writes exactly one SVG, with no PNG twin. It prints each series' y-label and unit, which must be the ten coil names in A and ip in A. grep -cE 'VirtualZarrView|read_channel|signal_map|TimeSeries\(' scripts/figures_jt60sa_signals.py returns 0. docs/figures/jt60sa-signals/ holds exactly one file. The SVG is rendered on a compute node because it reads GPFS; open it and confirm it has no legend and one time label. The evidence fragment embeds it with a project-absolute src and a caption naming the shot, the IDS paths and the units. uv run --no-sync ruff check imas_ambix tests scripts/figures_jt60sa_signals.py passes.

§2 — Flux loops and probes, once the rewritten E101154 carries them

The on-disk E101154 predates the magnetics bindings: its 27 flux loops and 17 poloidal-field probes are empty. The magnetics map now binds them, and its coordinator, imas-ambix-5b, is moving 26 loop rules to type-6 differential entries relative to loop 7. The pulse-mint coordinator, imas-ambix-0d, will rewrite E101154 after that, giving each loop and probe its own time vector (homogeneous time 0).

Both coordinators have agreed to signal this session. When they do, this section draws extract_signal_traces(magnetics, "flux_loop/flux") and the probe field the same way §1 draws the coil currents. It updates _read_pulse_ids to the per-run file layout if the rewrite uses it. Deferred until the rewrite exists.

§3 — C060033, once it has IDS

C060033 cannot be minted today, for two reasons:

  • No machine map covers the C-series commissioning shots: map_for_shot resolves 60033 to zero maps.
  • Its cache holds only MDAC and MMSYS. With no PSRC, magnetics/ip has no source.

The machine-map census also found that the C-series shots drive the TF coil alone, so PF panels for C060033 would show only noise floor. The pulse-mint coordinator has raised both blockers with the lead and will signal if C060033 is written. This section then decides from the written IDS whether any of its signals is worth a figure. Deferred until then.
