§1 — Overview: the per-solve GPU port is a dead end; batch the corpus

The problem, and the honest negative that motivates it. The reanalysis engine produces firewall-clean equilibrium labels; the label factory must run the free-boundary Grad–Shafranov solve over the ~12.6k-shot MAST corpus (~600k slices) to feed the learned cross-machine operator — ~37 core-days at today’s CPU rate. The obvious move — port the solver to the 8×H200 node — does not work per-solve: the greens-filament-solver §2 spike measured the grid-free matvec at 1.67× SLOWER than the cached grid solve on a single CPU slice, and the lead’s own prior jax GPU port of the nova scheme showed no material speedup. This plan is the re-architecture that does work.

Why a per-solve GPU solver fails (three independent reviews agree). A single equilibrium is close to the canonical anti-GPU workload:

  • Batch-1 is a memory-bound GEMV. The plasma→grid Green’s matvec (6305×1500, ~38 MB) has arithmetic intensity ~0.5 FLOP/byte — ~600× below the H200 tensor-core ridge (~295 FLOP/byte). The tensor cores that are the H200 sit ~99.5% idle; the 38 MB matrix stays hot in CPU L3 across all sweeps, so the CPU wins.
  • The fixed point is strictly sequential — a chain of 40–120 dependent sub-20-MFLOP kernels; latency-bound, not throughput-bound.
  • The topology read forces a per-iteration HOST round-trip (device→host ψ → NumPy critical-points + ndimage.label → host→device jφ) — the dominant killer, idling the GPU every sweep.
  • The anti-pattern is nested twice: the time-integration loop (resistive diffusion + passive circuits) is ALSO a Python loop with per-step host scalar reads, so even a perfectly batched per-slice solve re-serialises in time.

The fix. The parallelism is across solves, not within one. Two payoff axes, mapped to the two ways the engine is used:

Axis A — offline corpus (this is where shot-batching lives). Batch over shots; the GEMV becomes a GEMM; the whole rollout is one jitted, sync-free graph. Pure shot-batching is strictly optimal offline — the batch is already saturated, so the single-shot temporal split below would only add redundant FLOPs.

Axis B — single shot (live / between-shot reconstruction). With no shot-batch to fill, use parallel-in-time (windowed waveform relaxation): solve all ~50–200 slices of the shot simultaneously as independent per-slice GS equilibria (coupling lagged → decoupled → batched over slices), thread the diffusion + passive coupling sequentially, iterate the outer loop. The temporal coupling is a weak soft prior, so the outer iteration contracts in ~2–4 sweeps; a causal sliding-window, 1–2-outer-iteration variant is a viable live reconstruction.

The prerequisite both axes share. The topology read MUST move on-device as a fixed-shape, branchless op (nova’s 7-point stencil null-finder + a smooth/tracked core mask — no connected-components). Without it the per-iteration host round-trip re-serialises the batch and Amdahl caps everything at ~3×. This is a port of primitives nova already ships, not new research.

Honest ceiling & firewall. The matmuls become effectively free; the residual bottleneck is the sequential per-step thin-ops (topology + tridiagonal + circuit) × rollout depth, amortised across the shot batch. Converged estimate: 1–2 orders of magnitude, corpus label factory ~37 core-days → well under an hour (plausibly minutes) on 8×H200. The equilibria must stay byte-comparable to the CPU grid-free solver (validated, incl. the Ejima/flux-budget ledger); GS force balance and the firewall (physics + measured channels only, no EFIT) are unchanged — this is a compute re-architecture, not a physics change.

§2 — Framework spike + batched GEMM crossover + on-device topology (go/no-go)

The de-risking rung. (1) Framework decision (see decisions): the temporal stack (current_diffusion.py, temporal_operator.py) is already torch-fp64, so a unified torch pipeline avoids rewriting it; jax wins for whole-rollout fusion + clean implicit-diff. Prototype the inner GS step in both and decide. (2) Batched GEMM microbench on one H200: confirm the GEMV→GEMM crossover and the compute-bound regime past B ≈ 600, and measure achievable slices/s. (3) On-device topology port: reimplement the axis/X-point + core mask as nova’s fixed-shape stencil null-finder + smooth mask, and validate it against the exact CPU read on axis / boundary_psi / LCFS to tolerance. Gate G-A: a batched (B ≥ 512) inner GS solve on real held-out slices reproduces the CPU grid-free axis/LCFS/profile within the greens-filament-solver §2 tolerances AND shows the compute-bound GEMM crossover; the on-device read matches the exact read. Honest negative if the on-device read cannot hold tolerance.

§3 — Offline batched causal rollout (the corpus labeler)

Assemble the full vmap(shots) × scan(time) × fixed-point graph: the inner GS solve (§2) warm-started along time, the batched tridiagonal resistive diffusion (Thomas, fp64), and the exact modal-ZOH passive circuits in the scan carry. Fixed iteration budget + per-column convergence masking (no adaptive per-slice early-exit); shot-length bucketing; precision tiering (tf32/bf16 GEMM, fp32 topology, fp64 recurrent state). Gate G-B: the batched rollout reproduces the CPU sequential labeler’s equilibria (axis/LCFS/profile + the held-out-MSE pitch readout) on a held-out shot set to tolerance, with 0 fabricated readouts (label-honesty preserved).

§4 — Single-shot / parallel-in-time arm (live & between-shot)

Windowed waveform relaxation for the single-shot path: Gauss–Seidel across short causal windows (T_win/τ_R ≲ 0.3), Jacobi batched-over-slices within a window, exact causal eddy-state carry between windows; disc+centroid position prior (or a cheap coarse sequential pre-march) as basin insurance on the cold decoupled pass. A causal sliding-window, 1–2-outer-iteration variant for live reconstruction. Gate G-C: the outer iteration converges to the sequential march’s trajectory (axis/LCFS/flux-budget) to tolerance in a bounded outer count, and delivers a measured single-shot wall-clock speedup (target ~3–5×) vs the sequential march; the truncated live variant is validated against the converged one before any real-time use.

§5 — Multi-GPU sharding + corpus throughput benchmark

Data-parallel over the shot-batch across the 8 H200 cards (replicate the ~2 campaign Green’s matrices per device, ~76 MB each; zero cross-device comms during the rollout; per-device shard write). Bucket-aware load balancing. Stream inputs/outputs (600k shards) so I/O does not become the new wall. Runs on the betelgeuse H200 reservation (gpu_0003_grpA). Gate G-D: the full-corpus label factory clears the wall-clock target (well under an hour) with equilibria byte-comparable to the CPU grid-free solver.

§6 — (Stretch) differentiable rollout → gradient-based calibration

Once the topology read is smooth, the whole rollout is differentiable via an implicit-function / deep-equilibrium adjoint at each GS fixed point (no unrolling) + per-slice checkpointing across the time scan. The labeler then becomes its own gradient-based calibrator: fit η(ψ_N), the passive resistances, and the priors against EFIT-free held-out magnetics, replacing the current gradient-free search. Deferred/stretch — folds into the learned-operator endgame; the learned operator is also the natural coarse propagator for a future parareal variant of §4.

§ Decisions

Which framework for the batched on-device rollout?

OPEN — the §2 spike decides. The GEMM and batched tridiagonal are a tie; the decider is (a) how much of the already-torch-fp64 temporal stack we are willing to rewrite in jax, and (b) whether §6 differentiability (jax implicit-diff is cleaner) is pursued. Prototype the inner step in both.

What is the parallel axis — offline vs single-shot?

Locked from the three-review + parallel-in-time-analysis consensus (2026-07-20). Offline, pure shot-batching saturates the GPU and the temporal split only adds ~5-7x redundant FLOPs (PinT loses). Single-shot, there is no shot-batch to fill, so windowed WR over slices is the analogue (~3-5x, latency win). Batching raw slices while ignoring the diffusion + passive coupling is physically wrong (drops the causal profile evolution the engine earns).

Where does the axis/X-point + core-mask topology read run?

Locked (2026-07-20): all three reviews agree the per-iteration host round-trip is the dominant reason the per-solve jax port flatlined; without an on-device read Amdahl caps the whole thing at ~3x. nova already ships the branchless primitives. A final exact-read CPU polish for the EMITTED label is retained where sub-mm axis is a hard requirement (validated against the on-device read + the Ejima/flux-budget ledger).
