Reading note (educational dual-purpose). This is a research document, not a plan: it reports what we found when we first ran the world-model prototype end-to-end. It accompanies the world-model-prototype plan and the camera-dynamics-wm-v0 work. Acronyms are expanded on first use; the techniques and every external framework are named in §8 (glossary). The findings are reported warts-and-all — the headline result is a measured loss to a trivial baseline, and that is the honest, useful thing to know before scaling up.

§1 — What this document demonstrates

We trained the first world model on the multi-modal token substrate and evaluated it predict-vs-reality on shots it had never seen. A world model here is a learned model that, given a MAST (Mega-Amp Spherical Tokamak) shot's pulse schedule (the pre-programmed actuator waveforms — demanded plasma current, density, heating, coil currents) plus a short initial-condition context (the first 16 grid-steps of the shot), tries to predict how every tokenised diagnostic evolves for the rest of the shot. It does this autoregressively: it predicts the next step, feeds that prediction back in, and repeats — generating the whole rollout itself.

Three questions motivated this write-up, all asked directly by the lead:

  • The training was very short — is this demo territory, or do models like this really train in minutes? (§3)
  • Are we properly using all our data and signals? (§4)
  • Do we now have a generative model that can "dream" new MAST shots? (§6)

The short answers: demo territory (the model is small and the corpus subset modest); all signal types but only ~a quarter of the shots and a coarse camera view; and yes architecturally it is a generative "dreamer", but the dreams are not yet faithful — on average they lose to persistence. The rest of this document shows the evidence.

§2 — The model and how it was trained

The model is a decoder-only Transformer (the same family as a GPT language model) that consumes interleaved token streams from every modality on one common time grid, conditioned on the plan. It was built from the multimodal-tokenisation-substrate: continuous signals and camera images are converted to integer tokens drawn from learned codebooks, so a single sequence model can read them all.

Training run (the converged checkpoint). A single run on one NVIDIA H200 GPU:

  • Parameters: 1,034,027,033 (≈1.034 billion) — but see §3 for where they actually live.
  • Backbone: width d_model=384, 8 Transformer layers, 8 attention heads.
  • Streams (all 14 types): the plan (pulse_schedule); five Level-2 measured light-path groups (summary, pf_active, interferometer, gas_injection, soft_x_rays); three high-frequency signal streams (xma, xim, xsx); and all five cameras (rbb, rba, rco, rgb, rgc).
  • Optimiser: AdamW, learning rate 1e-3, batch 6, 40,000 steps over 64-step windows (≈240,000 windows seen).
  • Loss: next-token negative log-likelihood, 6.3 → 1.69, plateaued (1.75 → 1.69 over the final 15,500 steps — i.e. converged for this capacity).
  • Wall-clock: ≈75 minutes.

§3 — "Why so fast?" Where the billion parameters actually live

The 1.034-billion-parameter headline is misleading in an important and honest way. 97.5% of the parameters are pure lookup tables — the input embeddings and output heads for the five cameras, each of which has a 218 = 262,144-entry codebook. A lookup table contributes a parameter row per vocabulary entry, but for any given token only one row is read (and updated) per occurrence; it does not add per-step compute the way a Transformer layer does, and most rows receive only sparse gradient updates. The part of the model that actually learns dynamics — the Transformer backbone — is just ≈14.2 M parameters (a "tiny" model by modern standards; GPT-2 small is 124 M).

So is it demo territory? Yes. A ≈14 M-parameter sequence model, trained on a modest window budget, converges in ~75 minutes exactly as expected. This is not evidence that large, physically faithful world models train in minutes — it is evidence that a small model on modest data trains fast, which has always been true. The short time is a property of the prototype's size, not a breakthrough.

§4 — "Are we using all the data and signals?"

Signal types: yes — all 14 stream types are wired in (the plan, five Level-2 measured groups, three high-frequency streams, and all five cameras). Data volume: no — we used a subset, and the cameras are spatially sub-sampled:

  • Shots: 3,996 trained of 15,361 available (≈26%).
  • Camera resolution: each frame is encoded as 256 tokens (a 16×16 grid) by the Open-MAGVIT2 image tokeniser, but the world model consumes only a 4×4 = 16-token subsample (camera_grid_stride=4) — a coarse spatial summary, 1/16 of the tokens.
  • Cameras are sparse per shot: rbb is the most common; the other four are missing on many shots, so the camera streams in particular are under-fed.

There is therefore large headroom on data: more shots, full-resolution camera tokens, and a bigger backbone to use them (§7).

§5 — Predict-vs-reality: the held-out evaluation

Method. We took 8 shots at discovery indices 4000–4007 — beyond the 4000-shot training cap, so never trained on (verified). For each, the model was given only the plan and the first 16 grid-steps, then rolled forward 48 steps autoregressively. We score the predicted tokens against the truth with a skill score relative to persistence:

skill = 1 − (model token-mismatch rate) / (persistence token-mismatch rate)

where persistence is the trivial baseline "repeat the last observed token forever". Skill > 0 means the model beats persistence; < 0 means it loses; 0 means a tie.

Honest reading. The model loses to persistence overall. Two things are simultaneously true, and both matter:

  • The result is real: a small model on 26% of the corpus does not yet beat the trivial baseline. The worst losses are on gas_injection and summary — streams where persistence is already strong because they change slowly.
  • The metric is unforgiving: token-exact mismatch vs persistence is a harsh lens for slowly-varying signals — a prediction one codebook bin away from truth counts as fully wrong even if the decoded physical value is almost right, and persistence is near-unbeatable when the signal barely moves over 48 steps. This matches the project's earlier S7/S9 finding that persistence dominates short-horizon forecasts of quasi-stationary tokamak signals. Decoded-value metrics and longer horizons (where persistence finally degrades) are the fairer next lens (§7) — but they will not rescue this checkpoint; they will measure the next, larger one.

§6 — "Can it dream new MAST shots?" — the architecture pivot

The first design could not, and we found out why. The original model fused each camera frame by summing all 256 of its tokens into one vector before the transformer (a "bag-of-channels"), so the network attended over time only, never space. You cannot rebuild an image from an orderless sum of its pieces, so the decoded camera predictions were incoherent mush even when the model was overfit — an architectural flaw, not under-training. (A second bug fed token-0 padding frames, from the parts of a shot where the camera is off, as if they were data.) That run was retired.

The pivot: a spatiotemporal transformer. The camera tokens are now modelled as what they are — a video. A decoder-only transformer runs over the sequence of frames × 256 raster tokens; every token keeps its own identity (a value embedding + a factorized row/column spatial position + a temporal frame position), and attention is factorized into space and time: full spatial attention within a frame (≈256²) and causal temporal attention across frames at each position (≈T²), so cost is ≈ T·256² + 256·T² rather than the intractable (256·T)². The pulse-schedule plan is prepended as conditioning frames; a chunked cross-entropy head handles the 218-entry vocabulary without ever materialising the full logits. This is the modern, transformer-native pairing for a discrete-token video substrate — no CNN, no spatial summing. The backbone is now a real ≈269 M-parameter transformer (not lookup tables).

Foundation gate — PRE-TRAIN scoping/overfit data (NOT held-out). Before committing GPU hours we ran the decisive test: a correct spatial architecture must reproduce a handful of memorised frames near-exactly. We overfit 2 shots; loss fell 12.56 → 0.0045, and both the teacher-forced reconstruction and the autoregressive dream hit 0.0000 token mismatch (pixel exact) with a dream change-fraction of 0.99 (genuinely evolving, not frozen). The decoded video below is coherent — sharp central column, up/down divertor lobes, bright X-points, field-line arcs — exactly what the summed model could never produce.

Read these honestly: the GIFs in Figure 6 are an overfit on memorised shots — they prove the architecture is sound (spatial structure survives; the predict→decode→dream pipeline works end-to-end), not that the model generalises. Generalisation — coherence on unseen shots — is the held-out result reported next (§6.1), and it is the real deliverable.

§6.1 — The held-out result: it dreams unseen MAST shots

The pivot works. We trained the spatiotemporal transformer on a corpus of MAST rbb camera shots (4×H200, distributed data-parallel) and then ran the decisive test: predict and dream shots the model never saw in training — held-out shots 18502 and 18503. The figures below are that held-out decode. On both unseen shots, both the teacher-forced reconstruction and the autoregressive dream are clearly coherent: the correct plasma boundary, the dark central column, the bright divertor strike-point, all structurally on-track across the full 24-frame window. Crucially, the dream stays coherent rolling forward on its own predictions — it does not collapse or drift to noise as it consumes its own output. This is night-and-day versus the retired bag-of-channels model, which produced incoherent mush even when overfit. The honest blemish: occasional single-frame hallucination (e.g. shot 18502, frame 7, momentarily fans out) before the rollout recovers.

Why the step-3000 checkpoint, and the metric-vs-vision caveat. The training curve tells an honest two-part story, and the held-out evaluation earned its keep by catching both parts:

  • Overfitting (caught early). Held-out token-mismatch fell from 0.991 → 0.954, bottomed at 0.952 around step 3000, then rose monotonically — the classic signature of a 537 M-parameter model beginning to memorise a finite corpus. Step-3000 is the held-out-best checkpoint; everything after it generalises worse.
  • Late divergence (caught too). With a flat learning rate (no warmup/decay) the run later destabilised: training loss blew up from ≈0.1 to ≈12 at step 9600, and by the final step the held-out token-mismatch had degraded to 1.0000 — the last checkpoint is garbage. The earlier held-out decode the doc briefly carried (the step-12000 final checkpoint, 0.9976 mismatch) was from this diverged state; it has been superseded by the step-3000 figures above.

The caveat that reconciles the harsh number with the coherent video: a held-out token-mismatch of 0.95 sounds catastrophic, but it is computed over a 218-entry (262 144) vocabulary. Over a vocabulary that large, near-saturated token-mismatch coexists with strong visual coherence — the model predicts a token that decodes to a near-identical patch (a neighbour in the Open-MAGVIT2 codebook) rather than the exact training token. The harsh token metric undersold the result: the model learned generalisable plasma structure and dynamics, not memorisation. The token-level number is the right tool for detecting overfit and divergence (which it did, twice), but it is a poor proxy for visual fidelity at this vocabulary size — the decoded video is the honest readout of what the model actually knows.

Tonight's deliverable stands on its own: a coherent, plan-conditioned, autoregressive dream of held-out MAST camera shots at the step-3000 checkpoint. An overnight run (linear warmup → cosine decay with gradient clipping, added regularisation, ~8–10 k shots, and held-out-best checkpointing) is now training to remove the overfit and the late divergence and should sharpen this further — but it is an improvement on a result that already works, not a prerequisite for it.

§7 — Verdict and the path from demo to fidelity

Verdict. This is a genuine, end-to-end, leakage-free prototype: the plumbing works (plan-conditioned multi-modal tokens in, autoregressive multi-stream rollout out, scored on held-out shots with decoded ground-truth). It is a generative "dreamer" by construction. It is not yet a useful predictor — it loses to persistence. That is the right place to be after a first demo, and it tells us precisely what to change.

What to change, in rough priority order:

  1. Grow the actual sequence model. 14 M Transformer parameters is tiny. The headroom is in the backbone (depth/width), not in more codebook tables.
  2. Use the full corpus. 3,996 → 15,361 shots; and make the cameras less sparse.
  3. Full camera resolution. 16 → 256 tokens/frame (or a smarter spatial scheme) so the camera carries real structure.
  4. Train longer with a schedule. The loss plateaued for this capacity; a larger model needs a proper LR schedule and many more steps.
  5. Fairer evaluation. Add decoded-value (physical-unit) metrics, longer horizons where persistence degrades, and value-targeted scoring against the eval-only Level-2 reconstructed-equilibrium targets — not only token-exact match.
  6. Fix degenerate tokenisers. xma's size-1 codebook must be repaired so the stream carries information.
  7. Reconsider discrete heads for slow signals. Continuous/latent heads may suit slowly-varying streams better than discrete-token cross-entropy.

§8 — Glossary & frameworks

Terms.

  • MAST — Mega-Amp Spherical Tokamak (the UK fusion device this data comes from).
  • World model — a learned model of how observations evolve in response to actions.
  • Pulse schedule / plan — the pre-programmed actuator waveforms set before a shot (the actions).
  • Token / codebook — a signal or image is converted into a sequence of integer codes drawn from a learned dictionary (the codebook), so one sequence model can read every modality.
  • Decoder-only Transformer — the GPT-style architecture: predicts the next token from all previous tokens via masked self-attention.
  • Autoregressive (AR) rollout — generating a sequence by repeatedly predicting the next token and feeding it back in. This is what "dreaming a shot" means here.
  • NLL — negative log-likelihood, the next-token training loss.
  • Persistence baseline — predict "the last observed value, unchanged". A strong baseline for slowly-varying signals.
  • Skill score — 1 − model_error/baseline_error; positive beats the baseline.
  • Held-out — shots excluded from training, used only for evaluation (here, discovery indices ≥ 4000).
  • LFQ / VQ / FSQ — Lookup-Free / Vector / Finite-Scalar Quantisation: families of methods for turning continuous data into discrete tokens (the camera codebooks are LFQ at 218 entries).
  • Level-2 (L2) — the leakage-controlled measured + authorised-planned input light-path; reconstructed-equilibrium targets live in a physically separate eval-only store.

Frameworks used.

  • PyTorch (2.11, CUDA 13.0) — the model, training loop, and rollout.
  • Open-MAGVIT2 — the frozen image tokeniser/decoder (VQModel, LFQ) that turns camera frames into 218-vocabulary tokens and back to 256×256 images.
  • Zarr — chunked array storage for the token corpus.
  • NumPy / Matplotlib — the artifact bundle and the figures in this document.
  • SLURM — the H200 GPU compute scheduler (training and decode ran on one card).
