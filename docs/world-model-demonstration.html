Reading note (educational dual-purpose). This is a research document, not a plan: it reports what we found when we first ran the world-model prototype end-to-end. It accompanies the world-model-prototype plan and the camera-dynamics-wm-v0 work. Acronyms are expanded on first use; the techniques and every external framework are named in §8 (glossary). The findings are reported warts-and-all — the headline result is a measured loss to a trivial baseline, and that is the honest, useful thing to know before scaling up.

§0 — Reference guide: the architecture & training setup

This section is a self-contained primer on the machine-learning (ML) machinery used here, so the rest of the document reads without prior background. It describes the current spatiotemporal camera model (the design that replaced the earlier summed model — see §6), defines every term, and explains the learning-rate schedule with a diagram.

§0.1 — What kind of model this is

It is a decoder-only Transformer — the same neural-network family as a GPT language model, but instead of words it consumes tokens of a tokamak camera video. The pipeline is:

  1. Tokeniser (frozen, not trained here): the Open-MAGVIT2 VQ (Vector-Quantised) image model converts each 256×256 camera frame into a 16×16 grid = 256 integer tokens, each drawn from a fixed codebook (vocabulary) of 218 = 262,144 entries. A token is just an integer naming one entry in that codebook. Decoding reverses this: tokens → image.
  2. Transformer (what we train): reads the sequence of tokens (frames laid out in time, each frame a 16×16 grid) plus the pulse-schedule "plan" tokens, and predicts the next frame's tokens.
  3. Autoregressive rollout ("dreaming"): feed the model its own predicted tokens back in, step after step, to generate a whole video forward from a short context + the plan.

§0.2 — Key terms, defined

  • Token / codebook / vocabulary: an integer code for one patch of image; the codebook is the fixed dictionary of 218 possible codes the frozen tokeniser uses.
  • Embedding: a learned lookup that turns each integer token into a d_model-dimensional vector the network can compute with. We also add a spatial position embedding (which row/column in the 16×16 grid) and a temporal position embedding (which frame) so the model knows where and when each token sits. (The earlier model's fatal flaw, §6, was summing a frame's tokens and destroying this spatial information.)
  • Self-attention & "heads": the mechanism by which each token looks at other tokens and decides which to draw information from. A head is one independent attention pattern; using 16 heads lets the model attend to 16 different relationships at once (e.g. one head tracks the plasma boundary across frames, another the central column). With d_model = 1024 and 16 heads, each head operates in a 64-dimensional subspace.
  • Causal (masked) attention: in time, a token may only attend to earlier frames, never future ones — this is what makes the model a forward predictor rather than a cheat that peeks ahead.
  • Factorised space-time attention: doing full attention over all frames × 256 tokens at once is quadratically huge. We factorise it: full spatial attention within a frame (256 tokens), plus temporal attention across frames at each fixed grid position. Cost ≈ T·256² + 256·T² instead of (256·T)² — the difference between tractable and not.
  • Layer / block / depth: one "layer" is a self-attention + MLP unit; stacking 16 layers (the depth) lets the model build progressively more abstract structure.
  • d_model / d_ff: d_model = 1024 is the width of the vector carried between layers; d_ff = 4096 is the (wider) hidden width inside each block's feed-forward MLP (conventionally ~4×d_model).
  • Feed-forward MLP, residual, LayerNorm: the MLP is a small 2-layer network applied to each token; residual connections add a block's input to its output (helps gradients flow); LayerNorm rescales activations for stable training. Standard Transformer plumbing.
  • Parameters: the ~537 million learned numbers (weights) in this model — almost all in the attention/MLP blocks and the token embedding/head, this time a real sequence model (contrast the earlier design in §3, which was 97% lookup table).
  • DDP (Distributed Data-Parallel): the same model is replicated on all 4 H200 GPUs; each GPU processes a different slice of the batch and they average their gradients every step — ~4× throughput.

§0.3 — How it learns: loss, learning rate, and the cosine schedule

Two distinct things, often confused:

  • Loss = what we minimise. Here it is cross-entropy: a measure of how wrong the model's predicted token-probabilities are versus the true next-frame tokens. Lower is better; a perfect predictor scores 0, pure chance over 218 tokens scores ln(262144) ≈ 12.5. (The loss is cross-entropy — not cosine; "cosine" refers only to the learning-rate schedule below.)
  • Learning rate (LR) = how big a step the optimiser takes down the loss surface each update. The optimiser is AdamW (adaptive step sizes per weight + decoupled weight decay). Too high → unstable / diverges; too low → painfully slow. Our peak LR = 3×10⁻⁴.

A constant LR is what destroyed the previous run (§6): it trained to near-zero loss, then at step ~9,600 a single bad update blew the loss from ~0.1 back to ~12 with nothing to damp it. The fix is a learning-rate schedule — vary the LR over training:

  • Warmup (first 800 steps): ramp the LR linearly from ≈0 up to the peak. Early gradients are large and erratic; starting tiny avoids an early destabilising jump.
  • Cosine decay (remaining ~35,200 steps): glide the LR back down following the shape of a cosine curve — from the peak (3×10⁻⁴) to a small floor (1% of peak = 3×10⁻⁶). The cosine shape decays slowly at first, fastest in the middle, then flattens near the end, so the model settles into a minimum rather than bouncing out of it. This is the anti-divergence fix. It is a schedule on the learning rate, not on the loss.
  • Gradient clipping (max-norm 1.0): a hard cap on how large any single update can be — a second seatbelt against the kind of spike that blew up the previous run.

§1 — What this document demonstrates (status & verdict up front)

Bottom line (2026-06-19). We built an autoregressive camera-video "world model" that, given a shot's pulse schedule + a short context window + (in the final variant) the measured diagnostic signals, dreams the rbb camera forward. Across three training generations the honest held-out verdict is: the model essentially learned persistence (predict ≈ the last frame). The best variant — conditioned on measured physics signals — is the first to beat frozen-frame persistence, but only on 2 of 4 held-out shots, and only the dim/low-motion ones (§6.2). It does not yet forecast the bright, dynamic plasma that matters. We keep the generative camera model as the goal — but make it capable and correct by fixing its core flaw: it currently dreams open-loop (free-running from a fixed plan, never re-reading a measurement), so error compounds to persistence. The fix is to wrap the same camera encoder/decoder in a corrected latent state-space loop — a Kalman/EnKF filter that ingests broadband signals (video + diagnostics) every step — and to upgrade the frame generator to diffusion. The camera dream stays the product; closed-loop correction is what makes it work. Reasoned out in §9.

This document is the honest record of the camera-video world-model line: what the current model is (§2), how it trains and how it dreams (§2.1–§2.2), the three-generation result (§3, §6), and where we go next and why the current setup cannot be trained into a forecaster (§9). A world model here is a learned model that predicts how a MAST (Mega-Amp Spherical Tokamak) shot's tokenised camera evolves in response to its actions (the pulse schedule) — generated autoregressively (predict the next frame, feed it back, repeat).

§2 — The model and how it was trained

The model is a decoder-only Transformer (the same family as a GPT language model) that consumes interleaved token streams from every modality on one common time grid, conditioned on the plan. It was built from the multimodal-tokenisation-substrate: continuous signals and camera images are converted to integer tokens drawn from learned codebooks, so a single sequence model can read them all.

Training run (the converged checkpoint). A single run on one NVIDIA H200 GPU:

  • Parameters: 1,034,027,033 (≈1.034 billion) — but see §3 for where they actually live.
  • Backbone: width d_model=384, 8 Transformer layers, 8 attention heads.
  • Streams (all 14 types): the plan (pulse_schedule); five Level-2 measured light-path groups (summary, pf_active, interferometer, gas_injection, soft_x_rays); three high-frequency signal streams (xma, xim, xsx); and all five cameras (rbb, rba, rco, rgb, rgc).
  • Optimiser: AdamW, learning rate 1e-3, batch 6, 40,000 steps over 64-step windows (≈240,000 windows seen).
  • Loss: next-token negative log-likelihood, 6.3 → 1.69, plateaued (1.75 → 1.69 over the final 15,500 steps — i.e. converged for this capacity).
  • Wall-clock: ≈75 minutes.

§3 — Generation 1 (retired): the multi-modal token model — and why it was superseded

The first attempt was a single decoder-only Transformer over all 14 tokenised streams (plan + 5 Level-2 groups + 3 high-frequency signals + all 5 cameras) at once. Two structural problems retired it, and its figures are intentionally removed from this document as stale (they described this dead design, not the current model):

  • It was 97.5% lookup table. Of its 1.034 B parameters, ~1.008 B were the five cameras' 218-entry embedding/head tables; the actual sequence-modelling Transformer was only ~14 M. So "1 B-param model trained in 75 min" was misleading — the real model was tiny.
  • It bagged the camera spatially. The architecture summed a frame's 256 tokens into one vector before the Transformer — destroying spatial structure, so decoded camera predictions were incoherent mush even when overfit (the bug §6 fixes with a spatiotemporal model).
  • Honest held-out result: overall token-skill vs persistence −0.043 — it lost to persistence on the held-out set (worst: gas_injection −0.39, summary −0.22). The lesson that carried forward: token-exact mismatch over a 218 vocab saturates near 1.0 and is uninformative, so the decoded-pixel error vs persistence is the honest verdict (used throughout §6). The removed Figures 2–5 (param breakdown, coverage, per-modality skill, the PF-current / signal traces) all belonged to this retired generation.

Generations 2–3 (the spatiotemporal camera model, §6) replaced this with a real Transformer (no lookup-table inflation) and per-token spatial+temporal identity. The current-model description is §2 / §0; the verdict is §6.2; the strategic pivot is §9.

§6 — "Can it dream new MAST shots?" — the architecture pivot

The first design could not, and we found out why. The original model fused each camera frame by summing all 256 of its tokens into one vector before the transformer (a "bag-of-channels"), so the network attended over time only, never space. You cannot rebuild an image from an orderless sum of its pieces, so the decoded camera predictions were incoherent mush even when the model was overfit — an architectural flaw, not under-training. (A second bug fed token-0 padding frames, from the parts of a shot where the camera is off, as if they were data.) That run was retired.

The pivot: a spatiotemporal transformer. The camera tokens are now modelled as what they are — a video. A decoder-only transformer runs over the sequence of frames × 256 raster tokens; every token keeps its own identity (a value embedding + a factorized row/column spatial position + a temporal frame position), and attention is factorized into space and time: full spatial attention within a frame (≈256²) and causal temporal attention across frames at each position (≈T²), so cost is ≈ T·256² + 256·T² rather than the intractable (256·T)². The pulse-schedule plan is prepended as conditioning frames; a chunked cross-entropy head handles the 218-entry vocabulary without ever materialising the full logits. This is the modern, transformer-native pairing for a discrete-token video substrate — no CNN, no spatial summing. The backbone is now a real ≈269 M-parameter transformer (not lookup tables).

Foundation gate — PRE-TRAIN scoping/overfit data (NOT held-out). Before committing GPU hours we ran the decisive test: a correct spatial architecture must reproduce a handful of memorised frames near-exactly. We overfit 2 shots; loss fell 12.56 → 0.0045, and both the teacher-forced reconstruction and the autoregressive dream hit 0.0000 token mismatch (pixel exact) with a dream change-fraction of 0.99 (genuinely evolving, not frozen). The decoded video below is coherent — sharp central column, up/down divertor lobes, bright X-points, field-line arcs — exactly what the summed model could never produce.

Read these honestly: the GIFs in Figure 6 are an overfit on memorised shots — they prove the architecture is sound (spatial structure survives; the predict→decode→dream pipeline works end-to-end), not that the model generalises. Generalisation — coherence on unseen shots — is the held-out result reported next (§6.1), and it is the real deliverable.

§6.1 — The held-out generation, for the record — and why it is not yet forecasting

This is the actual generated output on unseen shots — shown in full, with the honest verdict it earned. We trained the spatiotemporal transformer on a corpus of MAST rbb camera shots (4×H200, distributed data-parallel) and ran the decisive test: predict and dream shots the model never saw in training — held-out shots 18502–18505. The GIFs below are that real held-out decode (step-3000 checkpoint, the held-out-best snapshot). Why the step-3000 checkpoint, and the metric-vs-vision caveat. The training curve tells an honest two-part story, and the held-out evaluation earned its keep by catching both parts:

  • Overfitting (caught early). Held-out token-mismatch fell from 0.991 → 0.954, bottomed at 0.952 around step 3000, then rose monotonically — the classic signature of a 537 M-parameter model beginning to memorise a finite corpus. Step-3000 is the held-out-best checkpoint; everything after it generalises worse.
  • Late divergence (caught too). With a flat learning rate (no warmup/decay) the run later destabilised: training loss blew up from ≈0.1 to ≈12 at step 9600, and by the final step the held-out token-mismatch had degraded to 1.0000 — the last checkpoint is garbage. The earlier held-out decode the doc briefly carried (the step-12000 final checkpoint, 0.9976 mismatch) was from this diverged state; it has been superseded by the step-3000 figures above.

The caveat that reconciles the harsh number with the coherent video: a held-out token-mismatch of 0.95 sounds catastrophic, but it is computed over a 218-entry (262 144) vocabulary. Over a vocabulary that large, near-saturated token-mismatch coexists with strong visual coherence — the model predicts a token that decodes to a near-identical patch (a neighbour in the Open-MAGVIT2 codebook) rather than the exact training token. The harsh token metric undersold the result: the model learned generalisable plasma structure and dynamics, not memorisation. The token-level number is the right tool for detecting overfit and divergence (which it did, twice), but it is a poor proxy for visual fidelity at this vocabulary size — the decoded video is the honest readout of what the model actually knows.

Tonight's deliverable stands on its own: a coherent, plan-conditioned, autoregressive dream of held-out MAST camera shots at the step-3000 checkpoint. An overnight run (linear warmup → cosine decay with gradient clipping, added regularisation, ~8–10 k shots, and held-out-best checkpointing) is now training to remove the overfit and the late divergence and should sharpen this further. (Superseded — see §6.2 for the overnight outcome, which corrects this: the camera-only run did not generalize, and the real positive came from adding measured-signal conditioning.)

§6.2 — Overnight outcome: measured-signal conditioning gives the first beat of persistence (partial)

The camera-only spatiotemporal model was trained to convergence overnight on 9,000 shots with a proper warmup→cosine learning-rate schedule, gradient clipping, and regularisation. The honest result, scored by the decoded-pixel-vs-persistence metric (§5's lesson: the pixel error against a frozen-last-frame baseline is the verdict, not the GIF's apparent coherence): it lost to persistence on all four held-out shots (2.3–3.8× worse) — held-out generalisation peaked early (~step 3,000) then degraded as it memorised. Camera pixels + the plan alone do not let it forecast unseen plasma.

The pivot that worked: condition on the measured physics. We added the diagnostic signal streams — magnetics (xma), density (interferometer), soft_x_rays, and the Level-2 measured groups (summary, pf_active, gas_injection) — as additional conditioning frames alongside the plan. (An ablation confirms they are load-bearing: zeroing the signals measurably changes the forecast, so they genuinely feed the prediction rather than being silently dropped.) Scored the same way on the held-out-best checkpoint:

Signal conditioning converts "loses on every shot" into "beats on half, one by 2×". That is a real, causal, measured step forward.

The honest limit (do not over-read it): the two wins are on the low-emission, dim shots, where the frame is mostly dark and low pixel-error is intrinsically easier to achieve; the model still loses on the bright, high-motion shots, which are the genuinely hard forecasting. The token-mismatch is still ~0.92 (saturated, uninformative at this vocabulary). So this is a partial, qualified positive — evidence that conditioning on physics lets the model forecast, not a clean win. The next step (planned) is to widen the corpus and re-score on the bright shots with a luminance-fair metric, to see whether the beat extends beyond the easy cases.

§7 — (Superseded) within-line tuning ideas

Superseded by §9. The original §7 listed ways to push the camera-token line further (bigger backbone, full corpus, full-res camera, longer schedule). Generations 2–3 did exactly that — bigger real Transformer (1 B), 9,000 shots, full 16×16 camera, warmup→cosine schedule — and the held-out result still collapsed to persistence (§6). So more of the same is not the lever. The honest next step is an architecture/strategy change, reasoned in §9.

§9 — Where we go now: the strongest levers, and why the current setup can't be trained into a forecaster

§9.1 — Why no amount of training fixes the current setup

Three independent results converge on the same conclusion — the ceiling is structural, not a training-effort problem:

  • Persistence is the near-optimal predictor at this horizon. Tokamak diagnostics are quasi-stationary over the ~tens-of-ms forecast window; the previous frame is an extremely strong guess. A free-running autoregressive generator with no new information per step cannot systematically beat it — the best it can do is reproduce persistence, which is exactly what all three generations converged to.
  • The information ceiling was already proven (S9 oracle). The mse-free-current-recovery sprint established with a supervised oracle that for internal-state recovery on MAST the binding constraint is interior information, not ML — "time-history adds nothing". A model that only re-reads the same observations it was given cannot manufacture missing interior information by training harder.
  • Free-running generation has no correction step. The current model dreams open-loop: it never compares its rollout against incoming measurements and corrects. Error compounds; the only stable fixed point is "don't move" (persistence). This is the structural giveaway that we are missing a filtering step, not parameters.

So the diagnosis is not "too small / too little data". It is that the generative camera model, as built, runs open-loop and uncorrected: it dreams from a fixed plan + context and never re-reads a measurement, so it has nothing to forecast from after the context ends, and error compounds to the persistence fixed point. The goal is unchanged — we still want the generative camera model, dreaming plausible video from a pulse schedule — but capable and correct. What makes it capable is giving it (a) an explicit state with uncertainty, (b) a correction step against streaming measurements, and (c) broadband, information-rich conditioning. Those are filtering ingredients; the output is still the generated camera video.

§9.2 — How to make the generative camera model capable: wrap it in a corrected state-space loop

The fix is not to abandon generation — it is to stop generating open-loop. The strategy doc frames the unifying identity: a generative world model is a learned state-space model (encoder → latent state → learned transition → observation/decoder). Our camera model already has the encoder (Open-MAGVIT2 + the spatiotemporal Transformer) and the decoder (the VQ decoder that makes the dream visible); what it lacks is the correction step and a state that accumulates information. Add a filter (Kalman/EnKF in the latent) that, at each step, predicts the latent forward (learned or physics transition), then corrects it against whatever measurements are still arriving — magnetics, fast diagnostics, and the camera itself — before decoding the next frame. The camera generation stays the product; the filter is what keeps the dream on the rails instead of decaying to persistence. The Kalman filter is just the linear-Gaussian special case of this loop; a conditional diffusion decoder/transition (§9.4) is the expressive, non-Gaussian version for sharp, plausible frames.

§9.3 — We are NOT discarding the capability that worked: the Kalman/EKF line

Critically, the project already has a working instance of this north-star that we should build on, not abandon. sequential-current-da-v1 built a reduced 1-D ψ-diffusion Extended Kalman Filter (RAPTOR-lineage) with a localized analysis update and split-conformal calibration, and on a held-out pilot reported pitch RMSE 0.124 with 90% coverage 0.962 — a genuine, calibrated, physics-grounded result that decisively beat the v0 EnKF parameter-smoother baseline. That capability is locked but idle. The lead's instinct is right: Kalman filters + broadband signals (video + diagnostics) is the live, validated lever, not a fresh gamble.

§9.4 — The strongest levers to make the camera dream capable, in priority order

All four serve the same goal — a generative camera model that produces correct, plausible, plan-driven video — by fixing the open-loop failure of §9.1, not by replacing generation.

  1. Close the loop: a latent filter around the camera generator (strongest). Keep the Open-MAGVIT2 + spatiotemporal Transformer as the encoder/decoder, but carry the camera latent as a filtered state: predict it forward, then correct it against the measurements still arriving (magnetics, fast diagnostics, and the observed camera) before decoding each next frame. The neural-KF survey already named the principled mechanisms — a Koopman linear-latent + EnKF (LAE-EnKF) (exact analysis in a learned latent) or a learned-gain KalmanNet. This is what stops the dream decaying to persistence: it keeps ingesting information instead of free-running. The camera work so far is the front-end of this, not wasted.
  2. Broadband conditioning as observation channels. Feed the measured physics — magnetics (xma), density (interferometer), soft_x_rays, the Level-2 groups — into the correction step as additional observations (§6.2 already showed signal-conditioning is load-bearing and produced the first persistence beat). Broadband signals carry the interior information the S9 oracle flagged as the binding constraint, so they are what let the generated frames track real plasma dynamics rather than the slow background.
  3. Known-good physics as the transition (TORAX). Use a differentiable/reduced TORAX (or the reduced ψ-diffusion model validated against TORAX q(ρ,t), already in sequential-current-da-v1) as the predict step the filter rolls the latent forward with — a trusted forward model the learned camera components only correct, per the learned-closure thread. A physics-anchored transition gives the dream the right dynamical drift between corrections.
  4. Diffusion as the generative engine (the route to sharp, correct frames). This is likely the biggest single upgrade to the camera model's quality: replace the discrete argmax-per-token rollout (which blurs and saturates) with a conditional diffusion / score-based decoder that samples the next frame given the corrected latent + plan. Diffusion is the natural non-Gaussian generator and pairs with score-based data assimilation, so it doubles as the filter's probabilistic observation/transition. Used inside the closed loop of §9.2 it gives plausible, non-blurry dreams; used open-loop (as now) it would still collapse — the loop is what matters.

§9.5 — Recommended next step

Keep the generative camera model as the deliverable; make it capable by wrapping the existing camera encoder/decoder in a corrected latent state-space loop. Concretely: build the camera latent into a filtered state (LAE-EnKF or learned-gain KalmanNet, lever 1) with the measured signals as observation channels (lever 2), reusing tonight's Open-MAGVIT2 + spatiotemporal encoder as the front-end and the EKF substrate that already works (RMSE 0.124, cov90 0.962) as the filtering machinery. Anchor the transition in reduced TORAX (lever 3); then upgrade the decoder to a conditional diffusion model (lever 4) for sharp, plausible frames. This produces exactly what was asked — a generative camera model that dreams from the pulse schedule, but capable and correct because it is corrected against streaming data instead of free-running. Captured as f-wmp-signal-scale on the world-model-prototype plan, aligned with the strategy north-star.

§8 — Glossary & frameworks

Terms.

  • MAST — Mega-Amp Spherical Tokamak (the UK fusion device this data comes from).
  • World model — a learned model of how observations evolve in response to actions.
  • Pulse schedule / plan — the pre-programmed actuator waveforms set before a shot (the actions).
  • Token / codebook — a signal or image is converted into a sequence of integer codes drawn from a learned dictionary (the codebook), so one sequence model can read every modality.
  • Decoder-only Transformer — the GPT-style architecture: predicts the next token from all previous tokens via masked self-attention.
  • Autoregressive (AR) rollout — generating a sequence by repeatedly predicting the next token and feeding it back in. This is what "dreaming a shot" means here.
  • NLL — negative log-likelihood, the next-token training loss.
  • Persistence baseline — predict "the last observed value, unchanged". A strong baseline for slowly-varying signals.
  • Skill score — 1 − model_error/baseline_error; positive beats the baseline.
  • Held-out — shots excluded from training, used only for evaluation (here, discovery indices ≥ 4000).
  • LFQ / VQ / FSQ — Lookup-Free / Vector / Finite-Scalar Quantisation: families of methods for turning continuous data into discrete tokens (the camera codebooks are LFQ at 218 entries).
  • Level-2 (L2) — the leakage-controlled measured + authorised-planned input light-path; reconstructed-equilibrium targets live in a physically separate eval-only store.

Frameworks used.

  • PyTorch (2.11, CUDA 13.0) — the model, training loop, and rollout.
  • Open-MAGVIT2 — the frozen image tokeniser/decoder (VQModel, LFQ) that turns camera frames into 218-vocabulary tokens and back to 256×256 images.
  • Zarr — chunked array storage for the token corpus.
  • NumPy / Matplotlib — the artifact bundle and the figures in this document.
  • SLURM — the H200 GPU compute scheduler (training and decode ran on one card).
