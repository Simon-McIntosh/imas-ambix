Reading note (educational dual-purpose). This plan doubles as a teaching document for the prototype. Acronyms are expanded on first use, the modelling techniques are explained in plain terms, and every external framework we lean on is named in §8. If a term is unfamiliar, the glossary (§8) defines it.

§1 — Objective

Build the first world model on top of the multi-modal token substrate. A world model is a learned model that predicts how a system's observations evolve over time in response to actions. Our actions are the pulse schedule — the pre-programmed actuator waveforms an operator sets before a MAST (Mega-Amp Spherical Tokamak) shot: the demanded plasma current, density, heating and coil currents. The "set target waveform" in everyday language.

The prototype answers one concrete question: given a shot's pulse schedule (and a short slice of how the shot started), can we predict what every diagnostic will show for the rest of the shot? We then score that prediction against what actually happened — the predict-vs-reality loop that is the "day-state" half of the ITER World-Model vision (iter-vision-program).

This is forward model identification: learning the plasma's action→response behaviour from data, rather than solving it from first-principles equations.

§2 — What we build on: the token substrate (done)

The hard, foundational data engineering is complete (multimodal-tokenisation-substrate, all followups landed). Tokenisation means converting continuous signals and images into sequences of integer codes drawn from a learned codebook, so that a single sequence model can consume every modality on a common footing — exactly as a language model consumes word-pieces. We have, across the ~11,573-shot corpus:

  • Camera frame tokens — five cameras (rbb/rba/rco/rgb/rgc) encoded by Open-MAGVIT2 (an open-source image tokeniser using LFQ, Lookup-Free Quantization — a vector-quantiser variant that maps each 256×256 frame to a 16×16 grid of discrete tokens). 6,155–9,527 shots per camera.
  • High-frequency (HF) signal tokens from our phase-aware patch-transformer tokeniser (a PatchTST/ViT-style model: it cuts the waveform into patches, lifts them through a complex Short-Time Fourier Transform so phase is preserved, runs a Transformer encoder, then a quantiser). Codebook chosen per modality by measured phase fidelity: xma (≈5 kHz Mirnov magnetic-pickup coils → MHD mode activity) → continuous embedding; xim (50 kHz Dα/CII line emission → edge/ELM activity) → FSQ (Finite Scalar Quantization); xsx (500 kHz soft-X-ray chord arrays → core emission/sawteeth) → VQ (Vector Quantization). 12k–14k shots each, ~750M tokens total.
  • Level-2 (L2) measured + authorised-planned inputs — the processed, physical-unit diagnostics (plasma current, line-averaged density, radiated power, neutral-beam power, neutron rate, interferometer density) and the authorised planned waveforms (pulse-schedule demands, coil-voltage / gas-valve setpoints). 67,858 channel-stores, every field passed through a provenance leakage guard.
  • L2 targets store (eval-only) — the code-reconstructed equilibrium (poloidal flux ψ on a 65×65 grid, the safety-factor profile q, the plasma boundary, global scalars) plus reconstruction-derived globals. These are what the model must predict, held physically separate behind a load-bearing boundary guard so they can never leak into the inputs.

§3 — Architecture: the plan-conditioned multi-modal transformer

The prototype is a decoder-only Transformer (the "GPT" architecture: a stack of self-attention layers that predicts the next token from all previous tokens), operating over the interleaved multi-modal token streams and conditioned on the pulse schedule. "Conditioned" means the planned waveforms are supplied as side-information the model can attend to at every step — so the same initial plasma state under two different plans yields two different predicted futures. Built in PyTorch.

How it trains. Standard next-token prediction with teacher forcing (the model sees the true previous tokens during training) under a cross-entropy / negative-log- likelihood (NLL) loss per token. At inference we switch to autoregressive rollout (the model consumes its own predictions). Per-group-local vocabularies (locked decision in the substrate plan) mean each modality is its own channel with its own embedding, disambiguated by tokeniser name; a unified-flat rebasing utility exists if a single shared vocabulary is ever wanted.

§4 — Predictive capability: what a plan-conditioned model can and cannot forecast

This is the honest, physics-grounded core. Predictability splits cleanly by whether the plan determines the quantity.

So the demo's honest claim is a plasma-response forecaster: sharp and quantitative on the controlled macroscopics and the equilibrium evolution; calibrated-statistical on the bursty micro-events. We frame outputs as a MAP estimate (Maximum A Posteriori — the single most-probable trajectory) for the controlled part plus sampled rollouts for the variability, and we score probabilistically with the CRPS (Continuous Ranked Probability Score — a proper scoring rule that rewards sharp and calibrated probabilistic forecasts). Over-claiming exact Edge-Localized-Mode (ELM) timing is the trap to avoid.

§5 — Evaluation: the predict-vs-reality "day" loop

The evaluation is the demo. Take a held-out shot (never seen in training), give the model only its pulse schedule + a short initial window, roll forward, decode, and compare to reality.

§6 — Implementation plan (the runnable skeleton)

The first deliverable is a skeleton that runs end-to-end — tokens in, recognizable prediction out — overfit on a handful of shots to prove the wiring, then trained. Four scoped pieces:

  1. Data assembly (imas_ambix/worldmodel/dataset.py): assemble per-shot multi-modal token sequences on a common time grid, attach the pulse-schedule conditioning, and split into a context window + a target window. Reuses the substrate's store_v2 readers, the boundary-guarded input loaders (so targets can never be ingested), and the L2 input stores. Done-when: a fixture test assembles a shot and a tiny real-shot smoke runs; the target store is provably never opened by the input path.
  2. Model (imas_ambix/worldmodel/model.py): the plan-conditioned decoder-only Transformer (per-group-local token embeddings; pulse-schedule injected as conditioning tokens). Done-when: forward/backward pass gradchecks; parameter count + context length documented.
  3. Train + overfit smoke (train.py + a hardened SLURM batch script): next-token NLL training loop with the repo's GPU-safety hardening (SIGTERM handler, watchdog, drain sidecar). Done-when: it overfits a handful of shots (loss → near-zero, decoded rollout is recognizable) on the idle H200s — the end-to-end proof.
  4. Eval (eval.py): forward-predict a held-out shot from its plan, decode, and score against the L2 targets + a persistence baseline at fixed horizons; report the controlled-vs-stochastic split per §4. Done-when: a predict-vs-reality figure for one held-out shot.

Compute & frameworks for the build: PyTorch on the 4×H200 Group-A reservation via SLURM (compute); two GPUs left free for the DeepSeek-V4-Flash serve. GPU-drain safety per AGENTS.md §2a (sidecar on, clean SIGTERM teardown).

§7 — Scope & sequencing

  • Prototype scope: start with a tractable modality subset (L2 measured inputs + one camera + xma), short horizon, small model — prove the loop, then widen. The substrate supports all modalities; the prototype need not use them all on day one.
  • Honest framing first: the skeleton's job is to make predict-vs-reality run; quantitative skill claims come only after a trained run with the §4 decomposition reported.
  • Augmentation (later): TORAX (Google DeepMind's JAX-based differentiable tokamak core-transport simulator) can supply a physics teacher / synthetic rollouts to regularise the learned dynamics — deferred past the first prototype.

§8 — Glossary: acronyms, techniques & frameworks (educational)

Domain / physics

  • MAST — Mega-Amp Spherical Tokamak (the UK fusion device our data comes from).
  • Pulse schedule — the operator's pre-programmed actuator waveforms (the "plan"): demanded plasma current, density, plasma shape, heating, coil voltages, gas valves.
  • Ip / n_e / ψ (psi) / q — plasma current / electron density / poloidal magnetic flux / safety factor (the ratio of toroidal to poloidal field-line turns; the key stability profile).
  • ELM — Edge-Localized Mode: a quasi-periodic burst at the plasma edge. MHD — magnetohydrodynamic (the fluid+magnetic-field instability physics). Sawtooth — a core relaxation oscillation.
  • Mirnov coils — magnetic pickup coils sensing MHD modes (our xma). Dα — deuterium-alpha line emission, an edge/ELM/recycling indicator (xim). SXR — soft X-ray, a core-emission diagnostic (xsx). NBI — Neutral Beam Injection (heating).
  • EFIT / Grad-Shafranov (GS) — the equilibrium-reconstruction code / the MHD force-balance equation it solves; produces the ψ(R,Z) and q we use as eval-only targets.
  • EnKF — Ensemble Kalman Filter: the classical data-assimilation baseline our forecaster must beat.

Modelling techniques

  • World model — a learned action→observation forward predictor.
  • Tokenisation / codebook — discretising signals/images into integer codes from a learned dictionary, so one sequence model handles every modality.
  • VQ / FSQ / LFQ — Vector Quantization / Finite Scalar Quantization / Lookup-Free Quantization: three ways to map continuous features to discrete tokens (we use each where it measured best).
  • Decoder-only Transformer ("GPT") — a self-attention stack that predicts the next token from the past. Self-attention lets every token weigh every earlier token.
  • Conditioning — feeding side-information (the plan) the model attends to. Teacher forcing (train on true history) vs autoregressive rollout (infer on own outputs).
  • NLL / CRPS — Negative Log-Likelihood (token training loss) / Continuous Ranked Probability Score (proper probabilistic-forecast metric). MAP — Maximum A Posteriori (most-probable point estimate).
  • Aleatoric vs epistemic uncertainty — irreducible randomness (e.g. ELM timing) vs reducible model/data uncertainty.
  • STFT — Short-Time Fourier Transform (gives the phase-preserving signal features the patch-transformer tokeniser uses).

Frameworks & tools

  • PyTorch — the deep-learning framework (tensors, autograd, nn.Module, DataLoader) the model + training loop are built in.
  • Open-MAGVIT2 — the open-source LFQ image tokeniser for the camera frames.
  • Zarr / xarray — chunked-array storage / labelled-array access for the token store and the FAIR-MAST data.
  • TORAX — DeepMind's differentiable (JAX) tokamak transport simulator, for later physics augmentation.
  • imas-python — the IMAS (Integrated Modelling & Analysis Suite) Access Layer for reading IMAS-formatted data correctly (transpose/COCOS/DD-version handling).
  • SLURM — the cluster job scheduler; we run on the 4×H200 (NVIDIA Hopper) Group-A reservation. reckon — the HTML-first plan/docs system this document lives in.
