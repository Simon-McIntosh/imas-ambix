The GS forward / physics-spine EM infrastructure (~8k LOC in imas_ambix/gs/, ~19k in imas_ambix/latent/) has grown organically through many superseding approaches. This is a read-only survey — four parallel subsystem passes plus direct verification — of the Biot–Savart kernels, the coupling-matrix assembly, the machine-description / circuit layer, and module liveness. It separates what is already well-factored and must not be broken from the genuine duplication, the dead / superseded code, and two stale-cache correctness hazards, then proposes a tiered consolidation roadmap. No code was moved — the trigger was noticing that two functions build passive couplings from the same circuits; the finding is that the fix is smaller and more surgical than it first looks.

§1 — Scope & method

Four parallel read-only passes, each cited to file:line, then cross-checked by hand on the physically-load-bearing paths. The line numbers are as measured when the survey ran and some have since drifted by a few lines as the files changed; the symbol names beside them are the durable anchors, and each one below was re-confirmed to resolve in the tree.

  • Kernels — every ψ / B / A primitive in gs/{elliptic,cylinder,polygon,filaments3d}.py and the point kernels in operator.py. (gs/elliptic.py was in scope when the survey ran and has since been retired — see the note above; the surviving three are where to look now.)
  • Coupling assembly — every site that builds a Green's / coupling matrix or column from circuits + geometry.
  • Machine description — GeometryTable, the circuit role taxonomy, circuits.py, the reader implementations, and the version / cache keying.
  • Liveness — external-import counts across imas_ambix/, scripts/, tests/ to classify each physics module CORE / ACTIVE / STUDY-ONLY / TEST-ONLY / ORPHAN, and to locate the live vs superseded boundary reads.

§2 — What is already well-factored (do not break)

The subsystem is not a mess; several things are done right and any reorg must preserve them:

  • One shared finite-area kernel. hybrid_greens (cylinder.py:188) is the single production finite-area primitive — it blends the exact rectangular thick-cylinder near-field with the point-filament far-field. build_operator, passive_coupling_matrices, and the inductance path all bottom out in it. The kernel layer is consolidated; the duplication lives in the wrappers above it.
  • The two flagged functions already share their sensor/grid couplings. build_passive_circuit_system (temporal_operator.py) does not re-derive a_circ/g_circ — it delegates straight to passive_coupling_matrices (boundary_disc.py). What it adds is the circuit×circuit inductance L and m_coil_circ, which use a different, intentional observer model (see below). So the user-observed duplication is real for circuit iteration but the coupling math is already shared.
  • The observer-model divergence is physics, not sloppiness. Sensor / grid couplings use a point observer with a finite-area source; the inductance L and drive-linkage lam use a two-section averaged observer (a midpoint sub-grid over the target section) because the flux a large vessel element links varies materially across its own cross-section. The 0.01 m source floor (a flux-integration guard) vs the 1e-4 m observer-placement floor is likewise deliberate. A naive "one kernel call everywhere" merge would be wrong.
  • circuits.py ↔ classify_circuits is a clean split. circuits.py is a static transcription of pfSystems.xml (13 active + 10 case circuits, no logic, no data reads); operator.classify_circuits is the sole role-assigner and consumes it. No duplicated classification.
  • The point-filament path is a legitimate fast path, not a bug-duplicate — it is the zero-size limit reached by the plasma-basis columns and by hybrid_greens' own far-field fallback; one implementation, two dispatch entries.

§5 — Stale-cache hazards (correctness, found incidentally)

Two binary caches are keyed by SetupSignature.key but not by the version strings that gate their contents — so a GEOMETRY_TABLE_VERSION / COIL_MODEL_VERSION bump silently reuses stale geometry:

  • temporal_operator circuit-system / eigenbasis .npz (save_circuit_system, save_eigenbasis) embed no version string; filename is campaign+k only. Built from classify_circuits + the merge, so a coil-model bump is invisible to them. This is exactly the hazard the D3 slanted-passive work hit — the geometry bump to amb-schema-canonical-v3 required moving these caches aside by hand.
  • PatchBasis g_pg cache (patch_basis.py:224) keyed on signature + nr + nz; validates array shape only, not version. Lower risk (grid-only) but a geometry-table bump that changes the limiter/plasma basis is not caught.

The JSON operator summaries and grounded-latent checkpoints do carry and check both version strings, so the hazard is confined to these two .npz paths. Folding the version strings into the cache key is a small, high-value correctness fix independent of any reorg.

§6 — Consolidation roadmap (proposed; not yet actioned)

Ordered by risk. Tiers 0/1/4 are safe and mechanical; Tier 2 is the real design the user is after; Tier 3 needs physics judgement.

Tier 0 — Dead-code removal (zero-risk) — largely LANDED at ae728ad

  • DONE. Retire elliptic.py (or reduce it to the single cylinder._ellipp definition it duplicates) — it is unused in production and polygon_greens needs no incomplete Π. Deleted outright; cylinder._ellipp is now the tree's only Π.
  • PARTLY DONE. Retire or wire q1_detect.py (870 LOC test-only) and patch_observation.py (280 LOC orphan) after confirming intent. q1_detect.py retired with its six tests; patch_observation.py is still present and still an orphan — the live patch path remains structure_residual.py + patch_inverse.py, so this one is the remaining Tier 0 item.
  • OPEN. Keep filaments3d's maxwell_mutual as a labelled test oracle; drop or fold the unused rdp/decimate if the EFCC path never defeatures.
  • DONE. Decide the fate of the unwired cross-machine reader seam (MastZarrGeometryReader, ImasGeometryReader): keep as a forward-looking protocol (documented) or remove until the IMAS bridge lands. Decided both ways, per reader: ImasGeometryReader removed because the published-artifact reader supersedes it; MastZarrGeometryReader kept, because the read it fronts is the live efm path. The seam itself is retained as the documented protocol with two implementations.

Tier 1 — Mechanical de-duplication (byte-identical copies)

  • One grouped_passive_circuits(table) / memoised classify_circuits to kill the ~8 by_circ copies (hotspot 1).
  • One sensor-row builder feeding both _sensor_rows and sensor_signature_arrays (hotspot 4).
  • Route boundary_disc's inline projections through _project_bprobe and normalise the kernel return-tuple order (hotspot 3).
  • One PolygonSection-override resolver (hotspot 6), parameterised by whether the observer is shaped or box.

Tier 2 — The geometry-coupling generator (the real design)

A single builder — call it a CouplingBuilder / geometry-operator class — that owns circuit classification + the source-side channel merge once, and exposes the observed coupling as an explicit choice of (source set, observer model, output shape). The four wrappers (build_operator, passive_coupling_matrices, build_passive_circuit_system, build_drive_linkage) become thin callers selecting a configuration. Binding constraints the design must encode explicitly, not erase: the point vs two-section observer model; the /n_merge reciprocal normalisation for drive–drive matrices; the 0.01 source floor vs 1e-4 observer-placement floor; the shaped-vs-box observer choice for polygon sections. Unify the coil→channel map (circuits.py ↔ _PF_COIL_AMC) as its single source of truth.

Tier 3 — Superseded-read consolidation (physics judgement)

  • Reduce boundary_moment.py and boundary_harmonic.py to the pieces still live (the moment basis; the harmonic anchor), moving them behind clearly-named provider functions and retiring the superseded standalone read paths + their study scripts.
  • Audit the gs_solve.py "historical"/"legacy" reproducibility branches (grid-delstar substrate, hard topology read, boundary-continuation arm) — decide which remain load-bearing vs candidate removals.
  • Clarify the status of the study-scoped passive/eddy arm (plasma_screening.py, passive_resistance.py): these are active experiments feeding the gates, not dead — the question is whether any is ready to promote into the production spine or should stay study-side.

Tier 4 — Cache-key hardening (correctness)

Fold GEOMETRY_TABLE_VERSION + COIL_MODEL_VERSION into the .npz cache filenames/payloads for the temporal-operator circuit system/eigenbasis and the PatchBasis g_pg cache, so a version bump auto-invalidates rather than silently reusing stale geometry (§5).

§7 — Recommended next step

This survey is the input to a proper reorganisation plan (a separate, future step — no code moved here). Recommended sequencing when that plan is authored: Tier 0 + Tier 4 first (safe, immediate clarity + a real correctness fix), then Tier 1 (mechanical, test-guarded), then Tier 2 (the generator, the bulk of the value), and Tier 3 last (physics judgement, largest blast radius). Tier 0 is now largely spent (ae728ad; the orphan patch_observation.py and the filaments3d helpers are what remain of it), so the next unspent safe step is Tier 4 — the cache-key hardening, which is the only correctness fix in the list. Every tier is gated by the existing gs + latent suites and, for anything touching solver inputs, a spine sanity check. The load-bearing invariants of §2 are the acceptance guard: the reorg is correct only if the shared kernel, the delegation, and the intentional observer divergences survive byte-for-byte where they matter.
