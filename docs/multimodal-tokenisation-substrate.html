§1 — Objective

Build a robust, multi-rate, phase-preserving token store of all MAST high-dynamic-range inputs, and the phase-aware, transformer-capable tokenisers that fill it. This is a first-class, reusable asset — the substrate that every downstream task consumes (the multi-modal forward World Model, frozen-probe diagnostic readout, structure discovery, ITER transfer). It is developed independently, with value beyond any single downstream proposal, and it runs now on the idle 4×H200 reservation. It is not gated on a forward-model experiment.

§2 — Why now: the fast signals are being destroyed, and one camera is starved

  • Only rbb + low-rate magnetics are tokenised today. Eight other cameras (rba lower, rco colour, rgb/rgc bremsstrahlung, …) and every high-frequency signal are absent from any token substrate.
  • The signal path silently destroys the fast information. tokenizer/alignment.py resamples every signal onto a 100 Hz grid (50 Hz Nyquist) (MODEL_HZ_DEFAULT=100.0, verified) — so the ~5 kHz Mirnov mode structure, 500 kHz SXR, 50 kHz Dα/ELM carriers are annihilated before any model sees them. Fixing this is the load-bearing design decision of the whole pivot.
  • The tokenisers need real development, not a convenience layer. They must be phase-aware (the interior-information study proved magnitude-only spectra are blind to mode structure — oracle_probe.py) and transformer-capable: patch transformers for 1D→3D signals (PatchTST/ViT-style patchification → transformer → learned codebook) so a downstream attention model consumes any modality on a common footing.

§3 — The substrate spec

  • Multi-rate store schema tokens/v2/<modality>/<shot>/<source>.zarr: every modality keeps its native token cadence with an explicit per-token time coordinate and a phase_preserving flag; per-channel validity masks (never silent zero-fill). Attrs: tokenizer_name, vocab_version, native_rate_hz, token_rate_hz, n_channels, channel_names, phase_preserving, original_window. This bypasses the 100 Hz aligner — modalities are resampled at consume-time by the downstream model, never destroyed at encode-time.
  • Registry v2 (tokenizer/registry.py, bump VOCAB_VERSION): one block per tokeniser — a shared frame block for the visible cameras, a Cosmos video block, and one codebook block per HF signal family; a new SIGNAL_HF block-kind in base.py.

§4 — The tokenisers and the parallel encode fan-out (authorised)

Six per-modality development/encode tracks fan out from the frozen schema, sequenced by value under the one reservation (cameras + the two highest-information HF families first). Each is gated only by its own per-modality reconstruction-fidelity QC (round-trip CRPS incl. phase on a holdout), not by any project-level decision:

  • Visible cameras rba/rco/rgb/rgc — the proven stream_encode.py OMAG2 path (any-res → 256² → 16×16 LFQ), one job per camera. (Care: rco is real 3-channel colour — do not grey-collapse; bremsstrahlung cameras may need a different normalise.)
  • Phase-aware patch-transformer tokeniser for 1D HF signals — the genuinely new modelling: patchify the windowed signal, a transformer encoder, a learned codebook (VQ/FSQ) over phase-preserving features (complex STFT bins / raw patches), a decoder; trained to reconstruct preserving phase + mode structure. First targets the highest-information families: xma ~5 kHz Mirnov (+ cross-channel poloidal/toroidal mode-number tokens) and xim 50 kHz Dα/ELM; then xsx 500 kHz SXR.
  • Cosmos DV4×8×8 video tokens — wire the staged-but-unused temporal tokeniser into a corpus encode (the motion substrate the camera arc named as the open lever), kept alongside the per-frame OMAG2 tokens.
  • Medium-rate bundle — interferometer ane, bolometer abm, reflectometry aoe (lowest priority; some may stay low-rate channels).

§ Decisions

What codebook does the phase-aware patch-transformer 1D tokeniser use?

Resolved by direct phase-fidelity measurement (commit 6777d80), not by prior. PER-MODALITY: (xma 40-coil Mirnov) CONTINUOUS+mask wins — quantisation destroys the cross-coil phase that carries mode structure (FSQ phase-err 0.219 rad vs continuous ceiling 0.015; mode complex-corr continuous 0.992 vs FSQ 0.815; VQ collapses to ~0.816). (xim Dα/CII carriers) FSQ wins — tolerates quantisation (96 active codes, no collapse, phase-err 0.182 within tolerance). VQ-VAE collapses in BOTH (3-6 active codes). This empirically confirms the interior-information study thesis that phase/mode structure is quantisation-fragile — so the store carries an optional continuous embedding array (commit 90746cc) for the continuous case.
