§1 — Overview: connectivity-first topology, ported GPU-native

The worry this plan closes. The topology read — magnetic axis (O-point), X-point(s), LCFS/boundary, core mask — is the one data-dependent step in the batched equilibrium engine, and the place EFIT-class reconstructors sink: contour trees, critical-point classification, private/common flux separation, strike-point finding, limited/diverted branches. Ported verbatim to a GPU it re-serialises the whole rollout (host round-trip, `argwhere` loops, union-find connected components, variable-count nulls). We deliberately skipped it; this plan resolves it cleanly, as a prerequisite for gpu-accelerated-labeler.

We already have the "other way" — port it, don't reinvent it. Our engine resolves the LCFS by connectivity, not stationary-point classification (the shipped connectivity-boundary-classification read lcfs_contour, used as the frozen-spine pushout boundary): the boundary is the outermost closed, axis-enclosing flux contour that still lies inside the wall, found by ONE monotone flux-offset push. There is no limited/diverted branch and no X-point gate; X-points and the class are read off afterward by proximity to the ring, with a soft margin. This is continuous through the marginal limited↔diverted transition by construction — exactly the case (limiter-ψ ≈ X-point-ψ; a marginal plasma looks identical in flux space) where classify-first is ill-conditioned, because the connectivity read never decides which surface bounds; it finds where the axis-connected region stops being closed inside the wall.

What to port (independent nova review verdict). Porting nova's topology is NOT a prerequisite; the connectivity read is the stronger GPU-native choice. Adopt from nova ONLY two proven, vmap-safe, differentiable primitives: the stencil sign-change null classifier (`zero_cross_count`: 0 sign-changes → O-point, 4 → X-point) for the axis and optional X-point diagnostics, and the local-quadratic sub-null refinement (`select.subnull`: sub-grid position/flux/Hessian type, with a proven `jax.grad` path), plus the static-count idiom (`jnp.where(size=K)` + NaN-pad → `nanargmax`). Do NOT port nova's boundary mode-gate, its half-plane core mask (spurious X-points pollute it; it is a geometric approximation, not a true interior), its single-loop wall-contact, or the host-side contourpy.

The GPU-native rewrite (the work). The connectivity ALGORITHM is validated; the current IMPLEMENTATION uses the GPU-hostile primitives (contourpy, `ndimage.label`, `argwhere`+Newton). Re-express the SAME algorithm with GPU-native ops: a fixed-iteration convolutional flood-fill from the axis (dilate ∧ {ψ_N < level}) replacing contourpy + `ndimage.label`; a fixed candidate-level sweep with batched containment/pinch reductions replacing the bisection; the axis + X via the nova stencils. Branchless, fixed-shape, vmap-safe, differentiable (smooth mask) — so the whole rollout supports implicit-diff. Machine-agnostic by wall MASK. This is the on-device topology read gpu-accelerated-labeler depends on; it also sharpens the CPU greens-filament-solver read.

Now doubly load-bearing — it also unblocks the fixed-point accelerator. greens-filament-solver §4 (shipped 2026-07-20) established that no per-solve CPU iterator — Picard, safeguarded Anderson, or Newton–Krylov — clears the throughput gate, and the wall is precisely this read: the hard-threshold host topology step (find_critical_points + ndimage.label core mask) makes the free-boundary map non-differentiable, so finite-differencing the residual across a mask flip corrupts Newton–Krylov’s Jacobian and the mask-flip noise corrupts Anderson’s history (measured: Anderson ~1.3× only on well-posed slices; NK diverges on 2/5). Making this read continuous and differentiable therefore does two things at once: it lets the accelerator schemes be revisited on a solvable (differentiable) map, AND it makes the map vmap-batchable for gpu-accelerated-labeler. This plan is the shared prerequisite for both the accelerated solve and the batched GPU throughput.

§4 — Machine-agnostic wall mask (single / multiple / movable limiters)

Generalise the wall-inside predicate to an arbitrary wall MASK so the read is machine-agnostic: MAST single closed loop, AUG multiple discrete limiters (a union mask; the poke-out test is "axis-connected region ⊄ union-wall-mask"), WEST movable / per-pulse limiters (a per-pulse/per-phase mask input). This is where a classify-first pipeline becomes machine-specific (limiter-contact search, strike-point logic); the connectivity read needs only the mask. Implement the mask as a raster boolean grid (the union of all limiter units rasterised) — strictly more general than EFIT's polygon-composite/convex-hull (`compositeInclusionPolygon`): a raster natively handles disconnected tiles and non-simply-connected walls, rebuilds cheaply per pulse (WEST), and admits a soft/smoothed (differentiable) form. Heed EFIT's own lesson (`zlimit.f90:826-829`): do NOT excise interior tile material from the flux-occupiable domain (it fragments the divertor into islands) — mark tiles as boundary, not holes. Gate T-D: the boundary read is correct on synthetic single-loop, multi-polygon, and time-varying-wall cases (limited and diverted), with the wall supplied as a raster mask, not code.

§5 — Differentiable + adversarial-topology robustness

Make the read differentiable (smooth/sigmoid core mask, soft level) for the implicit-diff rollout (feeds gpu-accelerated-labeler §7), and pin the adversarial topologies the connectivity read must get right: double-null / near-double ordering, secondary separatrix, private-flux pockets (already connectivity-separated in classify_regions), and snowflake configurations. Gate T-E: on synthetic and real double-null / high-triangularity slices the read matches the exact CPU read (boundary, private/core separation, X-slots) to tolerance; the smooth-mask variant is validated against the hard-mask read before use in the differentiable path.

§ Decisions

Connectivity-first or classify-first topology extraction?

Locked by the lead (2026-07-20), backed by an independent nova-topology review: classify-first is discontinuous through the marginal limited↔diverted transition (nova gates the boundary on a flux-vs-contact mode + an X-point height band, with a likely bug at topology.py:94-95); imas-efit carries the fuller contour-tree tar pit. The connectivity read is continuous by construction, already validated (connectivity-boundary-classification, best-in-class LCFS), and GPU-native as a flood-fill. This is the ONE topology paradigm for the engine.

How much of nova's topology do we port?

Locked (2026-07-20, lead + nova review): lean on nova's ALREADY-working, GPU-compliant, differentiable stencils (proven jax.grad path) for sub-grid O/X location — that is real, reusable value. Do NOT port nova's boundary mode-gate (discontinuous at the marginal transition), its half-plane core mask (approximate; spurious X-points pollute it), its single-loop wall contact (breaks on multi-limiter machines), or its host-side contourpy. The boundary + interior come from OUR connectivity flood-fill.

How is the limiter/wall represented?

Locked (2026-07-20): the ONLY machine-specific input to the connectivity read is the wall mask, so multiple discrete limiters and movable limiters are a union / per-pulse mask, not new code paths — the machine-agnostic North Star. A classify-first pipeline is where limiter/strike logic becomes machine-specific; designing the mask abstraction in from the start (green-field) keeps the read machine-agnostic.
