One-line cause

Our rbb bulk-encode 1208195 deadlocked (prefetch producer/consumer), leaving a GPU process stuck in uninterruptible state. On scancel it did not die within SLURM's UnkillableStepTimeout (~60 s), so slurmd marked "Kill task failed" and auto-drained the node.

Why the process was unkillable

  1. The prefetch double-buffer (commit 4f7ab48) used a producer thread pool feeding a bounded queue. A producer raised on a bad shot and died without signalling → the consumer blocked forever on queue.get() → deadlock.
  2. With the daemon mid-CUDA and threads blocked, the process sat in uninterruptible kernel sleep (D). SIGKILL cannot reap a D-state process until the kernel call returns — which never happens for a wedged CUDA/GPFS op.
  3. UnkillableStepTimeout expired → "Kill task failed" → drain.

Prevention (in motion)

  1. Retire the legacy frame-daemon path. stream_encode.py (in-process, no subprocess daemon, no prefetch threads) removes both drain surfaces and becomes the sole frame encoder once GPU-validated.
  2. Graceful SIGTERM handler — clean shutdown in <5 s (HARDEN-STREAM).
  3. Per-shot/batch watchdog — abort a stuck unit instead of hanging.
  4. Never scancel a CUDA-wedged job expecting clean teardown — detect the hang early (token-rate watchdog) and exit cleanly.
