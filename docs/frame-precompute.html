Plan: Pre-decoded + pre-resized rbb frames at 256² uint8

imas-ambix / Fusion World Model · Sprint S4 · Updated 2026-05-26

Pending — sprint S4, blocked on zarr-consolidate landing first.

Precompute the per-shot uint8 RGB 256×256 frame tensor once and store it next to the raw Zarr. Saves the uint16→uint8 normalisation and the 536×560→256×256 bilinear interp on every encode — converting the encode loop from I/O+CPU+GPU to pure GPU.

§1 · Why precompute

Current encode path per shot:

  • open_zarr → load uint16 (T, H, W) ≈ 89 MB
  • _normalise_frames_to_uint8 — per-shot min/max scan + cast
  • np.repeat to RGB
  • torch.bfloat16 cast
  • bilinear interp 536×560 → 256×256

The CPU/IO portion is ~0.4 s per shot. With 4 GPUs and a target encode time of ~3 s/shot, CPU/IO is 13 % of wall. At larger batches or with longer rbb shots, this fraction grows. Precomputing once amortises the cost across every future encode and the eventual training data loader.

§2 · Output layout

Write to /work/projects/imas_gpu/mast/preprocessed/rbb-256/<shot>.zarr with a single 4-D array data: (T, 256, 256, 3) uint8.

  • Per-shot bytes: 149×256×256×3 ≈ 30 MB
  • Corpus total: ~290 GB (9,527 shots)
  • Fits comfortably in GPFS quota
  • Compatible with xr.open_zarr for the encoding/training loader
  • Original L1 corpus left untouched

§3 · Implementation

New module imas_ambix/data/preprocess.py:

def preprocess_rbb_shot(shot_id, src_root, dst_root, image_size=256):
    ds = xr.open_zarr(src_root / f'{shot_id}.zarr/rbb', consolidated=True)
    raw = ds['data'].values  # (T, 536, 560) uint16

    # Per-shot lo/hi matches _normalise_frames_to_uint8 exactly — bit-exact reconstruction.
    lo, hi = raw.min(), raw.max()
    u8 = ((raw - lo) * 255.0 / (hi - lo)).clip(0, 255).astype(np.uint8)
    rgb = np.repeat(u8[..., None], 3, axis=-1)  # (T, 536, 560, 3)

    # Resize on CPU once — cv2.INTER_LINEAR matches torch F.interpolate bilinear closely.
    out = np.stack([
        cv2.resize(f, (image_size, image_size), interpolation=cv2.INTER_LINEAR)
        for f in rgb
    ])
    zarr.save_array(dst_root / f'{shot_id}.zarr/rbb', out)

CLI hook: ambix data preprocess-frames --camera rbb --image-size 256 --workers 16 --from-bucket-all. Sharded across CPU cores on a sun_debug SLURM allocation — no GPU needed, just RAM + GPFS bandwidth.

§4 · Encode-path integration

OpenMagvit2Tokenizer.encode_shot(shot_id) gains a preprocessed-aware fast path: if preprocess_root/<shot>.zarr exists, skip the normalise/repeat/resize and go straight from (T, 256, 256, 3) uint8 → bf16 → daemon. Falls back to the legacy path for shots without a precomputed cache.

Expected per-shot encode time after landing: drop from ~3 s to ~1.5 s on H200 (GPU-bound once CPU preprocessing is eliminated).

§5 · Validation

  • Bit-exact check: encode shot 15085 via (a) legacy path and (b) preprocessed path — assert identical token output.
  • Throughput check: 100-shot encode wall time goes from estimated 5 min to estimated 2.5 min on a single H200 (2× speedup).
