Plan: Pre-decoded + pre-resized rbb frames at 256² uint8

imas-ambix / Fusion World Model · Sprint S4 · Updated 2026-05-26

Pending — sprint S4, blocked on zarr-consolidate landing first.

Current encode path does the uint16→uint8 normalisation, RGB replication and 536×560 → 256² bilinear interp every time a shot is encoded. With a 4×H200 target throughput of ~4 Gb/s aggregate, this CPU/IO portion is ~13 % of per-shot wall and grows with concurrency. Precompute it once, store the (T, 256, 256, 3) uint8 tensor next to the raw Zarr, and the encode loop becomes pure GPU.

1. Why precompute

See state §1.

2. Output layout

/work/projects/imas_gpu/mast/preprocessed/rbb-256/<shot>.zarr, one (T, 256, 256, 3) uint8 array per shot. Corpus total ≈ 290 GB.

3. Implementation

New imas_ambix/data/preprocess.py + ambix data preprocess-frames CLI. Sharded across CPU cores on a sun_debug allocation — no GPU needed. See state §3.

4. Encode-path integration

OpenMagvit2Tokenizer.encode_shot gains a preprocessed-aware fast path; legacy path stays as fallback for shots without a cache.

5. Validation

Bit-exact token output on 5 spot-checked shots; 2× wall-time speedup on 100-shot encode.
