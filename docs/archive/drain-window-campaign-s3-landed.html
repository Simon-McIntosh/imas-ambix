What shipped

The existing separate-allocation observer was extended with four new streams that, for the first time, capture both halves of the drain causal chain in a single event: process-side (existing) and SLURM-side (new).

StreamOutput fileCadenceStatus
SLURM config .slurm_config Once at startup ✓ Captures UnkillableStepTimeout, KillWait, partition overrides
Node state / Reason= .node_state Every 2 s ✓ Full scontrol show node State + Reason lines
slurmd log .slurmd Continuous tail ⚠ Not accessible (0600 root root); stream documents this
Cgroup PID set .cgroup_pids Every 1 s ✓ cgroup v2 (RHEL 10 / Linux 6.12 confirmed); leaf-recursive discovery; per-PID state + wchan + cmdline

Pre-window SLURM config values (from scontrol)

  • UnkillableStepTimeout = 60 sec
  • KillWait = 30 sec
  • ProctrackType = proctrack/cgroup
  • CgroupPlugin = autodetect (resolves to v2 on this node)
  • No per-partition betelgeuse overrides found

Limitations

  • The .slurmd stream will be empty in all runs — the slurmd log is root-only. The stream documents the permission failure in its output file, so a missing stream is distinguishable from a silent failure.
  • Cgroup path layout on a running compute node (with a real active job) may differ from the login-node view; the runtime find -name "job_${TARGET_JOBID}" discovery handles layout variations without hardcoding.
