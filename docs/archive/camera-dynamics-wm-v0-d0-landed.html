Pre-registered win-condition metrics (locked)

  • W1 — dynamics beat statics. masked_token_nll + masked_top1_accuracy over the masked set (vocab-agnostic — the LFQ bit-head decision is free), with bootstrap_ci (10k-resample percentile) on the paired diff. The directional win gate is favours_dynamics (CI lower bound > 0); clear_of_zero is the weaker two-sided significance flag. A motion-weighted token subset (identity changes within ±50 ms) is reported alongside so static background tokens do not flatter the headline.
  • W2 — forward horizon. horizon_frame_offsets maps the locked physical horizons {10, 50, 200 ms} to frame offsets via the per-frame Δt (physical, not index-based); horizon_reconstruction_accuracy scores the predicted future frame at the frontier + offset, and persistence_baseline_accuracy is the copy-last-frame bar the arm must beat (alongside the per-frame baseline).
  • W3 — the latent knows physics. ProbeProtocol fits a frozen ridge / shallow-random-feature probe on train latents → diagnostics, then predicts held-out without refit; scored by per-target probe_rmse and closed-form crps_gaussian. Targets: Dα ada, line-integrated density ane, Thomson Te_core ayc, n=2 mode amplitude ama. The same protocol scores the dynamics latent and the baseline representation.
  • Banned: rFID as a primary metric (S5 lesson); pixel L1/SSIM via the frozen decoder is secondary-only and not implemented in D0.

Orchestrator evaluation

Independently verified after landing (the user directive was to evaluate all work as it lands): commit scope was clean (only imas_ambix/camdyn/, tests/camdyn/, the new figure, and a 4-line per-file ruff ignore in pyproject.toml for conventional linear-algebra naming — the dirty peer file sequential_da.py was left untouched); the leakage ban is enforced inside load_conditioning; the split invariants (disjoint partitions, 108 ⊂ held-out, 108 + 4 = 112) hold; the metric numerics pass on synthetic inputs; the 70-test suite reproduced green on an independent re-run. One latent footgun was fixed: bootstrap_ci's two-sided clear_of_zero would have read True for a significant regression, so a directional favours_dynamics field (+ a regression test) was added so the pre-registered W1 verdict cannot miscount a loss as a win (commit d7b7953).
