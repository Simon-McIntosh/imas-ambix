§4 record — performance to corpus scale: the CPU accelerator ceiling

Verdict (2026-07-20): campaign cache LANDED; G3 (≥3× on CPU) an HONEST NEGATIVE, routed to the GPU path per the pre-declared stop rule. §4 set out to reach a ≥3× corpus throughput on CPU via campaign-scope caching + collapsing the label solve + settling the fixed-point accelerator (Newton–Krylov primary, Anderson-accelerated Picard as the interpretable fallback). The caching is a clean, real win and is landed. The accelerator study, run honestly on the frozen shots, confirms what §2 and the three expert reviews predicted: no per-solve CPU iterator (Picard, Anderson, or Newton–Krylov) clears 3×, because the throughput ceiling is the sequential, non-smooth, host topology read, not the arithmetic. The 3×+ is a batched-over-shots GPU result and moves to gpu-accelerated-labeler, gated on the continuous/differentiable topology read (connectivity-topology-reader).

Gate verdicts (pre-declared in f-gfs-04)

The three levers, measured

  • Campaign-scope caching — LANDED (real). The grid, Δ* factorisation, and every Green’s / interaction matrix are pure functions of (campaign signature, resolution), so they are built ONCE per campaign and reused across every shot and slice: cold build 2718 ms → cache hit 0.04 ms. Opt-in (cache=; default keeps the gate’s independent-grid G1c invariant), wired into the corpus factory (factory_shot_payloads(cache_grid=True)). This satisfies the corpus-extrapolation caveat the spine_bench baseline recorded (~2% at corpus scale, paid once per campaign not per shot).
  • Temporal warm-rollout — NOT a lever. Warm-starting the rich solve from the previous slice’s converged current is 0.53× (slower) than the cold within-slice path AND diverges ~1.15 cm from the canonical equilibrium: the same-slice K=2 position scaffold is a better, cheaper seed than a different slice’s answer. Measured, reported, not adopted.
  • Fixed-point accelerator (G3b) — a modest, CPU-limited win. A safeguarded Anderson-accelerated Picard (engage-after-warmup + step-cap + finite guard; the free-boundary map is non-stationary and only piecewise-smooth) gives ~1.3× on the well-posed slices, byte-comparably. But it cannot help the under-determined interior-null slices (their residual limit-cycles ~1e-3 as the discrete mask flips), and those dominate the cost. Newton–Krylov on the same map is erratic (tight convergence on some slices, catastrophic divergence on others), and its scipy.optimize.newton_krylov is host-only.

Root cause — the non-smooth, host topology read

Both accelerators are blocked by the SAME wall: the free-boundary map re-reads the magnetic axis and the axis-connected core mask every sweep with hard-threshold host primitives (find_critical_points + ndimage.label). That read is non-differentiable — finite-differencing the residual across a mask flip corrupts Newton–Krylov’s Jacobian, and the mask-flip noise corrupts Anderson’s least-squares history — and it is a per-iteration host round-trip that serialises any GPU port (the §2 expert-review finding). The lead’s diagnosis was exact: with the current-centroid pin (a magnetics-derived soft prior) holding the branch, there is no basin escape to fear; the hard slices are under-determined (the interior null) so any iterator thrashes there — that is a property of the problem, and the accelerators must be tested on a solvable one, which is what the well-posed subset is.

The re-sequencing — the differentiable topology unblocks both

The cure for the wall is a continuous, differentiable topology read — already planned as connectivity-topology-reader (a connectivity flood-fill boundary + smooth core mask, GPU-native, continuous through the marginal transition by construction). Making the solve’s core-mask smooth makes the whole map differentiable, which (i) lets Newton–Krylov / Anderson converge cleanly (the schemes are revisited there, on a solvable map) and (ii) makes the map vmap-batchable so the GEMV becomes a corpus GEMM. The 3×+ therefore lives in the batched-over-shots GPU rollout (gpu-accelerated-labeler), whose locked topology-read-location decision already names connectivity-topology-reader as its prerequisite. §5 (adopt + integrate + re-score at corpus scale) folds into that path — the ONE jax engine (CPU+GPU) that adopts the grid-free substrate + connectivity FSA and re-scores the held-out MSE pitch.
