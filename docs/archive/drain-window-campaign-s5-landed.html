A written SDCC-admin proposal framing 3+ multi-hour drain outages (2026-05-26 through 05-28) and requesting three independent config changes to reduce recovery time from ~2 hours to <5 minutes:

ProposalMechanismImpact
Job epilog GPU reset nvidia-smi --gpu-reset via UnkillableStepProgram on job-end/drain Clears dirty GPU contexts automatically; eliminates need for manual gpu-reset or reboot
Auto-resume policy HealthCheckProgram (SLURM 23.11+) or 5-min cron gated on nvidia-smi health check Node rejoins reservation automatically after clean GPU; eliminates manual scontrol resume
UnkillableStepTimeout review Current: 60 s (confirmed). Proposal: review whether 60–120 s is optimal for this workload; placeholder for Track C measured value May prevent transient D-state from triggering drain; Track C will provide the first live measurement

Judgment calls in the proposal

  • UnkillableStepTimeout placeholder value 60 s — now confirmed from scontrol show config (2026-06-03); proposal marks it for update once Track C provides live timing.
  • nvidia-smi --gpu-reset is wrapped in timeout 120 in the epilog — it hangs if a process still holds the device; the timeout bounds the hang and logs the failure.
