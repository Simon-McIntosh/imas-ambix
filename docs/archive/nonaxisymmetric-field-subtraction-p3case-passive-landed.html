The f-nfs-p3case followup was written to fix a drive-data amplitude bug — audit the P3 *_case_current channel's turns/xmult/units/name upstream so the vacuum scale k→1. The audit found no such bug: every candidate is already correct, and the real mechanism is a passive induced-eddy current whose resistance R (equivalently τ = L/R) is the only free lever and is recoverable from the dynamic ramps. This overturns the premise and re-routes the anomaly to the passive layer (gate G-A / D3). The frozen operator is not modified.

§1 — Every candidate "upstream channel fix" is already correct

Firewall: coil-only vacuum slices, raw amb magnetics + raw amc currents + the geometry-only operator; no EFIT.

§2 — Why the static "k≈2.3" is ill-posed, and what it really is

The archived *_case_current is an Analysed (derived) signal, and the current it reports is an induced eddy in the coil case: it tracks −dIcoil/dt (Lenz), with corr(case, dIcoil/dt) ≈ −0.7 on P3 across shots. Because the case Green's column and its co-located winding column are ~98 % collinear, a per-slice static regression cannot cleanly split them:

  • the exposed-bay-loop estimator lands at k≈2.3 (the value the followup inherited),
  • the global all-sensor estimator lands at k≈0.9 (the old 85-shot audit's sub-1 band),
  • a free per-sensor OLS scatters from −1.6 to +4.7 with sign flips.

A genuine channel-amplitude error is sensor-independent by construction, so this spread proves the "k" is not a channel scale — it is the resistive-regime coupling M/R of an induced current, read through a near-degenerate static split. The P3 cases are the only ones the vacuum data resolves at all (P2 unexposed; P4/P5 vary sensor-to-sensor), so "why P3?" is an observability answer, not a P3-specific defect.

§3 — R and τ pulled from the dynamic vacuum ramps (the fix's real home)

§4 — Sensor-anchored isolation is confounded (honest negative → needs D3)

Fitting R against the bay-loop flux directly (bypassing the derived channel) is confounded: on P3's own exposed bay loops the geometry-built passive-case shape explains only 2.6 % (p3l) / 4.8 % (p3u) of the ramp flux residual left after the active windings. That residual is dominated by vessel eddy, not the coil case, so the case's absolute R cannot be pinned from the flux alone — it requires the full D3 vessel passive model alongside the case circuits. The circuit-level fit above (anchored on the case-current channel's dynamics) is therefore the clean source of R/τ for now.

§5 — Verdict and routing

  • Gate G-A input reversed. The P3 bay-loop case anomaly is layer A (passive induced eddy), not layer D (drive-data channel amplitude). G-A's passive circuit model must reproduce it; it does not bypass it. This corrects the tentative "drive-data, not passive screening" note carried from f-nfs-lever2.
  • No operator change. There is no units/turns/name fix to apply (all correct), and a per-case operator scale is the rejected option — doubly so now that the "k" is shown ill-posed. The frozen operator is unchanged; gs suite green (211 passed, the unrelated test_polygon.py collection error belongs to the concurrent polygon-section work).
  • Route. The case R/τ calibration folds into D3 (passive circuit-coupled eddy; the idle-ivc-circuit-state decision applies) and its sensor-level subtraction into D5 — carried by f-nfs-d2. The recovered R/τ per case is the starting point.
