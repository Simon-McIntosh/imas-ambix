What was built

  • imas_ambix/latent/topology.py — lcfs_contour(psi, r, z, axis, limiter…): one monotone flux-offset push. From the axis flux the level is swept OUTWARD (toward the domain-edge extreme); at each level the closed contour enclosing the axis is traced with contourpy (SeparateCode, CLOSEPOLY + min-point guard, ported from nova Contour.closedlevelset). The predicate "a closed axis-enclosing ring exists AND lies entirely inside the limiter" is monotone; a geometric backoff finds a valid lower bracket and a 14-step bisection converges the largest-valid level (the separatrix/wall flux). The reported ring sits at the 99.9 % normalised flux (nova psi_lcfs convention) and the 8 radii are read straight off it with the evaluator's own resample_lcfs_radii angle-interp — the same function that builds the EFIT LCFS labels, so the read is consistent with the target by construction.
  • emergent_xpoints(x_points, ring, tol) — the limited/diverted class + X-slots read AFTER the boundary: a saddle within tol (5 cm, a fixed physical margin — NOT tuned) of the ring is ON the boundary ⇒ diverted (report it); else limited (X-slots NaN). Soft margin, never a code-path switch.
  • scripts/boundary_harmonic_gate_eval.py::hybrid_target_harmonic — the innermost-X + limiter-fallback + outward ray-cast block replaced by the push + emergent read; a --xpoint-tol knob and a per-phase diverted_fraction diagnostic added.
  • scripts/profile_boundary_read.py and scripts/figures_connectivity_boundary.py — the profiling harness and the two figures.
  • Vectorised _inside_polygon (points × edges, no Python per-vertex loop) — the perf fix that took the push from ~51 ms to ~5.5 ms/slice; a drop-in win for every caller.

Performance — the plan's claim corrected (profiled)

The plan §5b claimed 0.019 ms/level and a 0.34 ms full push, concluding "~10× faster." Profiling the real chain on the 65×97 grid (single-thread CPU) shows that headline was trace-only — it counted the contourpy call (0.02 ms/level, confirmed) but not the per-level containment tests. The honest numbers:

So the read is faster than the one it replaces (2.2× for the primary LCFS shape; ~1.3× for the full read that also emits the class), just not the plan's fantastical 10×. The decisive perf lever was vectorising _inside_polygon — the dense contourpy rings were being tested against the limiter with a Python per-vertex loop tens of times per slice.

Decisions honoured

  • contour-library = contourpy — used via a persistent contour_generator (SeparateCode); ported nova's closedlevelset closed-ring logic and vectorised the point-in-polygon containment test in-tree (no numba dep).
  • xpoint-role = emergent-only — the LCFS shape is the scored deliverable; the X-point set + limited/diverted class are read off by proximity to the already-found ring, reported (not optimised) against EFIT. The 5 cm margin is a fixed physical value, not tuned on eval.
  • read-location = shared-topology — implemented in imas_ambix/latent/topology.py so all arms can adopt one boundary read; the gate calls it.

Scope guard (§7) — held

The read is one flux-offset push + one axis-enclosing ring test + one inside-limiter test. No discrete limited/diverted classifier as a code switch; no wall-contact / ψ-extrema-on-limiter chasing; no per-surface X-point↔limiter matching; no tuned distance cap. Far-field garbage is excluded by the enclose-the-axis test (unit-tested with NO cap); the masked interior is a deep plateau that produces no contour in the outward sweep (unit-tested). The limited/diverted class and X-points are emergent diagnostics only.

Honest caveats / what did NOT change

  • Skill is still negative — the read loses to the persistence baseline in absolute terms (as every arm does at n=160); the win is relative to the prior harmonic read, which it clears decisively on both LCFS and the emergent X-set.
  • Axis skill unchanged (−1.582) — the origin is still the current centroid; this plan changed the boundary read, not the axis.
  • Perf claim corrected — 5.5 ms, not 0.34 ms; still faster than the old read.
  • imas-efit applicability (§5b) remains a candidate simplification to flag, not assumed — EFIT has a globally-valid ψ (no garbage annulus) and needs the X-point for strike-point outputs, so its version would be a careful boundary-logic proposal, not a drop-in port.
