B4 — the equilibrium layer as the stage-3 filter's observation operator

Design note + prototype for patch-equilibrium-wm-integration §4 item B4, feeding closed-loop-latent-filter (stage 3 of machine-agnostic-latent-world-model §7, decision correction-mechanism = lae-enkf-ensemble). This item hands architecture, not results — there is no gate number. Module: imas_ambix/latent/patch_observation.py; tests: tests/latent/test_patch_observation.py.

The idea in one sentence

The shipped patch-current substrate's batched linear map y = vacuum + Msens·I (fp32, measured 693,599 slices/s on H200 — PatchBasis.sensors) is already an EnKF observation operator: a constant matrix from plasma state to predicted magnetics, with no re-linearisation and no grid solve per analysis step. Wiring the LAE-EnKF correction through it — rather than through a hand-built linear regression of the latent onto sensors — means the filter's innovation (measured − predicted) is expressed in a space with physical meaning: which patch of the flux surface the data pulled on.

Architecture

sens (fixed matrix) predicted sensors, matmul-only innovation raw magnetics − H·I ensemble_correct kalman_update per member (perturbed obs) posterior I ensemble corrected currents re-encode posterior latent

What the prototype does

  • build_observation_matrix(m_sens, mask) restricts PatchBasis.m_sens (S sensors × n cells) to the trusted/finite rows for one slice — the same "trust mask" concept as SlicePayload.mask / MagneticsObs.trust_rows elsewhere in this codebase — and returns the restricted H plus the applied boolean row mask. restrict_observation applies that identical mask to the raw measurement / vacuum (KNOWN-coil) prediction / whitening-scale triple so H and the measurement side can never drift out of alignment.
  • ensemble_correct(ensemble, h_mat, y_obs, vacuum, sensor_scale, rank=None) runs a perturbed-observation (stochastic) EnKF analysis: for every member it calls imas_ambix.statespace.sequential_da.kalman_update — imported, not reimplemented — with the SAME prior covariance (so every member shares one Kalman gain) and an independent per-sensor noise draw added to the mean-relative target resid_target = (y_obs − vacuum) − H·mean_prior. This is the textbook Burgers et al. (1998) construction and is why the posterior ensemble spread reflects the analysis covariance without ever sampling a fresh Gaussian.
  • Reduced-rank path (rank=r) routes the correction through leading_observable_modes(H, sensor_scale, r) first: the ensemble deviations are projected onto the leading r right-singular vectors of the whitened H before the covariance is ever formed, so the analysis never touches an n×n covariance (n = thousands of patch cells on a real campaign grid; the fixture here uses n=96 to keep the demo fast). Directions the sensors cannot see stay exactly on the prior — this is the localisation the closed-loop filter needs at production scale.

Cost

H is a constant matrix (built once per campaign geometry, already amortised by PatchBasis); the analysis step is matmul + one (n_obs, n_obs) or (r, r) solve per member, no re-linearisation. At production scale (S ≈ 40–100 sensors, n ≈ 5,000 patch cells) the reduced-rank path with r on the order of the sensor count keeps every per-member solve at the r×r scale; only the one-time projection H·modes touches the full cell dimension, and that is itself a constant matrix once the geometry (and hence H) is fixed.

What the innovation means physically

Because H is the same finite-area Green's-function map used everywhere else in the patch layer, the innovation y_obs − vacuum − H·I is directly interpretable: its whitened norm is the same "misfit" quantity the P3 variational inverse and the P4 amortised encoder already report, and the per-sensor residual after correction tells you which physical sensor (and, via the reduced-rank modes, which flux-surface-scale structure) the data still disagrees with. That is the concrete cash-out of routing the correction through the equilibrium layer instead of a latent-only regression: the filter's disagreement with the data has a magnetics-diagnostic reading, not just a KL-divergence number.

Synthetic demo (see figure)

Fixture: the _confining_table synthetic machine from tests/latent/test_patch_basis.py (5 B-probes, no KNOWN coils), a 9×13 grid (n=96 in-limiter cells). A truth current blob defines the "measured" sensors; a biased, noisy 300-member ensemble stands in for the filter's prior (whitening scale set to half the ensemble's own sensor-space spread — the well-posed EnKF regime; see the note in the test fixture on why an arbitrary fraction of the signal magnitude either saturates the innovation clip or gives a negligible correction). One ensemble_correct call: mean whitened sensor-space error falls from 10.4 to 4.9 (median 10.3 → 4.9), the ensemble covariance trace contracts 4.13×108 → 9.34×107 (77%), and the rank-1 reduced path reproduces the full-rank correction along the leading observable mode to 0.08% — the one case the two code paths can be checked against each other exactly.

Open questions for the stage-3 plan (closed-loop-latent-filter)

  • Latent-space vs current-space correction. This prototype corrects the patch currents directly (state = I, n cells). The alternative is to correct the hybrid latent's ψ/current-carrying block directly and only READ OUT through H for the innovation (i.e. H' = H · decode_to_currents, composing the fixed patch matrix with the learned decode head). The current-space form is what is implemented and tested here because it needs no decode-head Jacobian; the latent-space form would let the EnKF correct exactly the coordinates the transformer prior rolls forward, at the cost of differentiating (or ensemble- approximating) the decode head. Recommendation: start current-space (this prototype) for stage-3's first landing — it is gain-only, needs no additional Jacobian machinery, and every EnKF property proven here (contraction, reduced-rank agreement) carries over unchanged; revisit latent-space only if the decode head's own uncertainty turns out to dominate the analysis error.
  • Localisation / rank choice. leading_observable_modes gives a principled cutoff (the whitened singular-value spectrum, panel (c)) but the stage-3 plan must decide whether rank is fixed per campaign geometry (cheap, matches the "constant H" cost story) or adapted per slice (e.g. by trust-mask coverage, since a slice with fewer trusted sensors has fewer observable directions and a fixed high rank would be corrected against noise in the unobservable tail).
  • Inflation. This prototype exposes a single scalar cov_inflation multiplying the prior covariance every call (matches SequentialDAConfig.correction_inflation in spirit) but does not implement covariance decay/relaxation across time steps — that belongs to the stage-3 sequential loop (predict advances the ensemble through the transformer; how much the analysis covariance should inflate before the next correct depends on the transformer's own process noise, which this item does not model).
  • Multiplicative vs additive ensemble representation. The prototype's ensemble members are raw currents in amperes; if the latent world model's decode head instead produces a dimensionless shape (as the P4 encoder's x = I·n/Ip convention does), the EnKF should probably run in THAT dimensionless coordinate (consistent with the machine-agnostic latent's dimensionless-coordinate-set decision) rather than raw amperes — an open choice for whoever wires this into the stage-3 loop.

Firewall / scope note

patch_observation.py imports only numpy and imas_ambix.statespace.sequential_da (for kalman_update and leading_observable_modes) — no data loading, no GPU requirement, no EFIT/evaluator import, matching the firewall convention checked for patch_basis.py and patch_inverse.py.
