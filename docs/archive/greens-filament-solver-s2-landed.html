§2 record — the grid-free Green's/filament solver spike (GO)

Verdict (2026-07-20): §2 GO. The gridded elliptic Δ*ψ evaluation can be replaced by an analytic finite-area Green’s matvec — the coaxial mutual-inductance kernel is the free-space Green’s function of Δ* — with the free-boundary GS fixed point and every topology / profile read left byte-unchanged. On held-out slices the grid-free substrate reproduces the frozen grid-GS equilibria to sub-mm axis, ~60 µm LCFS, and ~2% profile RMS, cold- and warm-seeded, as genuine force-balanced equilibria, while provably never assembling the elliptic operator. The spike passes; the locked solver-substrate decision is confirmed GO.

Honest caveat, load-bearing for the plan’s framing. The grid-free matvec is 1.67× SLOWER per single CPU solve than the cached-LU grid solve (median 1.98 s vs 1.19 s): a dense (6305×1500) matvec every iteration loses to a cached sparse triangular backsolve when only one equilibrium is in flight. §2 proves physical reproduction, not per-solve speed. The throughput payoff is elsewhere — the smooth analytic ψ for flux-surface-averaging integrity (§3), and a batched GPU labeler where the per-solve GEMV becomes a corpus-wide GEMM (the follow-on plan). This is exactly the expert-review conclusion below.

Gate verdicts (pre-declared in f-gfs-01)

The mechanism

  • Substrate — an analytic Δ* inversion by matvec. The free-boundary loop’s one gridded step, ψ = solve_dirichlet(−2πµ0R jφ) + ψcoil (a 5-point Δ* LU backsolve), is replaced by ψ = Gcell→grid·icell + ψcoil, where G is the finite-area hybrid_greens kernel — the SAME kernel the coils and vessel use (the locked one-interaction-matrix decision, extended to the plasma). Both invert the same elliptic operator (one on the grid, one analytically), so they agree to discretisation error inside and exactly on the domain edge (both read the identical Green’s block there). Routed through one _plasma_psi_field helper, so the default grid-delstar path is byte-unchanged (94 solver tests green).
  • The nova scheme, on this engine. The fixed point is T(ψ) = ψcoil + G·I(ψ), with I(ψ) the force-balanced filament currents (topology → ψN → jφ pointwise → renormalise Σ = Ip). This maps exactly onto nova’s residual = ψ − (external + internal(ψ)). A Jacobian-free Newton–Krylov driver (solve_equilibrium_nk) on the shared grid-free evaluator is included as the accelerator arm; the go/no-go itself rests on the existing Picard driver so the ONLY changed variable is the ψ evaluator (a clean substrate control).
  • Filament turns sum to 1 → net = Ip. The per-sweep renormalisation i_cell ×= Ip/Σi_cell makes the net current exactly the measured Rogowski Ip — no KKT anchor needed for the net (T1).

Notable findings

  • The per-solve substrate is NOT the speedup (1.67× slower on CPU). A single equilibrium’s dense matvec loses to the cached sparse-LU backsolve; the 38 MB Green’s matrix streams from memory every iteration with no reuse, while the factorised Δ* is a cheap triangular solve. This is the correct result for a batch-1 workload and reframes the plan: the substrate’s value is (a) the smooth analytic ψ for FSA integrity (§3) and (b) enabling a batched GPU labeler (follow-on), where the matvec becomes a corpus-wide GEMM. It is not a per-solve CPU accelerator.
  • The interior-null ramp divergence is physics, not a substrate defect. On early low-Ip ramp slices the axis and LCFS still reproduce to sub-mm, but the interior profile coefficients diverge (profile RMS up to 1.4): with identical ψ geometry the coefficient readout is non-unique in the under-determined interior direction — exactly the slices the MSE label engine flags under-determined. Scoring the profile leg on the well-determined flat-top population is consistent with the label-honesty gate.
  • Stop rule NOT invoked. The grid-free solve reproduced the grid-GS equilibria within tolerance from physical (disc + centroid) seeds; no adoption was forced against a failing reproduction.

GPU-porting outlook (independent expert review)

Prompted by the lead’s question — and the datum that a per-solve jax GPU port of the nova scheme showed no material speedup — three independent expert reviews (HPC/roofline, batched numerical methods, jax/XLA systems) converged: a per-solve solver is the canonical anti-GPU workload (batch-1 GEMV at arithmetic intensity ~0.5, ~600× below the H200 tensor-core ridge; a strictly sequential fixed-point chain of tiny kernels; a per-iteration host round-trip for the topology read — the anti-pattern nested twice, in both the GS fixed point and the time integration). The realisable speedup requires a re-architected labeler: batch over shots (the parallel axis; the per-solve GEMV becomes a corpus GEMM, compute-bound past B ≈ 600), the whole causal rollout on-device as one vmap(shots) × scan(time) × fixed-point graph, and an on-device fixed-shape topology read (nova’s stencil null-finder + smooth mask, no connected-components). A single-shot / parallel-in-time arm (waveform relaxation: decoupled all-slice batched solve ⊗ sequential temporal threading, outer-iterated) accelerates the live/between-shot reconstruction where shot-batching is unavailable. Honest ceiling: 1–2 orders of magnitude (corpus label factory ~37 core-days → well under an hour on 8×H200), bounded by the sequential per-step thin-ops, not the matvec. Captured in the follow-on plan.
