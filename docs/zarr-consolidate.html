Plan: Consolidated Zarr metadata across L1+L2 corpus

imas-ambix / Fusion World Model · Sprint S4 · Updated 2026-05-26

Pending — sprint S4 (data-pipeline perf).

Every ambix data audit and ambix data bulk-encode-frames worker prints RuntimeWarning: Failed to open Zarr store with consolidated metadata, but successfully read with non-consolidated metadata. This is typically much slower for opening a dataset. On the 9,527-shot rbb corpus, this pays 0.5–2 s of metadata listing per shot — visible as the 0% GPU util on the earlier signals job and the 12-minute startup of the failed frames job.

Fix: run zarr.consolidate_metadata() once over both corpora. Writes a .zmetadata file at each shot root; subsequent opens read it in one GPFS roundtrip instead of recursively listing groups.
