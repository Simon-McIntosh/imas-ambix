§1 — Objective & scope

Upgrade the existing token substrate (multimodal-tokenisation-substrate) with the two properties the machine-agnostic goal makes non-negotiable, without abandoning tokens:

  • Absolute calibration. Quantise at corpus level in physical (SI) units, not per-shot. A given physical magnitude (e.g. 0.5 T) maps to the same code in every shot and on every machine. This repairs the scale-free blocker (per-shot z-scoring destroyed absolute magnitude — the reason diagnostics→equilibrium skill was ~0 — and cross-machine comparability).
  • Sensor-geometry positional encoding. Every token carries the physical geometry of its sensor: position (R, Z, φ), orientation / sensor normal, integration geometry (line-of-sight chord endpoints for interferometer/SXR; pixel footprint for cameras), plus machine geometry (vessel, PF-coil locations). Sensor geometry is apparatus metadata — freely used, never leakage (the firewall is on code outputs only; plasma geometry is excluded). It is the positional encoding that lets one attention model ingest a heterogeneous, machine-varying sensor set.

Scope: the v0 modality set — magnetics, plan, interferometer, SXR, all five cameras, the HF signals. Cameras remain decode-only. This stage produces the upgraded store + readers that stages 2–4 consume.

§2 — The gate (verifiable done-when)

  1. Tokens carry corpus-level absolute (SI) values + per-diagnostic sensor geometry + machine geometry; schema + readers committed.
  2. Per-modality reconstruction fidelity preserved under absolute calibration — no regression vs the per-shot baseline.
  3. The scale-free blocker is fixed: a diagnostics→equilibrium probe (the firewalled oracle) skill rises clearly off ~0 once tokens carry absolute magnitude — report the number.
  4. Tests green; outcome recorded; this plan collapses to a landed summary.

§3 — Approach

  1. Absolute calibration path. Replace the per-shot normalisation in the signal tokenisation with corpus-level SI scaling (per-channel physical ranges), and the value→token mapping for the L2 measured inputs. The camera VQ codebook (Open-MAGVIT2) is fixed; assess whether camera frames need re-encoding or only the conditioning/value streams do.
  2. Geometry schema. Attach per-diagnostic sensor geometry (probe/loop/chord/pixel coordinates + orientation + machine geometry) to the token store as a positional-encoding field; sourced from the device description, not from any reconstruction.
  3. Readers. Extend the store_v2 readers to surface absolute values + geometry on a common time grid, honouring the boundary guard (target/code-output store never opened by the input path).
  4. Validation. Per-modality reconstruction-fidelity check; the diagnostics→equilibrium probe (the firewalled oracle) to confirm absolute magnitude is now recoverable.

§4 — H200 footprint

Light–moderate, I/O-leaning — but trivially parallel. Re-tokenisation reuses the in-process stream_encode.py pattern; the bottleneck is GPFS I/O, not compute, and the GPU nodes read/write /work directly (no offload — only outbound-internet tasks like package downloads need standard compute, and there are none here). The corpus re-encode is embarrassingly parallel: shard it across all free cards (all 8 are available while DSv4 is down — check squeue), one in-process encoder per shard. Geometry tagging is pure metadata (no GPU). Per AGENTS.md §2b, in-process model-load-once. Fleet-suitable (sharded encode).

§5 — Inherited decisions

All architectural decisions are locked in the parent (machine-agnostic-latent-world-model): signal-representation = tokens + absolute calibration + sensor-geometry positional encoding; firewall-definition = code-outputs-only (sensor geometry free, plasma geometry firewalled). This plan honours them; it introduces no new architectural decisions.

Step 2 - RETRAIN the patch-transformer codebooks under absolute normalisation
  The xma/xim/xsx codebooks were trained per-window; absolute mode shifts the input distribution, so they MUST be retrained before re-encoding (the train path needs the same corpus calibration applied to its normalise; thread corpus_calibration into the PatchTransformerTokenizer.fit feature prep the same way encode_window does, or train on already-absolute-normalised windows). The L2 light-path UniformQuantizer needs NO retrain (it is parameter-free given mean/std).

Step 3 - re-encode in absolute mode (GPU for xma/xim/xsx; CPU for L2 light-path)
  Signal corpus (per group), loads calibration via load_group_calibration:
    python -m imas_ambix.tokenizer.signal_hf_encode encode --group xma --shots all --ckpt <retrained-ckpt> --absolute
  L2 light-path inputs (CPU):
    python -m imas_ambix.data.l2_input_build --shots all --absolute
  Both fall back per-shot for any group lacking a calibration file (with a warning) and record calibration=absolute|per_shot + the corpus mean/std in each store's metadata.

Geometry table schema (the exact columns)
  Flat per-channel float feature vector, order = GEOMETRY_FEATURE_NAMES =
    (r, z, phi, angle_deg, normal_r, normal_z, chord_r1, chord_z1, chord_r2, chord_z2)
  10 columns, float32, NaN where not applicable. A parallel per-channel categorical sensor_kind in
  SENSOR_KINDS = (bpol_probe, flux_loop, interferometer_chord, sxr_chord, pixel, coil, scalar).
  Plus a shared MachineGeometry block: limiter_r/limiter_z (vessel contour), pf_coil_r/pf_coil_z (turns-weighted
  PF-circuit centroids), r0, minor_radius. B-probes carry R/Z + orientation angle_deg -> (normal_r, normal_z) unit
  field-direction (0deg=radial reads B_R, 90deg=vertical reads B_Z); flux loops are point sensors (NaN orientation/chord);
  line-integrated diagnostics (interferometer/sxr) get the chord kind with NaN endpoints today (schema present, endpoints
  to be tabulated); pure scalars (ip, gas-valve setpoints) are present + explicit with scalar kind + NaN coords (never dropped).

Step 1 - build + attach geometry during the re-encode
  Per shot: fields = imas_ambix.gs.geometry_export.build_geometry_table(shot_id, extra_channel_names=<the store's channel_names>).
  Project to the store's channel order: feats, kinds = fields.feature_matrix(attrs.channel_names) (NaN-fills absent channels).
  Pass geometry=feats and set attrs.geometry_feature_names=GEOMETRY_FEATURE_NAMES, attrs.geometry_sensor_kinds=tuple(kinds)
  into save_signal_hf_tokens(...). geometry is OPTIONAL and geometry-less stores stay byte-identical, so this can ride the
  same absolute-mode re-encode (f-ags-calib) without a separate pass. Use the campaign-keyed table (one GeometryFields per
  SetupSignature) so geometry from different campaigns is never mixed.

Step 2 - feed geometry into the diagnostics->equilibrium probe
  At load time: aligned = imas_ambix.tokenizer.geometry_reader.geometry_for_channels(channel_names, shot_id=..., group=...)
  returns AlignedGeometry (features (n_channels, 10) float32 aligned 1:1 to channel_names, sensor_kinds, feature_names),
  reading the store's attached geometry when present and falling back to a campaign GeometryFields else (all-NaN/scalar if
  neither). Use aligned.features as the per-channel positional encoding the attention model attends with (embed sensor_kind
  as a learned categorical; project the float block; NaN-mask the absent columns). Honour the boundary guard (the reader
  already routes every opened path through assert_not_target_path).
