§1 — Objective & scope

Upgrade the existing token substrate (multimodal-tokenisation-substrate) with the two properties the machine-agnostic goal makes non-negotiable, without abandoning tokens:

  • Absolute calibration. Quantise at corpus level in physical (SI) units, not per-shot. A given physical magnitude (e.g. 0.5 T) maps to the same code in every shot and on every machine. This repairs the scale-free blocker (per-shot z-scoring destroyed absolute magnitude — the reason diagnostics→equilibrium skill was ~0 — and cross-machine comparability).
  • Sensor-geometry positional encoding. Every token carries the physical geometry of its sensor: position (R, Z, φ), orientation / sensor normal, integration geometry (line-of-sight chord endpoints for interferometer/SXR; pixel footprint for cameras), plus machine geometry (vessel, PF-coil locations). Sensor geometry is apparatus metadata — freely used, never leakage (the firewall is on code outputs only; plasma geometry is excluded). It is the positional encoding that lets one attention model ingest a heterogeneous, machine-varying sensor set.

Scope: the v0 modality set — magnetics, plan, interferometer, SXR, all five cameras, the HF signals. Cameras remain decode-only. This stage produces the upgraded store + readers that stages 2–4 consume.

§3 — Approach

Direction (2026-06-25): this is a clean architecture pivot, not an incremental add-on. Corpus-level fixed-scale calibration is the default and only operative representation, per the North Star (§1a-reqs #2: "absolute calibration is mandatory, not optional"). The per-shot z-scoring path is the retired approach (it caused the scale-free blocker); we do not carry it forward as a default or a silent fallback. New-approach parameters are not gated behind opt-in flags; a missing required calibration fails loud (or is computed), never silently reverts to per-shot. Any per-shot path that remains exists only as an explicit, clearly-labelled diagnostic escape (e.g. the one-time gate baseline), never the operative default.

"Absolute" means a fixed physical-unit SCALE, not absolute value — signals stay SIGNED. Calibration is z = (x − μcorpus) / σcorpus with a symmetric ±4σ range, so field direction / flux polarity is preserved end-to-end (there is no magnitude/abs op anywhere in the calibration, quantiser, or continuous paths). The "absolute" in absolute calibration is the absolute reference scale (the same physical value maps to the same representation in every shot and on every machine), as opposed to per-shot relative scaling.

Magnitude/sign-carrying analog signals are persisted as CONTINUOUS signed embeddings, not 256-bin discrete tokens. Measured 2026-06-25: the continuous signed lane recovers ~2–3× the diagnostics→equilibrium skill of the 256-bin token lane (magnetics axis_R +0.14→+0.27, axis_Z +0.18→+0.58). Tokenising a signed analog value embeds its bin id as an unordered categorical vector, discarding the ordinal/metric/sign structure that boundary triangulation needs; a continuous projection keeps it. So magnetics (B-probes, flux loops), coil currents, and plasma current are carried as continuous signed values on a fixed corpus scale (the store already supports a continuous-embedding array; this matches the per-modality tokeniser decision that put xma on continuous embeddings). Discrete tokens remain where they win (cameras; phase-tolerant HF families).

  1. Absolute calibration path. Replace the per-shot normalisation in the signal tokenisation with corpus-level SI scaling (per-channel physical ranges) as the default, and the value→token mapping for the L2 measured inputs. The camera VQ codebook (Open-MAGVIT2) is fixed; assess whether camera frames need re-encoding or only the conditioning/value streams do.
  2. Geometry schema. Attach per-diagnostic sensor geometry (probe/loop/chord/pixel coordinates + orientation + machine geometry) to the token store as a positional-encoding field; sourced from the device description, not from any reconstruction.
  3. Readers. Extend the store_v2 readers to surface absolute values + geometry on a common time grid, honouring the boundary guard (target/code-output store never opened by the input path).
  4. Validation. Per-modality reconstruction-fidelity check; the diagnostics→equilibrium probe (the firewalled oracle) to confirm absolute magnitude is now recoverable.

§4 — H200 footprint

Light–moderate, I/O-leaning — but trivially parallel. Re-tokenisation reuses the in-process stream_encode.py pattern; the bottleneck is GPFS I/O, not compute, and the GPU nodes read/write /work directly (no offload — only outbound-internet tasks like package downloads need standard compute, and there are none here). Geometry tagging is pure metadata (no GPU). Per AGENTS.md §2b, in-process model-load-once. Fleet-suitable (sharded encode).

§ Decisions

Is absolute calibration the default, or an opt-in layered over a per-shot default?

During the SSM architecture pivot the foundational code was first built backward-compatible (absolute behind opt-in flags; per-shot the silent default/fallback; 'byte-identical' as a success criterion). The lead flagged this as wrong and potentially harmful.

Locked by the lead 2026-06-25. This is a clean architecture pivot (SSM); dragging retired per-shot defaults forward is harmful. North Star physics-world-model-strategy §1a-reqs #2: absolute calibration is mandatory, not optional. No opt-in flags for new-approach params; no 'byte-identical to the retired path' as a goal.

How are multi-sensor diagnostic streams combined — pool, or space-time attention?

The diagnostics->equilibrium probe mean-pooled the 94 magnetic sensors into one vector, destroying the per-sensor spatial pattern EFIT triangulates the boundary from (raw-float ceiling axis 0.57-0.68 / xpt_R 0.50 vs tokenised 0.05/-0.07). Same failure mode as the camera data (averaging spatial positions into one vector), which space-time transformers fixed.

Locked by the lead 2026-06-25. Same fix that made cameras decodable (16x16 spatial position) generalised to every diagnostic: spatial (between-sensor) + temporal (incl. phasing) structure must be learnable and PERSISTED, not pooled. No averaging of sensor positions into a single vector.

How is toroidal/poloidal angle encoded so the 0/2π seam is respected and rotating modes are seen?

phi (toroidal) and theta/orientation are PERIODIC. A linear phi-in-degrees positional encoding places a sensor at 2π−ε and one at 0+ε maximally far apart, when they are physically ADJACENT. Rotating MHD ~ exp(i(mθ−nφ−ωt)) lives in the cross-sensor phase around the torus; the toroidal array was also not ingested at all.

Locked by the lead 2026-06-30. Angles are on a circle — periodic encoding is required for the relational model to treat the 0/2π seam correctly and to resolve toroidal mode number + rotation. The toroidal saddle array must be ingested (it was missing). Skill in the new ingestion must be demonstrated (synthetic rotating-mode n-recovery + the oracle).

Do ALL diagnostic signals use the space-time transformer ingestion pattern?

Different streams historically used different ingestion (per-scalar uniform tokens, per-channel patch-transformer, mean-pooling). The lead requires one consistent pattern.

Locked by the lead 2026-06-30. All signals must learn spatial (between-sensor) AND temporal (incl. phasing) relations via the space-time transformer pattern; review every stream to ensure it conforms.

How is the X-point target represented given multimodal flux / public-private / exotic divertor topologies?

A single 'primary' X-point target is bimodal across topology switches. A ψ-proximity 'boundary' filter (ψ(null)≈ψ(LCFS)) is physically INVALID: the flux map is multimodal with a public/private distinction, so a secondary null in a private region (snowflake / X-divertor / super-X) can sit at ψ≈ψ_LCFS yet not be on the confined boundary. The divertor topologies we must support are not limited to upper/lower SN.

Locked by the lead 2026-06-30. The flux map is multimodal (public/private); ψ-proximity cannot identify boundary nulls; exotic divertor topologies (snowflake/X-divertor/super-X) are out of scope to classify here. Axis + LCFS + the rotation demo carry the verdict; the X-point stays out of the headline. Robust topology-aware X-point handling is a documented DEFERRED requirement, not solved in this stage.
