§1 — Objective & scope

Upgrade the existing token substrate (multimodal-tokenisation-substrate) with the two properties the machine-agnostic goal makes non-negotiable, without abandoning tokens:

  • Absolute calibration. Quantise at corpus level in physical (SI) units, not per-shot. A given physical magnitude (e.g. 0.5 T) maps to the same code in every shot and on every machine. This repairs the scale-free blocker (per-shot z-scoring destroyed absolute magnitude — the reason diagnostics→equilibrium skill was ~0 — and cross-machine comparability).
  • Sensor-geometry positional encoding. Every token carries the physical geometry of its sensor: position (R, Z, φ), orientation / sensor normal, integration geometry (line-of-sight chord endpoints for interferometer/SXR; pixel footprint for cameras), plus machine geometry (vessel, PF-coil locations). Sensor geometry is apparatus metadata — freely used, never leakage (the firewall is on code outputs only; plasma geometry is excluded). It is the positional encoding that lets one attention model ingest a heterogeneous, machine-varying sensor set.

Scope: the v0 modality set — magnetics, plan, interferometer, SXR, all five cameras, the HF signals. Cameras remain decode-only. This stage produces the upgraded store + readers that stages 2–4 consume.

§2 — The gate (verifiable done-when)

  1. Tokens carry corpus-level absolute (SI) values + per-diagnostic sensor geometry + machine geometry; schema + readers committed.
  2. Per-modality reconstruction fidelity preserved under absolute calibration — no regression vs the per-shot baseline.
  3. The scale-free blocker is fixed: a diagnostics→equilibrium probe (the firewalled oracle) skill rises clearly off ~0 once tokens carry absolute magnitude — report the number.
  4. Tests green; outcome recorded; this plan collapses to a landed summary.

§3 — Approach

Direction (2026-06-25): this is a clean architecture pivot, not an incremental add-on. Corpus-level absolute calibration is the default and only operative representation, per the North Star (§1a-reqs #2: "absolute calibration is mandatory, not optional"). The per-shot z-scoring path is the retired approach (it caused the scale-free blocker); we do not carry it forward as a default or a silent fallback. New-approach parameters are not gated behind opt-in flags; a missing required calibration fails loud (or is computed), never silently reverts to per-shot. Any per-shot path that remains exists only as an explicit, clearly-labelled diagnostic escape (e.g. the one-time gate baseline), never the operative default.

  1. Absolute calibration path. Replace the per-shot normalisation in the signal tokenisation with corpus-level SI scaling (per-channel physical ranges) as the default, and the value→token mapping for the L2 measured inputs. The camera VQ codebook (Open-MAGVIT2) is fixed; assess whether camera frames need re-encoding or only the conditioning/value streams do.
  2. Geometry schema. Attach per-diagnostic sensor geometry (probe/loop/chord/pixel coordinates + orientation + machine geometry) to the token store as a positional-encoding field; sourced from the device description, not from any reconstruction.
  3. Readers. Extend the store_v2 readers to surface absolute values + geometry on a common time grid, honouring the boundary guard (target/code-output store never opened by the input path).
  4. Validation. Per-modality reconstruction-fidelity check; the diagnostics→equilibrium probe (the firewalled oracle) to confirm absolute magnitude is now recoverable.

§4 — H200 footprint

Light–moderate, I/O-leaning — but trivially parallel. Re-tokenisation reuses the in-process stream_encode.py pattern; the bottleneck is GPFS I/O, not compute, and the GPU nodes read/write /work directly (no offload — only outbound-internet tasks like package downloads need standard compute, and there are none here). The corpus re-encode is embarrassingly parallel: shard it across all free cards (all 8 are available while DSv4 is down — check squeue), one in-process encoder per shard. Geometry tagging is pure metadata (no GPU). Per AGENTS.md §2b, in-process model-load-once. Fleet-suitable (sharded encode).

§5 — Inherited decisions

All architectural decisions are locked in the parent (machine-agnostic-latent-world-model): signal-representation = tokens + absolute calibration + sensor-geometry positional encoding; firewall-definition = code-outputs-only (sensor geometry free, plasma geometry firewalled). This plan honours them; it introduces no new architectural decisions.

§ Decisions

Is absolute calibration the default, or an opt-in layered over a per-shot default?

During the SSM architecture pivot the foundational code was first built backward-compatible (absolute behind opt-in flags; per-shot the silent default/fallback; 'byte-identical' as a success criterion). The lead flagged this as wrong and potentially harmful.

Locked by the lead 2026-06-25. This is a clean architecture pivot (SSM); dragging retired per-shot defaults forward is harmful. North Star physics-world-model-strategy §1a-reqs #2: absolute calibration is mandatory, not optional. No opt-in flags for new-approach params; no 'byte-identical to the retired path' as a goal.
